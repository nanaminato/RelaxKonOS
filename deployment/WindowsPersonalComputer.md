# 在自己的 Windows 10/11 电脑上使用 Server + Client

RelaxKonOS Server 可以部署在 Windows 10/11 个人电脑上，Client 可以运行在同一台电脑上。这里的「服务器」指承载工作区、文件和进程的电脑，不要求安装 Windows Server，也不要求租用云主机。Client 负责显示界面，Server 负责执行操作；两者在同一台电脑时，文件与工作负载就在这台电脑上。

Windows 使用现有的 **System Mode**：Server、Guardian Agent 与权限助手作为系统服务安装。安装和维护需要已提升的管理员权限，日常登录使用自己的 Windows 账号。Linux 的无 sudo User Mode 不适用于 Windows。平台支持不代表每个内置应用都具备相同能力，具体以服务端能力检测结果为准。

## 安装并连接本机

1. 从[下载页](https://relaxkon.com/downloads)取得匹配本机架构的桌面 Client 和 Windows `server` 包。Client 包不能代替 Server 包；发布包不需要安装 .NET SDK。
2. 在 Windows 桌面 Client 的登录页选择 **「安装到这台电脑」**。该入口无需 OpenSSH Server、SSH 密码或主机密钥；Linux 客户端不显示此入口。需要从桌面 `RelaxKonOS.exe` 启动客户端。
3. 选择官方稳定版、本地 Server ZIP 或自定义 HTTPS 下载。自定义下载必须提供 SHA-256。本机入口固定 Windows 系统模式，不显示「服务器上的发布包」等 SSH 专用选项。
4. 网络默认「仅本机」，服务端端口默认 `5000`，文件范围默认受限；需要自己的目录时选择白名单并加入相应目录。需要 HTTPS 时选择自签名或自有证书，证书应覆盖实际本机连接地址 `127.0.0.1`。
5. 审阅设置并开始安装，批准 Windows UAC 管理员权限请求。只有部署子进程被提升，Client 保持原有权限；取消授权会返回向导，可以重试。已有安装会按本次设置更新并可能中断服务。
6. 等待部署操作回执和独立状态健康检查通过。默认程序目录为 `C:\Program Files\RelaxKonOS`；安装成功后自动返回登录页，填入从核验结果取得的本机 API 地址（保留实际 HTTP/HTTPS 协议与端口），直接探测服务端。不会创建 SSH 隧道，也不会自动信任 TLS 证书。
7. 登录页填入当前 Windows 账号，并清空旧连接密码；使用本机 Windows 账号密码登录，例如 `电脑名\用户名`。Windows Hello PIN 不是系统账号密码。初次尝试建议使用有密码的本地账号；域账号的认证能力不代表所有按用户执行的功能都支持域身份。

安装完成后，本机 Client 可直接连接 Server API；日常连接不依赖 SSH 隧道。再次进入本机安装入口可以更新安装。修复、回滚和卸载仍通过服务器中心的 SSH 维护流程执行，使用这些功能前按[安装指南](https://relaxkon.com/docs/zh-CN/latest/getting-started/installation)准备 OpenSSH Server 与已提升的管理员 SSH 会话。

失败时向导显示操作编号。引擎的权威回执与诊断日志保留在 `%ProgramData%\RelaxKonOS-Deployment\operations\<操作编号>.json` 和 `<操作编号>.log`；使用管理员权限查看。暂存包和证书密码文件在本次操作结束后清理，失败不会被当作安装成功。连接中断时，以持久回执和重新预检为准。

## 从手机或另一台电脑连接

另一台设备的 `127.0.0.1` 指向它自己。要连接这台 Windows 电脑，需要使用电脑的局域网地址，选择 LAN 监听，并核对防火墙入站规则；不要把 SSH 端口当作 Server API 端口。

跨设备使用时配置 HTTPS，证书身份应覆盖实际连接的主机名或地址。仅本机监听时，另一台设备也可以使用现有 SSH 隧道连接，前提是 SSH 可达且客户端支持该连接流程。网络监听、证书和防火墙说明见[部署指南](./README.md)。

## 个人电脑的运行特点

- 服务与客户端分开运行：关闭 Client 不等于停止 Server。服务是否继续可用以系统服务状态和健康检查为准。
- 关机、休眠或睡眠时，这台电脑不能持续提供服务；唤醒后客户端可能需要重连。需要持续远程访问时，应根据自己的使用习惯配置电源设置。
- 文件、终端和应用操作的目标是承载 Server 的电脑；在同机使用时，就是自己的 Windows 电脑。服务安装权限不等于每次操作都自动拥有管理员权限。
- Docker 等功能还依赖宿主上的实际运行时与服务配置。部署 Server 不会使未安装的依赖自动可用，也不会把 Linux 专属能力变成 Windows 能力。
- 卸载默认保留数据；清除工作区、配置和密钥前先备份，并在维护界面明确选择删除数据。

## 实现与验证

本机入口复用三步安装向导和内置 Windows 部署启动器，后者继续负责包校验、部署锁、服务安装、失败恢复与持久回执。UAC 子进程在启动 Avalonia 前进入专用部署模式；它只接收固定 Windows 部署请求，使用限制访问的命名管道和双方进程编号核对身份，不接受客户端传入的任意脚本或命令。用户包与证书从普通客户端流式传入管理员暂存目录，支持 UAC 使用另一管理账号时读取用户选择的文件。

自动检查覆盖成功安装、更新身份、UAC 取消、失败回执、状态不健康、端口与 TLS 地址交接、文件传输和 SSH 选项隔离。发布前还需在 Windows 10/11 实机检查 UAC、系统服务安装、自签名证书确认、非默认端口和使用另一管理员账号的授权流程；自动检查不替代这些验收。

## 系统服务模式下的 Windows 账号与设备配对

Windows 10/11 本机安装提供两种独立模式：

- **个人模式（默认）**：以当前账户的非提升令牌运行，登录后启动、注销后停止。程序和数据分别保存在 `%LocalAppData%\RelaxKonOS-Personal\program` 和同级 `data`，操作记录位于同级 `deployment`。安装、更新、修复、回退及卸载无需 UAC，卸载默认保留数据。仅当前账户可登录和执行操作，Docker 使用该账户的 Docker Desktop 权限。
- **系统服务模式**：保留现有服务和安装目录，无人登录也能持续运行，安装和维护需要管理员授权，支持不同 Windows 账户登录。Docker 仍受服务账户权限限制。

两种模式不自动转换、不共用数据库或安装标识，同时运行需要不同端口。个人模式目前从本机管理入口部署，远程 SSH 安装仍只提供系统服务模式。个人模式暂不支持特权辅助进程、Guardian 服务及机器级设置，访问其他账户的受保护文件尚不能通过 UAC 完成，按操作授权的 UAC 通道需单独实现。个人安装不修改防火墙规则，LAN 访问需要管理员预先配置防火墙。

Server 以系统服务运行时，仍可用这台电脑的 Windows 账号密码登录（不是 Windows Hello PIN）。登录用户映射到自己的 Windows SID，而不是 LocalService 等服务进程身份。

Windows 10/11 本机管理员可通过仅 loopback 的 Windows Negotiate 验证设置或恢复自己的设备密钥；Server 以 LocalService、NetworkService 或 LocalSystem 运行时，不要求管理员 SID 与服务 SID 相同。普通桌面进程仍只允许启动该进程的管理员账号执行此操作。此例外不开放远端免密登录、不允许服务账号成为设备所有者，也不改变其他账号已有的设备绑定。普通用户可继续通过账号密码登录后使用已有的设备配对流程。

# AD02：Android 应用部署向导计划

> 状态：待开始 Android 接入与验收。优先级：P0。工作量：中。
> 总入口：[无电脑部署路线图](./RelaxKonOS.Mobile.Deployment.Roadmap.md)。

## 1. 目标与依赖

把镜像、Java JAR、.NET 发布归档和 Python 项目归档部署为远端容器应用，在手机上完成日志查看、更新、停止和版本回滚。已有 Server 可直接使用；新主机通过 [AD01](./RelaxKonOS.Mobile.ServerBootstrap.Plan.md) 接入。

依赖应用部署能力、实际可用的 Docker Engine 和当前身份的管理权限。Server 在线不代表 Engine 可用；预检需分别展示缺失能力、执行身份限制和运行时故障。

## 2. 复用与明确限制

复用 `Shared/RelaxKonOS.Protocol/ApplicationDeployments/`、`RelaxKonOS.Server/ApplicationDeployments/` 及对应 Endpoints。权威来源为 [共享部署设计](../../../docs/applications/RelaxKonOS.ApplicationDeployment.Design.md)、[实施进度](../../../docs/applications/RelaxKonOS.ApplicationDeployment.Progress.md)。

现有服务端具有应用定义、不可变修订、后台操作、日志、就绪检查和停机替换实现，但真实 Docker 验收仍有缺口。Android 页面完成与服务端运行验收是两项独立条件。

本计划不接受 Compose、Git 或任意 Dockerfile，不承诺无停机升级，不允许任意宿主目录或 Docker socket 挂载。Git 和 Compose 分别由 AD06、AD04 扩展。

## 3. 手机工作流

入口位于“管理 → 应用部署”；列表展示名称、真实运行状态、当前修订及最近操作。未完成实现前不挂载入口。

新建流程：选择来源 → 输入镜像或选择文件 → 运行参数 → 持久化与资源 → 可选访问配置 → 确认 → 操作详情。手机每步只突出必要字段；平板允许表单与摘要并排。高级字段按需展开。

| 来源 | 输入与反馈 |
| --- | --- |
| 镜像 | 镜像引用、必要的仓库凭据、端口和工作负载类型；服务端固定实际镜像身份 |
| Java | 当前模板要求的 JAR/归档格式及启动参数；无有效入口时明确报错 |
| .NET | 发布归档及模板所需入口/运行时信息；区分框架依赖与自包含 |
| Python | 项目归档、入口和符合当前模板的锁定依赖；安装发生在构建阶段 |

字段、必填项、默认端口从当前模板契约消费，不在 Android 复制一套运行时版本表。密钥引用与普通环境变量分开，不在确认摘要回显秘密值。

## 4. 上传和操作状态

手机文件通过 Storage Access Framework 选择。现有普通文件上传与应用部署暂存上传不是同一个契约；接入时明确“直接上传部署暂存”或“文件上传完成后申请部署文件引用”，核对账号归属、有效期、大小和摘要。

不得因为普通文件上传已有续传就宣称部署上传支持续传。若当前暂存接口无法满足大包要求，先演进共享协议，再更新所有调用方。应用包不得整包读入内存。

提交携带当前协议的幂等标识，取得操作 ID 后转为查询。详情分别展示上传、拉取/构建、创建、就绪和发布结果；完成语义由远端决定。超时先查原操作，取消等待最终状态，恢复和通知接入 [AD08](./RelaxKonOS.Mobile.OperationsRecovery.Plan.md)。

应用详情提供概况、操作、日志和版本入口。回滚显示目标修订与停机影响，并明确“数据卷不会随版本回滚”；运行状态未知时保留诊断入口，不能显示为已停止或健康。

## 5. 实施阶段

| ID | 工作 | 完成条件 |
| --- | --- | --- |
| AD02-M1 | Gateway/DTO、Repository、能力与运行时预检、只读列表详情 | wire 与当前 Protocol 一致；错误和未知状态可理解 |
| AD02-M2 | 镜像向导、配置/密钥引用、操作提交与查询 | 手机完成单应用部署并读取真实就绪状态 |
| AD02-M3 | 日志、停止/启动、修订和回滚，接 AD08 | 断线不重复提交；停机与数据语义清晰 |
| AD02-M4 | 三类包输入、上传引用和模板适配 | 手机选择包到运行全程完成，无电脑打包步骤之外的隐含依赖 |

R1 要求 M1–M3；M4 的输入可以是用户已下载的发布包，并不意味着手机能编译任意源码。源码构建由 AD06 覆盖。

## 6. 验收清单

| ID | 场景 | 预期 |
| --- | --- | --- |
| AD02-T1 | 镜像部署、应用停止/启动、查看日志 | 真实 Linux Engine 上成功，端口和健康结果与实际一致 |
| AD02-T2 | Java、.NET、Python 正反样例 | 合法样例运行；入口、平台、依赖错误可定位 |
| AD02-T3 | 重复点击、请求超时、断网和 App 回收 | 同一提交不重复建资源，可回到原操作 |
| AD02-T4 | 镜像不存在、仓库拒绝、磁盘不足、端口冲突、Engine 失联 | 失败阶段与下一步清晰，不用统一“网络错误”掩盖 |
| AD02-T5 | 新版不就绪、回滚、旧镜像缺失 | 不误激活失败版本，真实恢复结果可查，数据卷保留 |
| AD02-T6 | 大包、过期文件引用、切账号、错误归属 | 有界传输、失效可恢复、跨身份引用被拒绝 |

T2 和大包专项随 M4 验收，其余为首轮必需。复用 [部署样例](../../../examples/application-deployments/README.md)，运行证据统一写入 [Mobile Progress](./RelaxKonOS.Mobile.Progress.md)。

# AD06：Android Git 部署与轻量编辑计划

> 状态：待开始，包含新增共享构建能力。优先级：P2。工作量：大。
> 总入口：[无电脑部署路线图](./RelaxKonOS.Mobile.Deployment.Roadmap.md)。

## 1. 目标与首版范围

用户用手机选择仓库、分支/标签和构建入口，由远端拉取、构建并发布。提供受限文本编辑、差异查看和明确的提交/发布动作，解决只有手机时无法本地打包的问题。

首版从带 Dockerfile 的仓库开始；后续增加静态站点及经过验证的运行时构建模板。不包含完整 IDE、调试器、任意 CI 工作流、自动执行 webhook 或集群构建。

## 2. 现有基础与新增边界

复用 [Git 客户端设计](../../../docs/applications/RelaxKonOS.GitClient.md)、[冲突处理](../../../docs/applications/RelaxKonOS.GitClient.ConflictResolution.md) 及 Git 服务端接口。现有应用部署明确排除 Git 源码和任意 Dockerfile，因此本计划必须新增共享的源码输入、构建操作及发布衔接设计。

构建不能依靠 Android 常驻或把 Git 拉取后随意执行宿主 shell 当作完整实现。源码、依赖和 Dockerfile 均可能执行代码，需要独立受限的构建环境、资源配额、超时、上下文边界和清理策略。具体后端在共享构建设计阶段确定。

## 3. 手机流程

仓库地址 → 凭据引用 → 分支/标签 → 构建目录及 Dockerfile → 配置预览 → 解析并固定提交 → 远端构建 → 产物就绪 → 交给 AD02 发布 → 查看日志和访问结果。

发布记录关联仓库、实际提交 SHA、构建定义、构建操作和最终镜像身份。用户选分支后远端再次移动时，当前构建仍绑定已确认的提交；下一次更新显式解析新的提交。

手机编辑器优先覆盖小型文本配置，提供编码/大小限制、保存前差异和基线版本检查。编辑草稿按服务器、账号、仓库与文件隔离；文件含秘密时不持久保存普通草稿。保存、Git 提交、推送和部署是清楚分开的用户动作，保存文件不自动执行代码。

第一版源码部署使用已提交版本。若编辑后要发布，先明确提交本地变更，构建记录绑定该提交；是否推送由用户另行决定，不悄悄纳入未提交工作区。

## 4. 凭据与执行规则

- 仓库 token/SSH 密钥使用独立的服务器侧凭据引用，不进入克隆 URL、构建参数、日志和普通草稿。
- 构建日志脱敏且有界；凭据只在必要阶段按受控方式提供，不固化到镜像层或构建上下文。
- 服务端校验仓库来源、构建目录和上下文范围，防止读取仓库外宿主文件。子模块、LFS 和私有依赖在首版明确支持或拒绝。
- 拉取、构建、发布是相关但独立的阶段；构建失败不替换运行中的版本，产物存在也不代表部署健康。
- 源码构建操作使用持久记录和幂等提交；取消、超时和远端重启可核实结果。取消构建不等于删除旧应用。
- 回滚复用已发布产物与配置，不重新构建旧分支来冒充同一版本；数据恢复走 AD08。

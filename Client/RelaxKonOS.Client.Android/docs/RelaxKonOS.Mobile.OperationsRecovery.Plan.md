# AD08：Android 运维与恢复中心计划

> 状态：待开始移动端聚合；领域操作记录已有基础。优先级：P0 任务基础，备份/告警分阶段扩展。
> 总入口：[无电脑部署路线图](./RelaxKonOS.Mobile.Deployment.Roadmap.md)。

## 1. 目标与交付分层

用户离开页面、锁屏、断网或 Android 进程被回收后，仍能核实操作结果，定位失败，并在后续阶段备份和恢复数据。

| 层级 | 内容 | 发布要求 |
| --- | --- | --- |
| 基础层 | 任务入口、领域操作观察、断线核实、日志和重试 | 与 AD01/AD02/AD05 一同进入 R1 |
| 恢复层 | 更新前备份、数据恢复、保留数据卸载与恢复演练 | R2 |
| 告警层 | 事件聚合、持续故障提示、通知策略 | R3，可按已有领域成熟度提前 |

统一的是观察和导航体验，不是强制把安装、容器发布、证书和上传的不同执行状态机合并成一个万能任务引擎。

## 2. 当前基础与数据归属

可复用服务器中心回执、应用部署的操作账本、Android `UploadResumeJournal` 的恢复经验，以及 [事件告警 Goal](../../../docs/applications/RelaxKonOS.EventAlertCenter.Goal.md) 和 [进度](../../../docs/applications/RelaxKonOS.EventAlertCenter.Progress.md)。事件告警仍存在领域接入与验证缺口，不能把新移动页面当作全部告警已就绪。

`RecentOperationJournal` 只记录本进程内的简短成功操作，不作为部署恢复、历史审计或备份目录。普通上传、SSH 安装和应用部署各有自己的权威 ID 与恢复规则，不能直接混用。

本地观察记录至少能够关联稳定服务器/安装身份、账号、领域、资源、操作 ID、最后核验时间及显示摘要；不保存密码、token、私钥、完整请求或日志正文。安装前无 API 登录时，按宿主信任身份和部署契约限定记录归属，不伪造用户登录。

## 3. 基础任务体验

“管理 → 任务与恢复”展示近期操作，主页只显示活动任务或需要处理的结果；从任一业务详情均可回到其原操作。任务行显示目标、当前阶段、核验时间和是否需要处理。

| 观测情况 | 展示与动作 |
| --- | --- |
| 远端明确运行中 | 阶段、真实进度或未知进度；可用时提供取消 |
| 手机失联 | “结果待核实”，保留原任务引用和重连入口 |
| 远端明确成功/失败 | 展示结果、诊断及业务详情链接 |
| 远端记录过期或不存在 | “无法取得原操作记录”，查询目标实际状态，不自动重提 |
| 远端恢复中/已中断 | 使用领域返回的状态及允许动作，不自行猜测成功或可重试 |

重试前重新核对身份、权限、请求和原任务是否已产生副作用；沿用领域幂等规则，不能统一给所有失败加“再执行一次”。本地删除观察记录不删除远端资源。

长时间操作应由远端承担。手机上传阶段使用适用的 Android 后台传输机制和可见进度；通知权限被拒绝时仍可从应用查询。默认不承诺在 App 被终止后即时送达结果通知，可靠远程通知需要另外明确传输与服务端支持。

## 4. 备份与恢复能力

备份是新增跨领域能力，不能把 Docker 卷复制按钮称为数据库一致性备份。共享设计需冻结：备份范围、应用/版本关联、存储目标、加密与密钥管理、校验、保留策略、空间上限、删除与恢复授权。

| 对象 | 首轮要求 |
| --- | --- |
| 应用定义与配置 | 可关联实际修订，秘密通过安全引用或专门加密备份恢复 |
| 持久数据卷 | 明确停机、一致性快照或应用专用方法；记录一致性级别 |
| 数据库 | 使用已支持的一致性备份流程，记录版本与恢复前置 |
| 服务器安装配置 | 按服务器中心共享恢复规则处理，不混入应用版本回滚 |

恢复先预检目标、空间、版本、密钥和冲突，展示将覆盖的数据。优先支持恢复到新实例/新卷验证，再明确替换；恢复失败保留可诊断状态。备份成功必须有可读取与校验结果，是否“可恢复”还需真实恢复演练。

更新前检查是否涉及数据迁移，并说明应用版本回滚不撤销数据变化。未经验证的备份或不兼容快照不能成为“放心升级”的成功提示。

## 5. 告警与诊断

优先接入部署失败、应用持续不健康、磁盘不足、证书异常及备份失败。相同故障按领域事件关联去重，恢复事件关闭对应活动故障；确认告警只表示已读，不表示故障解决。

凭据、请求正文和任意敏感日志不进入通知。用户可按服务器和事件类别配置通知，静默状态不反复打扰。诊断导出明确时间范围、包含内容和目标，不默认上传到外部服务。

## 6. 实施阶段

| ID | 工作 | 完成条件 |
| --- | --- | --- |
| AD08-M1 | 领域任务观察接口、本地无秘密索引、任务列表和详情 | AD01/AD02/AD05 原操作可定位；不重复定义执行状态机 |
| AD08-M2 | 重连、账号切换、进程回收、取消和失效记录处理 | 手机生命周期变化不会误报结果或重做副作用 |
| AD08-M3 | 共享备份恢复契约、受支持对象与 Android 流程 | 备份和恢复在真实数据上演练通过 |
| AD08-M4 | 领域事件接入、告警投影、通知与诊断 | 事件去重、恢复与通知语义可验证 |

M1–M2 是 R1 前置；M3–M4 不阻塞首次部署，但未完成时不得宣称具备完整灾难恢复和可靠后台推送。

## 7. 验收清单

| ID | 场景 | 预期 |
| --- | --- | --- |
| AD08-T1 | 活动任务中离开页面、锁屏、旋转与回收进程 | 重开后定位同一领域操作并读取真实结果 |
| AD08-T2 | 断网、服务端重启、操作记录过期 | 结果未知与失败分开，不重复提交副作用 |
| AD08-T3 | 切账号、切服务器、隧道换端口、宿主重装 | 记录归属正确，不向其他身份展示任务或凭据 |
| AD08-T4 | 取消竞争、重复重试、最终结果迟到 | 以远端终态为准，取消按钮不伪造取消完成 |
| AD08-T5 | 拒绝通知权限、App 被终止 | 应用内可查；未实现可靠推送时不作即时到达承诺 |
| AD08-T6 | 活跃数据库备份、备份损坏、空间不足及密钥丢失 | 按一致性方法执行，明确失败，不生成虚假可恢复状态 |
| AD08-T7 | 新实例恢复及升级后数据格式不兼容 | 校验数据和版本，阻止不兼容覆盖，记录演练结果 |
| AD08-T8 | 重复故障、恢复、确认和敏感输出 | 不重复打扰，确认不关闭故障，通知无秘密 |

T1–T5 为 R1 必需；T6–T8 随恢复与告警阶段执行。证据统一写入 [Mobile Progress](./RelaxKonOS.Mobile.Progress.md)。

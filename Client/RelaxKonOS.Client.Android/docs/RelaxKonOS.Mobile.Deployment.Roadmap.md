# Android 无电脑部署路线图

> 建立日期：2026-09-26。状态：规划已建立，未开始本路线图的功能实现或验收。
>
> 目标：用户只有 Android 手机和一台具备管理权限的远端主机，也能完成首次安装、应用部署、发布访问和持续维护。无需使用电脑、外置 SSH 客户端或本地开发工具链。

## 1. 产品范围与文档关系

这里的“没有电脑”指没有用于操作的桌面设备。应用仍运行在用户已有的 VPS、NAS 或其他受支持的远端主机；本路线图不包含购买云主机、在 Android 本机运行生产容器或集群调度。

Android 负责表单、草稿、输入检查、凭据授权、上传、操作提交和结果展示。远端负责权威校验、构建、部署、守护和持久任务记录。增加移动端业务能力不意味着把服务端执行规则复制到 Kotlin。

本路线图是 [Mobile 设计](./RelaxKonOS.Mobile.Design.md) 与 [V1 设计](./RelaxKonOS.Mobile.V1.Design.md) 的后续扩展。V1 的“不做”清单仍描述原初版范围；本文明确为后续阶段规划 Git、证书、网络发布和轻量编辑。认证、凭据、安全、自适应和国际化规则继续适用。

文档职责：本目录维护 Android 体验、接入计划和验收；共享协议及执行语义仍由对应的根目录领域文档维护。新增跨端接口时，同一变更更新 Protocol、Server、桌面、Android、测试及文档，不保留旧路由、别名或双格式解析。

## 2. 已核对基线

基线日期为 2026-09-26；“已有代码”不代表端到端验收通过。实际进度统一记录到 [Mobile Progress](./RelaxKonOS.Mobile.Progress.md)。

| 范围 | 当前基础 | 本路线图仍需交付 |
| --- | --- | --- |
| Android Shell | Kotlin/Compose、三种宽度布局、登录、凭据、文件传输、监控和进程管理 | 面向部署的完整用户流程 |
| 服务器中心 | 宿主资料、SSH 验证、主机指纹确认；底层 SSH/SFTP、隧道与部署操作层 | 安装界面、发布信任接入、应用级任务恢复和真实宿主验收 |
| 应用部署 | Server/Protocol/桌面已有镜像、Java、.NET、Python 四类来源，操作记录、修订和回滚 | Android 接入；真实 Docker 验收。共享进度仍记录运行期验证缺口 |
| Docker Stack | 服务端有 Docker/Compose 管理接口 | Android 工作流、持久长任务与故障恢复核验 |
| 发布、Git、守护 | 相关服务端领域已有接口与实现 | 手机交互及跨领域编排；Git 到构建发布属于新增能力 |
| 运维 | 领域操作记录与事件告警基础可复用 | 移动聚合、恢复入口、备份恢复及必要的领域事件补齐 |

服务端部署限制见 [应用部署设计](../../../docs/applications/RelaxKonOS.ApplicationDeployment.Design.md) 和 [实施进度](../../../docs/applications/RelaxKonOS.ApplicationDeployment.Progress.md)。现有应用部署不接受 Compose 项目、Git 源码或任意 Dockerfile；这些是后续计划，不能以新 UI 声称已支持。

## 3. 八个实施计划

工作量仅用于相对排序，不是工期承诺。P0 为首个可交付流程，P1 为扩大可用范围，P2 为开发与高级维护。

| ID | 文档 | 优先级 / 工作量 | 前置条件 | 用户获得的结果 |
| --- | --- | --- | --- | --- |
| AD01 | [服务器初始化](./RelaxKonOS.Mobile.ServerBootstrap.Plan.md) | P0 / 中 | SSH、受支持 Linux、可信发行包 | 从干净主机到可登录的 Server |
| AD02 | [应用部署向导](./RelaxKonOS.Mobile.ApplicationDeployment.Plan.md) | P0 / 中 | 可登录 Server、实际可用的部署和 Docker 能力 | 镜像或应用包变成运行中的应用 |
| AD03 | [模板应用库](./RelaxKonOS.Mobile.ApplicationCatalog.Plan.md) | P1 / 中到大 | AD02；公开发布时接 AD05 | 少量必要参数即可部署常见服务 |
| AD04 | [Docker 与 Compose](./RelaxKonOS.Mobile.DockerCompose.Plan.md) | P1 / 大 | Docker/Compose、AD08 任务基础 | 管理容器及带数据库的组合应用 |
| AD05 | [网站发布与网络配置](./RelaxKonOS.Mobile.WebPublishing.Plan.md) | P0 基础 / 中到大 | AD02、实际可用的站点/证书能力及可达网络 | 获得经过检查的访问地址 |
| AD06 | [Git 部署与轻量编辑](./RelaxKonOS.Mobile.GitDeployment.Plan.md) | P2 / 大 | AD02、远端隔离构建任务、AD08 | 从仓库直接发布，无需电脑打包 |
| AD07 | [终端、脚本与守护](./RelaxKonOS.Mobile.TerminalAutomation.Plan.md) | P2；终端可提前 / 中到大 | 终端/守护能力；SSH 路径复用 AD01 | 排错、运行脚本和管理持续任务 |
| AD08 | [运维与恢复中心](./RelaxKonOS.Mobile.OperationsRecovery.Plan.md) | P0 基础，后续扩展 / 分阶段 | 各领域权威操作记录 | 断线恢复、诊断、备份与告警 |

AD01 是新主机用户的入口；已有 Server 的用户可直接使用 AD02 等计划。AD08 的任务观察基础与 AD01/AD02 一起交付，不要求先完成完整备份与告警中心。

## 4. 发布阶段与退出条件

| 阶段 | 交付组合 | 退出条件 |
| --- | --- | --- |
| R0 基础准备 | 明确受支持宿主矩阵、发行签名信任、Docker 权限和真实验收环境；建立 AD08 任务恢复规则 | 环境可复现，前置缺失可在界面解释；关键远端操作有可查询结果 |
| R1 首次部署 | AD01 首次安装、AD02 镜像部署、AD05 基本站点发布、AD08 任务观察 | 干净 Linux 主机到可访问应用全程用手机完成；支持断网重连和失败定位 |
| R2 日常可用 | AD02 其余三类来源、AD03 首批模板、AD04 组合部署、AD08 备份恢复 | 包部署和组合应用可更新、持久数据可恢复；通过对应真实环境验收 |
| R3 开发与维护 | AD06、AD07 完整能力，AD05 内网发布扩展，AD08 告警 | 仓库到发布、脚本守护及故障恢复均可独立在手机完成 |

R1 的端到端验收宿主必须具备已验证的容器运行条件。不能只装好 Server 就宣布可部署应用：缺 Docker、网络不可达或权限不足时，要给出可执行的下一步；支持自动安装依赖前，必须先定义对应的共享安装操作及授权。User Mode 不自动获得系统 Docker、站点或防火墙权限。

## 5. 共同交互与执行要求

- 保留“主页 / 文件 / 终端 / 管理 / 更多”导航。未实现功能不显示占位入口；服务器中心在未登录时也可进入。
- 手机使用逐步表单与独立详情；平板使用列表/详情和日志双栏。键盘弹出、大字体与横屏下主操作可达。
- 表单草稿按稳定服务器身份和账号隔离；不得把密码、令牌或私钥存进导航参数、草稿、恢复日志或错误报告。
- 能力是否存在、执行身份是否可用、资源是否授权分别判断。客户端检查用于反馈，服务端仍作最终校验。
- 操作提交后取得领域操作 ID；本地记录其所属域、稳定目标身份和最后核验时间。重复点击或超时重试不能重复创建资源。
- 页面关闭不等于取消；取消请求不等于远端已停止。失联显示“结果待核实”，重新读取权威状态后才报成功。
- 初次安装由独立 SSH/部署启动器执行；已安装后的构建和部署由远端后台任务执行，均不能依赖手机常驻。
- 日志有界、可暂停自动滚动；未知进度显示阶段，不编造百分比。轮询先形成可恢复闭环，实时流只作增强。
- 三套 `strings.xml` 同步维护；沿用现有视觉令牌和桌面镜像图标。

Android 后台执行机制参考 [官方后台任务说明](https://developer.android.com/develop/background-work/background-tasks)；实现时按目标 SDK 核对适用机制。本路线图不承诺前台服务永不被终止。

## 6. 验收与进度纪律

每个计划的验收表均为待执行要求。本次只建立文档，没有新增业务代码、执行设备测试或取得功能验收证据。

| 层级 | 必须留下的证据 |
| --- | --- |
| 契约与逻辑 | DTO/枚举/问题码一致，幂等、身份隔离、状态恢复和错误映射的检查结果 |
| 真实远端 | 宿主 OS/架构、安装模式、Engine/Compose 版本、提交、步骤、脱敏结果 |
| Android | 手机竖横屏、8/11 英寸级平板、三语、大字体、通知拒绝、旋转和进程回收 |
| 故障恢复 | 断网、客户端被回收、远端重启、磁盘/端口/权限错误及恢复结果 |

状态使用“待开始 / 实施中 / 已实现待验证 / 已验收 / 阻塞”。编译通过、模拟通过、真实运行通过分别记录；跳过不计通过。后续实施在 Mobile Progress 用 AD01–AD08 和阶段/验收 ID 关联证据，避免再创建第二套进度真源。

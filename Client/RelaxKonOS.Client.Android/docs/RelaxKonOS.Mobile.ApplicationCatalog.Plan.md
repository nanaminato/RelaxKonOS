# AD03：Android 模板应用库计划

> 状态：待开始。优先级：P1。工作量：中到大。
> 总入口：[无电脑部署路线图](./RelaxKonOS.Mobile.Deployment.Roadmap.md)。

## 1. 目标与首批范围

用户选择用途模板，填写必要参数即可部署，无需理解容器命令。首批类别为个人网站、状态监控、文件服务与 Webhook 服务；具体软件、版本、许可证和资源需求在模板验收时确定，本计划不代表这些应用已可安装。

首版只交付少量维护过的单容器模板，依赖 [AD02](./RelaxKonOS.Mobile.ApplicationDeployment.Plan.md)。需要公网访问时接 [AD05](./RelaxKonOS.Mobile.WebPublishing.Plan.md)；多服务模板必须等 [AD04](./RelaxKonOS.Mobile.DockerCompose.Plan.md) 的管理与恢复语义完成。

不建设用户随意上传执行脚本的市场，不接受模板绕过现有权限和挂载限制。

## 2. 现有基础与新增能力

现有 `ApplicationTemplates` 是 Java/.NET/Python/镜像等运行时模板，不等于产品应用目录。本计划新增“应用用途、配置表单与部署定义”的模板层，底层仍使用当前应用部署领域。

模板契约属于跨客户端能力，实施时应在共享 Protocol 和服务端领域文档定义；Android 文档只维护消费方式，不把模板 schema 固定在 APK 内。模板必须可追踪来源与版本，不能远端更新后静默改变已安装应用。

## 3. 模板所需信息

以下是待在共享设计中冻结的需求，不是现有 DTO 字段声明。

| 信息 | 用途 |
| --- | --- |
| 稳定模板 ID、模板版本、发布者与来源 | 审核、更新与问题追踪 |
| 应用用途、支持架构、最低资源、必要能力 | 安装前兼容性检查 |
| 镜像及版本固定策略 | 可复现发布；最终记录真实镜像身份 |
| 字段类型、必填、校验、默认值、三语标签 | Android 原生生成文本、数字、枚举与秘密输入控件 |
| 命名卷、端口、健康检查与资源建议 | 将配置映射到受管部署定义 |
| 更新、备份、数据迁移和卸载说明 | 用户了解维护影响 |

模板只描述受限字段和资源，不下发任意 UI 代码或 shell 片段。客户端校验帮助输入，服务端重新验证模板、字段和最终定义。

## 4. 手机流程

“管理 → 应用部署 → 从模板安装”展示模板用途与兼容状态。打开详情后，显示预计资源、持久数据位置、访问方式与必要前置；填写字段后展示配置摘要，再交给 AD02 的操作详情。

秘密字段不进入草稿和摘要；默认密码不能硬编码或在普通日志展示。需要初始凭据的模板必须给出独立的受控获取或设置方式。

已安装应用保留实际模板版本和配置快照。模板有更新时先比较变更和数据影响，再明确发起更新；模板撤回不擅自停止已部署应用。发现不支持的 schema 时阻止安装并说明客户端能力缺口，不尝试双格式解析。

## 5. 实施阶段

| ID | 工作 | 完成条件 |
| --- | --- | --- |
| AD03-M1 | 冻结共享模板契约、可信目录分发及校验 | 一个模板能生成合法部署定义，无法注入任意宿主操作 |
| AD03-M2 | 目录、详情、原生动态表单与 AD02 衔接 | 手机完成模板安装，字段与错误均有三语文案 |
| AD03-M3 | 首批模板真实环境验证 | 每个模板记录资源、架构、版本、升级和数据恢复证据 |
| AD03-M4 | 模板更新说明、差异预览与版本关联 | 已安装实例不受目录静默更新影响 |

## 6. 验收清单

| ID | 场景 | 预期 |
| --- | --- | --- |
| AD03-T1 | 选模板、填必填项、安装、打开服务 | 全程无需命令和配置文件编辑 |
| AD03-T2 | 架构/能力/资源不匹配、模板来源不可验证 | 提交前明确阻断并指出缺失条件 |
| AD03-T3 | 非法端口、缺秘密、不支持字段或 schema | 客户端提示且服务端独立拒绝 |
| AD03-T4 | 模板更新、撤回与安装期间目录变化 | 实例绑定的版本可追踪，不发生静默替换 |
| AD03-T5 | 每个首批模板更新、卸载保留数据、恢复 | 数据行为符合模板说明；升级失败可诊断 |

所有首批模板逐个验收，不能用一个模板通过代替整目录。进度记录到 [Mobile Progress](./RelaxKonOS.Mobile.Progress.md)。

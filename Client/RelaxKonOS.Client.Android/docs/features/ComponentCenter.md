# 组件中心（Android）

## 1. 入口与前提

“管理”应用目录中提供“组件中心”入口，与其它应用图标并列。入口只在当前会话的服务器描述携带 `server.host.capabilities.privilegedOperations` 时出现；该能力缺失时服务器不会注册组件路由，界面也不显示一个只能得到 404 的入口。

入口不按单个产品能力过滤：组件状态描述的是宿主软件，不是某个应用是否启用。能否变更由每个组件自己的安装能力与提权决定，页面按实际状态显示动作，不以隐藏入口代替服务端校验。

## 2. 页面内容

组件按服务器管理的宿主软件列出：

| 组件 ID | 界面名称 | 关联应用 | 本页动作 |
| --- | --- | --- | --- |
| `nginx` | Nginx | 站点管理 | 状态、安装/更新/卸载（系统包）、当前实例选择 |
| `mihomo` | Mihomo | 代理管理器 | 状态、打开运行时页 |
| `sing-box` | 代理服务端 | 代理服务端 | 状态、打开运行时页 |
| `docker` | Docker | Docker 管理器 | 状态、安装/更新/卸载（系统包） |
| `samba` | SMB 文件服务 | SMB | 状态、安装/更新/卸载（系统包） |
| `squid` | Squid | 网关代理 | 状态、安装/更新/卸载（系统包） |
| `frpc` | FRP 隧道（客户端） | 隧道 | 状态、打开运行时页 |
| `frps` | FRP 隧道（服务端） | 隧道 | 状态、打开运行时页 |

`git` 不出现在本页：Android 当前不提供 Git 工作流。

每个组件卡片显示所有权（受管、外部、未安装、未知）、实测版本、安装模式、目标平台、恢复提示与问题码；“详情”补充宿主、修订、目标平台和待处理操作 ID。

## 3. 安装、更新与卸载

只有服务器把该组件报告为**系统包**（`systemPackage`）、状态可读、当前会话是 controller，并且对应模块能力存在时，卡片才显示变更动作。动作还按所有权区分：只有未安装时显示“安装”，只有受管安装时显示“更新/卸载”；外部安装没有变更按钮，因为本页不能替宿主接管它。待恢复组件不显示变更按钮，应先进入“任务与恢复”。托管归档（Windows Nginx、frpc/frps 等）需要明确版本或文件，改动由对应应用页或运行时页完成；本页不猜测发布来源。

流程与桌面端组件中心一致：

1. 用户在卡片上选择动作（未安装时只有“安装”，已安装时显示“更新”和“卸载”）。
2. 客户端用用户刚才看到的宿主、模式与 `expectedRevision` 构造组件计划请求，服务端返回冻结目标；协调器拒绝或返回问题时直接显示稳定问题码，不提交安装。
3. 确认对话框显示动作、目标组件与“保留业务数据”的说明。取消不产生请求。
4. 确认后用同一冻结请求构造域安装请求（`frozenPackage`），交给该组件的安装台账：同一幂等键、同一提权流程、同一持久操作记录。Android 复用应用页已有的 `InstallationRepository`，不新增第二条安装通道。
5. 服务器接受后显示操作 ID，可直接进入“任务与恢复”查看进度、取消（若可取消）与恢复入口；返回组件页时重新读取状态。

卸载只冻结组件卸载，默认保留业务数据与配置；删除数据仍走各领域自己的显式操作，不能由本页复选框推断。

## 4. 当前 Nginx

Nginx 卡片提供“当前 Nginx”，读取宿主全局选择并列出受管或已集成实例：

- 只有一个实例且没有显式选择时，服务器把它解析为当前实例，页面显示该实例，无需手动选择。
- 选择写入宿主全局设置（同一宿主的所有客户端共享）；只允许选择服务器当前列出且可用的 Nginx 实例。
- 已保存实例消失时保持不可用，不自动切换到另一个实例。
- 页面显示实例 ID、管理方式与版本，选择成功后刷新当前标记；失败显示稳定问题码。

## 5. 数据与读取规则

- 每个组件读取一次 `GET /api/v1.0/components/{componentId}/state`；计划读取 `POST /api/v1.0/components/{componentId}/plan`，应用通过 `POST /api/v1.0/installations/{service}/{kind}`。
- 单个组件读取失败只影响该行；401/403 与全部传输失败按整页错误处理；旧会话的迟到响应不能填充新会话界面。
- 页面进入时读取一次，“刷新”重新读取；不轮询。
- 计划结果中的 `request`/`target` 原样保留并提交，客户端不重建包、版本或来源；组件身份或变更类型与请求不一致时拒绝使用该计划。

## 6. 明确不做

- 不在本页选择托管归档版本、上传安装包或输入版本号；这些仍由应用页/运行时页完成。
- 不提供修复、回退、批量变更或 TaskPlan 草稿；服务器端组件中心继续拥有这些能力。
- 不绕过提权：安装台账要求管理员密码时沿用全局提权对话框。
- 不删除业务数据、配置或受管软件；组件卸载与应用卸载、软件卸载是不同操作。
- 不根据登录人数或页面停留时间触发任何变更。

## 7. 验证

自动化：

```powershell
gradle :app:compileDebugKotlin
gradle :app:assembleDebug
gradle :app:testDebugUnitTest --tests "app.relaxkonos.mobile.core.net.ComponentWireTest" `
    --tests "app.relaxkonos.mobile.data.ComponentRepositoryTest"
```

- `ComponentWireTest`：受管状态、平台不支持、仅待处理操作表示恢复、组件身份不匹配、未知所有权。
- `ComponentRepositoryTest`：按请求顺序读取、单组件失败隔离、全部传输失败折叠、缺少 `privilegedOperations` 时发请求前拒绝、会话切换取消；计划请求携带用户看到的修订/模式；冻结包通过安装台账提交（`frozenPackage`）、FRP 使用 `frozenArchive`、未知组件无安装归属；当前 Nginx 读取与切换。

完整单元测试套件中，`ProxyViewModelTest` 与 `SingBoxRuntimeViewModelTest` 存在与本页无关的既有失败（在干净 `HEAD` 工作树上同样复现）；组件检查独立通过。

界面检查按[界面与流程复查要求](../development/UiReview.md)在手机与平板尺寸、明暗主题及三种语言下查看确认：动作按钮、确认对话框、操作结果与 Nginx 选择对话框可见且没有未翻译文本；该检查不替代真实宿主的安装、更新或卸载验收。

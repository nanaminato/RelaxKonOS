# 组件中心（Android）

## 1. 入口与前提

“管理”应用目录中提供“组件中心”入口，与其它应用图标并列。入口只在当前会话的服务器描述携带 `server.host.capabilities.privilegedOperations` 时出现；该能力缺失时服务器不会注册组件路由，界面也不显示一个只能得到 404 的入口。

入口不按单个产品能力过滤：组件状态描述的是宿主软件，不是某个应用是否启用。能否变更由每个组件自己的安装能力与提权决定，页面按实际状态显示动作，不以隐藏入口代替服务端校验。

## 2. 页面内容

组件按服务器管理的宿主软件列出：

| 组件 ID | 界面名称 | 关联应用 | 本页动作 |
| --- | --- | --- | --- |
| `nginx` | Nginx | 站点管理 | 状态、安装/更新/卸载（系统包）、当前实例选择 |
| `mihomo` | Mihomo | 代理管理器 | 状态、打开运行时页 |
| `sing-box` | 代理服务端 | 代理服务端 | 状态、打开运行时页 |
| `docker` | Docker | Docker 管理器 | 状态、安装/更新/卸载（系统包） |
| `samba` | SMB 文件服务 | SMB | 状态、安装/更新/卸载（系统包） |
| `squid` | Squid | 网关代理 | 状态、安装/更新/卸载（系统包） |
| `frpc` | FRP 隧道（客户端） | 隧道 | 状态、从服务器固定版本安装、打开运行时页 |
| `frps` | FRP 隧道（服务端） | 隧道 | 状态、从服务器固定版本安装、打开运行时页 |

`git` 不出现在本页：Android 当前不提供 Git 工作流。Mihomo 与 sing-box 的安装/更新/回退仍由各自运行时页承担，本页只显示状态并提供打开对应应用的入口；应用内没有重复的安装入口。

每个组件卡片显示所有权（受管、外部、未安装、未知）、实测版本、安装模式、目标平台、恢复提示与问题码；“详情”补充宿主、修订、目标平台和待处理操作 ID。

## 3. 安装、更新与卸载

只有状态可读、当前会话是 controller，并且对应模块能力存在时，卡片才显示变更动作。动作按所有权区分：只有未安装时显示“安装”，受管安装显示“更新/卸载”；宿主核验出完整包身份的外部系统包也显示“更新/卸载”，但这不会取得长期管理授权，本页也不提供“纳入管理”（该动作只在桌面组件中心）。身份无法核验的外部包、未知状态与待恢复组件不显示普通变更按钮；Tailscale 提供绑定原操作的停止与核对后关账，其余组件进入“任务与恢复”。

- **系统包**（`systemPackage`）：安装/更新/卸载都由服务器自己的包管理器冻结，客户端不提交包名、版本或仓库。外部包更新冻结服务器解析出的候选与依赖，同时冻结当前安装身份；外部包卸载只冻结该身份，不依赖候选仓库或旧下载地址。受管包被外部 `apt` 更新后，卡片显示“已核实外部变化”及原记录版本到当前版本；仍保留管理授权，不把新版本当作原安装回执。
- **受管归档**（`managedArchive`）：FRP 的 frpc/frps 由服务器提供一组固定版本（`pinnedArchives`）。卡片显示“选择版本”，选中的版本连同其 `releaseId`、固定版本修订一并进入计划；客户端不提交 URL、摘要或任意版本号，服务器未固定的版本无法选择，冻结目标不是该固定版本时计划被拒绝。归档只提供首次安装；更新、修复、回退与卸载仍按服务器能力显示，当前 FRP 归档没有这些动作。
- **系统安装程序**（`nativeInstaller`）：Windows Tailscale 使用宿主 Helper 执行官方 MSI，不走归档解压或手机本机安装。Linux Tailscale 使用官方签名 APT 仓库。两者均先读取宿主状态、冻结计划，再通过 `installations/tailscale` 台账提交安装、真正较新版本的更新或保留配置与登录数据的卸载；外部 Windows 实例只能观察，不自动接管；外部 Linux 系统包在宿主核验完整包身份后可按系统包规则更新或卸载，但仍不被登记为受管。
- Tailscale 计划确认展示宿主、版本、来源和 SHA-256，提示网络服务变更可能中断连接。冻结计划的幂等键必须沿用到提交、持久请求索引与显式重试，不能另生成一个键。取消确认不发送安装请求。
- Linux 来源缺失时，须显式确认 Tailscale 官方稳定版仓库与固定签名密钥指纹，再由宿主配置并刷新索引；已有冲突来源或密钥不会被替换。“刷新软件包索引”只刷新已授权来源。待恢复时可绑定原操作停止服务或核对后关账；关账不会伪造原安装成功。
- Windows Nginx 等不能由本页执行的归档只显示状态与说明，不显示安装按钮。
- 已安装的 FRP 还可在本页升级（输入目标版本）、回退（修复到上一版本）与卸载；受管 Nginx 可在本页卸载。动作经同一领域安装台账提交，沿用提权、幂等与待恢复语义。运行中的应用不再提供这些按钮。
- FRP 与 Nginx 还提供“从文件安装”：可选用服务器上已有的归档或上传本机归档，填写归档包含的版本并建立文件引用，随后以 `FrpInstallationRequest` / `NginxInstallationRequest(confirmed, version, fileReferenceId)` 进入该组件所属服务的安装台账。引用与当前操作者绑定并会过期；服务器仍校验平台、身份与内容。归档版本以操作者填写和文件引用为准，本页不解析归档内部版本。

流程与桌面端组件中心一致：

1. 用户在卡片上选择动作（未安装时只有“安装”，已安装时显示“更新”和“卸载”）。
2. 客户端用用户刚才看到的宿主、模式与 `expectedRevision` 构造组件计划请求，服务端返回冻结目标；协调器拒绝或返回问题时直接显示稳定问题码，不提交安装。
3. 确认对话框显示动作、目标组件与“保留业务数据”的说明。取消不产生请求。
4. 确认后用同一冻结请求构造域安装请求：系统包与 Windows Nginx 走 `frozenPackage`，FRP 归档走 `frozenArchive`；两者都交给该组件的安装台账，使用同一幂等键、同一提权流程、同一持久操作记录。Android 复用应用页已有的 `InstallationRepository`，不新增第二条安装通道。
5. 服务器接受后显示操作 ID，可直接进入“任务与恢复”查看进度、取消（若可取消）与恢复入口；返回组件页时重新读取状态。

卸载只冻结组件卸载，默认保留业务数据与配置；删除数据仍走各领域自己的显式操作，不能由本页复选框推断。

## 4. 当前 Nginx

Nginx 卡片提供“当前 Nginx”，读取宿主全局选择并列出受管或已集成实例：

- 只有一个实例且没有显式选择时，服务器把它解析为当前实例，页面显示该实例，无需手动选择。
- 选择写入宿主全局设置（同一宿主的所有客户端共享）；只允许选择服务器当前列出且可用的 Nginx 实例。
- 已保存实例消失时保持不可用，不自动切换到另一个实例。
- 页面显示实例 ID、管理方式与版本，选择成功后刷新当前标记；失败显示稳定问题码。

## 5. 数据与读取规则

- 每个组件读取一次 `GET /api/v1.0/components/{componentId}/state`；计划读取 `POST /api/v1.0/components/{componentId}/plan`，应用通过 `POST /api/v1.0/installations/{service}/{kind}`。
- 单个组件读取失败只影响该行；401/403 与全部传输失败按整页错误处理；旧会话的迟到响应不能填充新会话界面。
- 页面进入时读取一次，“刷新”重新读取；不轮询。
- 计划结果中的 `request`/`target` 原样保留并提交，客户端不重建包、版本或来源；组件身份或变更类型与请求不一致时拒绝使用该计划。
- 状态中的 `installedPackage` 是宿主独立核验的包名、版本、架构与程序 SHA-256；只在它存在且 `recoveryRequired` 为假时，外部系统包才允许更新或卸载。`externalPackageChange` 与 `recordedPackageVersion` 只用于提示受管包经外部更新后的版本变化，不能据此推断原安装操作成功。

## 6. 明确不做

- 不在本页上传安装包或输入版本号；受管归档只能在服务器固定的版本中选择，未固定的版本一律不可安装。
- 不提供修复、回退、批量变更或 TaskPlan 草稿；服务器端组件中心继续拥有这些能力。
- 不绕过提权：安装台账要求管理员密码时沿用全局提权对话框。
- 不删除业务数据、配置或受管软件；组件卸载与应用卸载、软件卸载是不同操作。
- 不根据登录人数或页面停留时间触发任何变更。

## 7. 应用内依赖入口与进入提示

每个依赖宿主组件的应用在自己的动作行提供一个“组件依赖”入口（Docker 工作区、站点、SMB、Squid、代理管理器、代理服务端、隧道）：

- 入口只读取当前状态：组件名称、所有权与实测版本；底部一句说明安装/更新/修复/回退/卸载只在组件中心进行，并提供“前往组件中心”和关闭按钮。它不安装、不修改、不上传文件。
- 进入应用时读取同一状态路由（`GET /components/{id}/state`）。**只有实测未安装、待恢复或执行中**才拦截：未安装提示“需要组件”并可前往组件中心，待恢复/执行中提示先处理“任务与恢复”；取消不会打开应用，而是返回上一页。
- 已安装（含服务停止）、外部安装、宿主不支持的平台、状态未知或读取失败都不拦截：读取失败不能把用户锁在应用外，也不能把未知当作未安装。
- 隧道把 frpc 与 frps 视为可替代依赖：任一已安装即可进入；否则按“待恢复 > 执行中 > 缺失 > 未知”的顺序给出提示。
- 应用动作行入口不替代组件中心的卡片：能否变更仍由组件中心按所有权、controller 与模块能力决定。

## 8. 验证


自动化：

```powershell
gradle :app:compileDebugKotlin
gradle :app:assembleDebug
gradle :app:testDebugUnitTest --tests "app.relaxkonos.mobile.core.net.ComponentWireTest" `
    --tests "app.relaxkonos.mobile.data.ComponentRepositoryTest" `
    --tests "app.relaxkonos.mobile.ui.manage.components.ComponentDependencyRulesTest"
```

- `TailscaleComponentWireTest`：Windows x64/ARM64 官方 MSI 冻结元数据、拒绝篡改来源/摘要/架构、独立安装目标、维护请求及宿主提权目标。`TailscaleInstallationReviewTest` 使用生产确认框检查大字体滚动、取消不提交、卸载保留数据提示和忙碌门禁；模拟界面不代表 Windows 原生安装验收。
- `ComponentWireTest`：受管状态、外部系统包的已核验身份与外部版本变化、平台不支持、仅待处理操作表示恢复、组件身份不匹配、未知所有权、固定归档解析（身份/摘要/适用范围）与归档计划体（`host-pins`、固定版本修订、`releaseId`），以及系统包计划不带归档身份。
- `ComponentRepositoryTest`：按请求顺序读取、单组件失败隔离、全部传输失败折叠、缺少 `privilegedOperations` 时发请求前拒绝、会话切换取消；计划请求携带用户看到的修订/模式；冻结包通过安装台账提交（`frozenPackage`）、FRP 使用 `frozenArchive`、未知组件无安装归属；当前 Nginx 读取与切换。
- ComponentDependencyRulesTest：缺失仅指实测未安装、外部/未知/不支持的平台不拦截、待恢复与执行中优先于同组件的缺失、替代依赖任一就绪即通过、空或读取失败不拦截，以及路由到组件的映射（含隧道替代与 Docker 子路由）。

完整单元测试套件中，`ProxyViewModelTest` 与 `SingBoxRuntimeViewModelTest` 存在与本页无关的既有失败（在干净 `HEAD` 工作树上同样复现）；组件检查独立通过。

界面检查按[界面与流程复查要求](../development/UiReview.md)在手机与平板尺寸、明暗主题及三种语言下查看确认：动作按钮、确认对话框、操作结果与 Nginx 选择对话框可见且没有未翻译文本；该检查不替代真实宿主的安装、更新或卸载验收。

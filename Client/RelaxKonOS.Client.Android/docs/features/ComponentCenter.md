# 组件中心（Android）

## 1. 入口与前提

“管理”应用目录中提供“组件中心”入口，与其它应用图标并列。入口只在当前会话的服务器描述携带 `server.host.capabilities.privilegedOperations` 时出现；该能力缺失时服务器不会注册组件状态路由，界面也不显示一个只能得到 404 的入口。

入口不按单个产品能力过滤：组件状态描述的是宿主软件，不是某个应用是否启用。看到组件不等于拥有变更权限；本页不提供任何变更操作。

## 2. 页面内容

页面顶部说明目标是当前登录服务器，并明确本页只读。组件按服务器管理的宿主软件列出：

| 组件 ID | 界面名称 | 关联应用 |
| --- | --- | --- |
| `nginx` | Nginx | 站点管理 |
| `mihomo` | Mihomo | 代理管理器 |
| `sing-box` | 代理服务端 | 代理服务端 |
| `docker` | Docker | Docker 管理器 |
| `samba` | SMB 文件服务 | SMB |
| `squid` | Squid | 网关代理 |
| `frpc` | FRP 隧道（客户端） | 隧道 |
| `frps` | FRP 隧道（服务端） | 隧道 |

`git` 不出现在本页：Android 当前不提供 Git 工作流，列出它会产生一个没有对应应用的组件入口。

每个组件卡片显示：

- 所有权：受管、外部、未安装或未知；外部安装不等于受管，未安装不等于服务已停止。
- 实测版本；服务器没有报告版本时显示“未知”，而不是猜测。
- 安装模式：受管归档或系统包。
- 恢复提示：状态或待处理操作表明需要恢复时，显示提示并给出“任务与恢复”入口。
- 关联应用入口：打开消费该组件的应用，不触发安装或变更。

“详情”对话框补充宿主 ID、修订号、目标平台（OS / 架构 / 服务宿主）、问题码和待处理操作 ID。所有字段来自服务器同一次状态读取，不由客户端推导。

## 3. 数据与读取规则

每个组件读取一次 `GET /api/v1.0/components/{componentId}/state`，路径与共享 `ComponentRoutes` 一致，响应按共享 `ComponentStateView` 解析：

- `state` 为 null 时仍保留 `modes` 与 `problems`，因此“平台不支持”与“服务器读不到状态”可以区分。
- 单个组件读取失败只影响该行：该行显示稳定问题码或“状态不可用”，其它组件照常显示。
- 401/403 视为整页拒绝，显示错误与重试，不伪造成每行未知。
- 全部请求都是传输失败时显示整页错误，不渲染一组“未知”行。
- 会话切换、服务器切换或登出会取消读取并清空页面；旧会话的迟到响应不能填充新会话的界面。
- 页面每次进入读取一次；“刷新”重新读取。页面不轮询，不因停留时间自动刷新。

## 4. 明确不做

Android 组件中心是观察入口，不是安装后端：

- 不提供安装、更新、修复、回退或卸载；这些动作需要冻结计划、明确确认和恢复台账，在桌面端或服务器端组件中心完成。
- 不列出可用版本、不冻结来源、不提交计划、不使用提权。Mihomo、sing-box 等应用页已有的安装/运行时入口保持各自现状。
- 不隐藏应用入口：组件未就绪时关联应用仍然可见，由应用自身按依赖状态提示。
- 不把组件卸载与受管软件、配置或业务数据删除混为一谈。
- 不引用桌面组件的完整目录与来源声明；Android 只读取服务器实际注册的组件状态。

## 5. 国际化与主题

新增文案同时存在于 `values/`、`values-zh/`、`values-ja/` 的 `components_strings.xml`。状态、模式、恢复提示与按钮均使用资源键，不内嵌语言判断。页面使用既有主题与 `SectionCard` / `ScreenHeader` / `EmptyState` 组件，不引入新的颜色或间距常量。

## 6. 验证

自动化：

```powershell
gradle :app:compileDebugKotlin
gradle :app:testDebugUnitTest --tests "app.relaxkonos.mobile.core.net.ComponentWireTest" `
    --tests "app.relaxkonos.mobile.data.ComponentRepositoryTest"
```

- `ComponentWireTest`：受管状态、平台不支持、仅待处理操作表示恢复、组件身份不匹配、未知所有权。
- `ComponentRepositoryTest`：按请求顺序读取、单组件失败不隐藏其它行、无状态行保留声明模式、全部传输失败折叠为一次、缺少 `privilegedOperations` 时在发请求前拒绝、会话切换后旧读取被取消。

完整单元测试套件中，`ProxyViewModelTest` 与 `SingBoxRuntimeViewModelTest` 存在与本页无关的既有失败（在干净 `HEAD` 工作树上同样复现）；组件页的检查独立通过。

界面检查按[界面与流程复查要求](../development/UiReview.md)在手机与平板尺寸、明暗主题及三种语言下查看，确认“只读”说明、恢复提示和关联应用入口都可见；该检查不替代真实宿主的组件状态验收。

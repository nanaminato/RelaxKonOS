# Mihomo 代理管理器

概览的运行状态与启停操作集中成卡；启动、停止、重启按钮之间保持 8dp 间距，换行后也保留间距。分类导航下方使用 8dp 留白，已访问的隐藏页面不参与根布局的间隔计算，切换分类不累积顶部空白；订阅、配置详情和节点组分别成卡。独立“操作记录”页承接代理任务、安装/升级/修复/卸载、取消、恢复、原请求重试和待核实写入，其他页面仅显示需要处理时的跳转提示；从外部恢复任务或提交运行时操作会选中记录页。记录不存在时显示明确空状态。

权威运行时状态为未安装时显示一条安装引导，隐藏归档完整性、控制器不可用和节点区的重复诊断；订阅与配置仍可查看。安装入口使用“安装 Mihomo”，历史任务查询收在“恢复之前的操作”后。现有任务、未知写入和安装回执不因未安装空状态被隐藏；已安装但校验失败仍展示诊断。

对应 BP06-M1/M2，入口为“管理 → Mihomo 代理管理器”，按 `server.proxy` 能力显示。观察者只读取；宿主变更要求管理权限。此页管理服务器运行时和网络，手机不运行 Mihomo，也不提供手机 VPN。

## 运行时和任务

安装、升级、修复、回滚与卸载使用公共 Installations 数据层及确认/提权流程。安装支持宿主下载固定可信版本、服务器归档限时引用、手机 SAF 选包后受控上传；包与哈希由服务端校验。升级和修复从宿主下载，回滚通过 Repair 的 rollback 标记读取前一版本。表单检查可信版本，不把任意路径传入安装请求。变更可能停止代理并中断管理连接，确认后提交。

Start/Stop/Restart 使用 Proxy 操作账本。只显示从宿主读取的任务状态，不用提交成功推断运行时健康。Proxy 操作没有取消端点；安装任务仅在最新宿主状态允许时提供取消。离页停止页面观察，宿主任务继续执行；重新进入查询本地索引中的原任务 ID。索引与请求标记按宿主和账户隔离，注销、换宿主或身份后旧响应不能覆盖新会话。

首个响应丢失时，Proxy 队列请求保留原键、动作和目标 ID，显式重试先读取宿主事实再使用原键，不自动重发。接收 ID 后先持久化索引，再查询状态；查询失败仍可按该 ID 恢复。安装使用既有原键/ID 恢复机制，无法证明未知请求归属时须确认确切原 ID。

安装请求已持久关联原任务 ID 时，刷新并核实该 ID、服务和操作类型后自动清除对应待核实标记。尚未关联 ID 的请求仍须明确确认归属；操作记录的安装待核实提示旁提供预填已核实安装 ID 的恢复入口，确认原请求后解除安装阻塞。订阅导入断线留下的同步写入标记须单独接受当前宿主事实，再按实际订阅列表决定是否重新导入。

## 配置、订阅和节点

没有原安装任务 ID 时，用户也可显式接受当前宿主事实解除安装请求标记。客户端重新读取概览和活动安装，只有读取成功且无活动安装才清除本机请求与重试意图；不重发原请求、不推断原请求结果。按 ID 恢复安装仅保留一个入口，并预填已核实的安装 ID。

配置列表可创建、重命名、删除非活动配置、激活已存 YAML，名称更新携带 ExpectedRevision。页面提供完整新 YAML 的校验/应用表单；服务端不提供普通配置 YAML 读取，所以此表单不预填原文。草稿仅在内存保留，关闭有未保存确认。配置加载健康后才更新活动标记；校验失败保留活动配置，重载失败尝试回滚，无法恢复时返回恢复问题码。

订阅来源由用户输入，支持宿主直连或宿主系统代理下载；后者按下载能力启用。来源 URL 在服务端加密，列表不返回来源 URL；本地请求标记不保存 URL、YAML 或节点名称。导入、单项/全量刷新及激活通过当前 API，活动订阅刷新由服务端重新应用配置。

订阅弹窗提交时先读取宿主概览检查管理连接，读取失败不发送导入、不创建待核实写入标记；恢复连接并刷新后可再次提交。连接检查成功后发送导入但响应丢失时仍保留标记，须在操作记录接受当前事实。

控制器可达时读取 Rule/Global/Direct、代理组与当前节点。仅 Selector 组可手动选择，选择请求和延迟请求分别编码 Unicode/空格/斜线等不透明名称。延迟测试从宿主使用 5 秒超时访问 `https://www.gstatic.com/generate_204`，显示毫秒或超时，不作为手机联网质量。

节点页用横向滚动标签切换分组，只展示当前组的紧凑网格；按每列至少 140dp 的可用宽度显示 1–4 列，常规手机显示两列。卡片点击即提交手动选择，不再显示逐行选择按钮或额外确认弹窗；服务器读回确认后才更新选中高亮和勾选标记。自动组显示自动选择提示，观察者和忙碌/未核实状态禁止切换节点。请求正文保留国旗等非 BMP 字符，不将 UTF-16 代理项单独编码为 UTF-8。

当前组右侧的闪电按钮一次测试组内全部节点，最多四个请求并发。每个节点直接显示未测试、测试中、毫秒、超时或测试失败，单节点失败不影响其他结果；进度显示组名和完成数量。测速时仍可浏览其他分组并选择 Selector 组节点，包括正在测速的节点；禁止重复测速，节点切换不打断测速。测速数据只保存在当前宿主/账户会话的内存中，切换会话取消旧响应，不保存到本地请求账本。

同步写入无任务 ID/幂等键。响应未知时持久化不含秘密的动作类型/目标标记并锁定新写入；普通刷新不自动清除标记。用户检查宿主事实后显式接受当前状态，选择/路由还须成功读取对应控制器状态。接受当前事实不宣称原 YAML 或导入请求已成功。

## 布局与验证

手机配置列表与详情切换；可用宽度至少 600dp 时显示配置列表/详情双栏。表单滚动并避让 IME，中文/英文/日文文案同批维护。安装与代理操作接入运维中心；Proxy 任务不能显示无效取消入口。

## 宿主网络与诊断

设置页参照桌面端按 GeoData、系统设置、Mihomo 常规设置分卡。系统设置以紧凑行显示宿主 TUN、系统代理的当前状态、开关和各自的设置入口；恢复异常直接显示，正常恢复标记与时间收在 TUN 设置中。紧急关闭入口始终保留。长宿主网络说明放在 TUN 弹窗内。DNS 诊断默认折叠，展开后查看状态、读取时间和刷新入口，不再使用“流量、连接与有界日志”作为设置页标题。

设置页读取完整 Mihomo 设置、TUN 状态与持久恢复标记。TUN 启用按平台支持、控制器可达、管理路径安全、活动配置与无遗留标记门控；启用/关闭走原键 Proxy 操作，服务端观察真实远端地址并保存管理路径保护快照。紧急关闭不依赖控制器健康或普通写入已核实，可另存独立恢复键，同时保留先前未知请求；恢复响应丢失后可用原键再次请求，不要求概览先恢复健康。页面会展示原任务 ID/待核实，不把断线当作 TUN 已关闭。

系统代理读取必需的 `platformCapabilities.systemProxy` 四项实际能力，不再按宿主操作系统名称门控。Linux System Mode 可配置新的 PAM 登录环境与当前已登录的本地 GNOME/KDE 用户，弹窗分别说明当前桌面检测结果、生效范围及 Linux 绕过规则；桌面应用须使用 GNOME/KDE 系统代理设置，终端环境变量供新的登录会话使用，已有进程和独立 systemd 服务不会自动更新。宿主通过提权 Helper 修改全局环境，并以桌面用户身份修改桌面设置；启用前持久保存原值。Windows 仍要求交互用户会话，系统服务不能代写登录用户设置。PAC 仅支持它的宿主显示和提交。能力暂不可用时仍允许关闭已启用的代理；宿主写入冲突提供“关闭并恢复”入口，恢复保留用户之后修改的键。Linux Docker/下载等受管消费代理由独立宿主出站页面配置。Server、Helper 1.4 与客户端须同步升级，单独更新 APK 不会增加宿主能力。

编辑拆为独立的 Mihomo、TUN、系统代理弹窗：常规设置覆盖混合端口、监听地址、LAN、DNS、IPv6、统一延迟、不安全订阅来源与日志级别；TUN 设置覆盖 stack/device/MTU/自动路由/严格路由/接口检测/DNS Hijack；系统代理设置覆盖可用的 PAC 自动检测、代理守护/间隔、默认与自定义绕过，代理地址跟随常规设置中的监听地址。开关按行排列，日志级别和 TUN 协议栈用下拉选择。各弹窗独立保留草稿、关闭确认与应用确认，保存更新完整当前对象并保留其他分组字段；修改其他字段保留 TUN 会话由服务端负责，设置保存不会隐式启用 TUN。同步响应未知时须读取当前设置再接受事实。

连接、日志、设置分别读取本页所需的诊断数据，每 3 秒自动采样，离开这些页面即停止发起新的观察。连接列表与流量并行读取，连接先完成便先显示，不等待流量或其他页日志；单次观察失败显示读取错误并允许下一轮重试，不再由流量错误阻断连接观察。自动观察使用独立忙碌状态，刷新按钮内显示进度，不改变内容位置，不阻塞已核实的关闭连接操作。

连接按能力显示，最多展示 200 项并标记截断；卡片展示协议、来源与目标地址/端口、规则和代理链，零连接有明确空状态，并说明仅显示经过宿主代理的请求。关闭连接需要确认，成功后移除对应卡片。日志每次请求最近 100 条服务端有界脱敏记录，当前会话去重累计最多 500 条；空日志也有说明。DNS 按引擎能力门控。GeoData 由服务器文件选择器选择服务账户可读文件，服务端校验暂存，仅返回配置标记与字节数。上述行为全部作用于宿主，手机不提供 VPN。

受管出站来源与 Docker/下载消费仍由独立宿主出站设置拥有，见 [宿主出站代理](OutboundProxy.md)。真实宿主联网、设备交互与安装验收独立记录于 [Verification](../status/Verification.md)。

## Mihomo 安装版本选择

安装表单的服务器文件、手机文件和“我要自行下载”流程见 [公共安装来源](Installations.md#安装来源与自行下载)。手机选择的是供宿主安装的归档。

运行时管理弹窗通过宿主的 `GET /api/v1.0/proxy/runtime/releases` 获取与宿主系统、架构匹配且通过受信清单校验的版本，默认选择推荐版本。用户可以切换版本或刷新列表；获取失败可重试，空列表时禁止安装。恢复已有安装请求时保留原请求版本。当前受信清单支持 v1.19.30，归档 SHA-256 校验仍由宿主执行。

宿主下载只跟随 GitHub 和其归档 CDN 的 HTTPS 重定向，最多五次，下载总超时为五分钟。归档上传在关闭输出流后登记长度，避免缓冲尾部使引用失效。Linux 系统服务安装器为 Server 配置私有 HOME，确保控制器加密密钥在服务重启后仍可读取。

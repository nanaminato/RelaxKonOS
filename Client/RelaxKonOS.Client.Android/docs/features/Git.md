# Android Git 工作区、构建与发布

冲突编辑器打开期间刷新仓库清单保持原仓库目标；原仓库从清单消失或读取失败时保留只读草稿，不自动把冲突输入绑定到另一仓库。关闭编辑器后再选择其他仓库。

冲突读取异常导致仓库事实不可用后，可在编辑器内重读冲突版本：先核实原仓库事实，再读取该冲突，成功后恢复解决入口并保留本地结果草稿。原仓库仍不可读时继续只读并显示原因，不以单独读到冲突正文清除仓库失败，也不自动提交解决结果。

准备变更被拒绝或无法核实后可刷新事实，但刷新成功不清除本次预览失败原因；用户按最新事实重新审阅，不把刷新当作变更准备成功。

冲突编辑器打开期间，准备、读取和提交失败反馈在编辑器内显示，关闭反馈保留冲突草稿；没有冲突表单时反馈显示在工作区主页面，避免表单遮住恢复原因。

每次工作区操作使用独立反馈标识；即使快速重试得到相同错误文案，也重新显示本次反馈，不沿用上一次已确认关闭的状态。

冲突解决结果待核实时，编辑器内显示原仓库及动作的待核实提示，并滚动到该提示；后续解决操作暂停。可直接在原表单显式“读取并采用当前事实”，确认摘要包含仓库名称、ID 和动作；取消或读取失败保留待核实记录与结果草稿，成功只清除对应本机记录，不重放提交。打开冲突草稿时不能采用其他仓库的记录来重新绑定目标。当前事实已不包含该冲突文件时，显示专属说明并禁用旧解决入口，保留结果草稿供核对及显式关闭。

构建状态轮询被拒绝、传输失败或发生意外异常时，停止本次轮询并显示安全错误，保留最后读取的构建记录。取消与会话失效不会误报为传输错误；读取失败不能作为构建终态。

## 1. 仓库工作区

“管理 → Git”按 `server.git` 门控。普通宿主执行身份不可用时显示原因并禁用仓库修改；运行时安装另按宿主平台、安装能力和提权规则处理。注册服务器已有工作树，选择仓库后读取分支、上游、领先/落后、暂存/未暂存/未跟踪文件及当前冲突操作。

页面按职责划分：仓库页负责仓库注册与选择；工作区负责文件差异、编辑、暂存与提交；分支负责切换、创建、删除及 Fetch/Pull/Push；历史负责提交搜索、分页与提交差异；冲突负责冲突解决和继续/中止操作；构建负责远端固定提交构建及镜像发布；环境集中显示 Git 可用性、版本、安装进度、取消和原任务 ID 恢复。

仓库页面共用仓库选择和分支摘要，不重复展示版本或安装表单；环境未就绪时提供前往环境页的入口，没有仓库时提供前往仓库页注册的入口。构建页不显示工作区的仓库选择、安装或状态信息；工作区和历史的差异仅在各自页面显示。无冲突时显示明确的空状态。工作区隐藏空的文件分组，无任何变更时仅显示干净状态；有暂存文件或已有提交草稿时才显示提交表单，文件路径输入通过“打开文件”对话框按需展示，上游信息留在分支页。切换页面保留共享工作区状态，活动安装继续观察并保持仓库写入限制。

### 界面组织与常用操作

界面借鉴 [GitHub Desktop 的分支与提交工作流](https://docs.github.com/en/desktop/making-changes-in-a-branch) 和 [Git 暂存区模型](https://git-scm.com/book/en/v2/Getting-Started-What-is-Git%3F)，适配 Android 触摸操作，不改变现有服务契约。

- 仓库相关页面顶部统一提供当前仓库下拉选择、刷新及分支状态摘要；工作区的打开文件入口放在工具栏。仓库页用名称和完整路径卡片列出已有仓库，点击后进入工作区；注册表单可折叠，没有仓库时默认展开。
- 工作区按未暂存、未跟踪、已暂存分组，每组显示文件数；文件卡片将路径、状态和差异/暂存/编辑动作分开。每组可批量暂存或取消暂存，仍经过完整预览与确认，重命名保留新旧路径并去重；超过现有 5000 路径契约上限时禁用批量入口，单文件操作仍可用。宽度至少 840dp 时文件列表与提交表单分列，窄屏顺序显示。
- 分支页把 Fetch/Pull/Push 放在远端同步区，折叠策略标题显示当前 Pull 策略；分支列表支持名称搜索和本地/远端切换，当前分支明确标记。新建分支使用对话框，删除仅出现在非当前本地分支旁。
- 历史首次进入当前仓库时自动加载；加载失败后由用户显式重试，避免循环请求。提交卡片区分主题、短 SHA、作者和时间，点击进入独立详情；差异在独立全屏对话框显示，等宽文本可横向滚动，关闭后回到原列表。
- 冲突页显示文件数量、每个文件的解决入口及操作的继续/中止动作；存在冲突时工作区提供跳转入口，不显示干净状态。
- 构建页分为新建构建、任务列表、选中任务结果与发布面板。新建凭据、上下文/Dockerfile、日志、镜像发布按需展开；任务显示引用、短 SHA、翻译后的状态与选中标记。通过构建 ID 深链接进入时默认收起新建表单，直接查看任务。创建凭据的 token 仍只存内存。
- 环境页集中显示 Git 检测和安装任务，原安装 ID 恢复表单默认收起，存在待恢复记录时首次显示默认展开。

分支可以切换、创建并切换，以及删除非当前的本地分支；删除使用 Git 的安全删除规则，不强制删除。Fetch 获取远端，Pull 显式选择仅快进、合并或变基，Push 使用当前分支已配置上游。修改前显示仓库、分支、目标、策略和相关差异；确认后再次核对工作区、HEAD、分支尖端、配置摘要、冲突状态和所选差异版本。401 明确拒绝后的认证重试也重新核对，读取失败或事实改变时不派发。

文件分为已暂存、未暂存、未跟踪，分别查看差异、暂存或取消暂存；重命名同时使用精确的新旧路径。提交确认显示全部已暂存差异和消息，提交全部索引内容，保留后续未暂存修改；不隐式暂存工作树，不 amend、不 force push。差异标明新增/删除数、二进制与截断状态，完整内容可从文件入口读取或下载。历史每页 50 条，可搜索提交消息、翻页、查看完整 SHA、作者/日期、正文、父提交、变更文件及其提交差异。

文件编辑使用 [共用编辑器](TextEditor.md)，只编辑仓库内已存在的非符号链接 Unicode 文本，最多 256 KiB。保存使用精确字节版本条件；保存文件、暂存、提交、推送和部署分别执行。工作区修改没有服务端事务式 CAS；客户端复核与普通文件条件写入不能替代真实宿主的外部 Git/文件系统并发验收。

冲突界面比较 base/ours/theirs，复用共用语法输入和查找替换，保留内存结果草稿。编辑结果最多 200 KiB UTF-8，不能保留冲突标记；也可明确采用一方或删除文件。不存在的一方必须明确删除；二进制/过大文件仅采用完整一方或删除，符号链接/子模块由外部 Git 工具处理。

全屏冲突编辑器通过布局处理系统安全区与 IME，不平移整个窗口；标题与底部解决入口保持在可用区域，比较及编辑正文可滚动访问。系统栏图标跟随编辑器表面明暗，键盘开合不提交或清除结果草稿。

版本变化时不覆盖，读取最新冲突版本会保留草稿，需要用户对照新版本检查；编辑保存复核文件原始字节哈希。未保存关闭需确认，配置重建保留草稿，换账号/退出清除。全部冲突解决后可继续真实 merge/rebase/revert/cherry-pick 操作，也可确认中止；没有对应操作的冲突不伪造继续动作。

失联、错误回执或结果回读失败保留账号/服务器/仓库范围的本机待核实标记，暂停该仓库后续修改；记录仅保存仓库 ID、动作和随机标记，不保存文件内容、消息、配置、凭据或可重放正文。重新进入和运维中心均能看到记录。显式“读取并采用当前事实”只清除本机标记，不重复操作，也不证明远端推送成功；远端须单独核实。普通同步 Git 操作没有任务 ID、取消或幂等键。

Linux 宿主检测确实缺少 Git 且允许安装时，提供公共 Git 安装任务入口，显示阶段、阶段进度和终态，按已核实状态取消，离页停止观察。未知安装可显式复用原请求键和相同选项重试，或独立识别原 ID 后恢复；活动任务本身不证明属于未知请求。安装期间、安装记录待恢复或活动查询失败时，仓库写入暂停。当前安装由宿主包管理器和精确 `gitPackageInstall/git` 授权处理，不接受任意命令。Windows 没有自动安装表单。

Git 工作区不新增手机凭据表单；HTTPS 使用服务器已有加密凭据或宿主支持的认证，SSH 使用宿主普通账号配置。认证需要补充时只显示固定提示，Git 原始错误、配置和可能带凭据的远端 URL 不进入界面、草稿或未知记录。共享执行与契约规则由 [Git 客户端](../../../../docs/applications/RelaxKonOS.GitClient.md) 拥有。

## 2. 固定提交构建

仓库 URL → 加密凭据引用 → 分支/标签 → 上下文和 Dockerfile → 解析并确认完整 SHA → 持久构建任务 → 查看有界日志/取消 → 成功镜像 → 显式交给 [Image 应用部署](ApplicationDeployments.md)。编辑后发布需先提交和推送，再解析远端引用，不能暗中纳入未提交内容。

Ubuntu 使用独立 rootless BuildKit remote builder，提交与执行时核对容器用户、无特权/宿主 bind/附加 capability、网络、CPU/内存/PID 配额；不满足条件拒绝，不使用默认 Docker builder。准备与配置见 [Ubuntu 构建环境](../development/GitBuild.Ubuntu.md)。Git LFS、私有子模块和完整 IDE 不在当前支持范围。

## 3. 执行与产物边界

仓库 token 是按账号隔离的服务器加密引用，不进入 URL、日志或普通草稿。构建任务幂等、可取消/超时；重启将活动任务标为中断，不自动重跑。构建失败不替换运行中的应用。

成功记录真实镜像 tag/ID；发布预检核对用户、成功状态与本机镜像身份，修订记录构建 ID、仓库、引用、SHA 和构建定义。创建容器按镜像 ID，回滚复用原修订产物与配置，不重新构建旧分支，也不撤销数据迁移。

静态站点/其他构建模板、更新比较与按修订引用安全回收产物仍见 [支持范围](../design/SupportScope.md)。Git 工作区当前行为见第 1 节，真实宿主/设备检查独立追踪。

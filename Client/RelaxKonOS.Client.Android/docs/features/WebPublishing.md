# Android 网站发布

## 1. 入口与前置

“管理 → 网站”按 `server.web-server` 门控。读取受管实例、配置语法检查、站点和 TLS 关联；证书读取另需 `server.certificates`。无权限或未核实不显示为无站点/无证书。

发布需要运行中的应用、loopback 上游、受管 Web Server、可控域名与当前 `nginxConfigurationWrite` 授权。共享执行行为见 [Web Server 设计](../../../../docs/applications/RelaxKonOS.WebServerManager.Design.md) 和 [证书管理](../../../../docs/applications/RelaxKonOS.CertificateManager.md)。

## 2. 手机流程

选择应用与实例 → 输入域名并按提示配置 A/AAAA → 显式选择有效期内、状态可用且 SAN 匹配的既有证书（缺失/未核实/不覆盖时禁止提交，不自动改为申请），或填写联系人/同意条款/确认 HTTP 80 可达 → 确认目标与授权 → 提交持久发布操作 → 核实结果。

Android 不生成宿主 Nginx 配置，不缓存私钥、挑战凭据或 DNS token。站点关联只读取服务端 `siteId`，不从端口、域名或上游猜测。

发布表单通过当前 `WebsitePublicationRequests` 提交，绑定原登录并先持久化请求键与摘要。同一未知提交只允许按原请求显式重试，不在再次确认时生成第二个发布键；本机记录不保存发布正文、联系人或证书内容。

发布前置刷新遇到异常或取消时结束加载，撤下旧实例、应用和证书事实，显示脱敏读取失败并允许显式刷新恢复；失败不显示为空列表，也不依据旧选择继续发布。切换登录后的旧读取不得修改新会话状态。

## 3. 结果与恢复

服务端检查域名/站点归属和证书覆盖，受控写入经过 `nginx -t`、reload 与失败恢复，再绑定应用。发布账本持久保存幂等键、阶段和检查；每应用只允许一个活动操作，重启标为中断，不重放 ACME 或配置写入。绑定失败只还原本次站点变更，保留旧证书及应用进程。

分别展示上游、DNS、TLS 握手和 HTTP 检查的观察位置、时间与结果。配置完成但访问无法证明时显示未核实，不能把宿主 loopback 可达当公网成功。手机断网后按原操作查询，不自动重新发布。

发布操作查询属于发起时的应用选择和登录代次；切换应用后，即使再次选回原应用，旧查询也不能覆盖当前结果。后发的查询使先前查询失效，旧响应不得触发当前页面的历史刷新。

已知操作查询失败或取消时撤下旧结果、保留原操作 ID，记录区域提供显式只读刷新，读取期间禁用重复刷新。查询恢复不重新发布；非终态操作按原 ID 持续观察，即使连续响应的状态值相同。切换应用清除原查询入口。

查询响应的操作 ID 必须与请求一致；不匹配时按读取失败处理，保留原查询目标，不将响应中的错误操作写入恢复索引。

发布历史读取失败或取消时显示脱敏失败信息，提供只读重试入口；加载期间禁用重复重试。历史请求绑定应用选择和登录代次，切换后再选回原应用也不能接受旧响应。

前置刷新移除或替换所选应用时，同步清除旧发布结果、操作查询入口和历史；与手动切换应用使用同一归属检查。延迟观察在发起下一次查询前重新核对登录、查询代次和操作 ID，不能恢复已离开的目标。

发布记录自动观察仅在该栏目可见且 Activity 处于前台时进行；保留但隐藏的栏目或后台不发起下一次查询，重新显示后继续核实原操作。计时器还须复核当前已显示的完整任务快照，旧的运行中快照不能重启已终态或已被手动查询替换的观察。此限制不取消宿主发布任务，也不重发发布。

发布记录区域区分尚未选择目标、读取失败及服务器返回空历史，避免只有标题的空白区域。页面展示服务器本次返回的全部发布历史，不截为前三条。

记录页独立选择服务器返回的应用，包括已停止应用；查看历史不要求已有 Web 实例，也不经过发布表单。应用停止后刷新仍保留历史目标。发布表单只列出运行中的应用，提交还须核对所选应用当前为运行状态。

停止应用、关闭访问、删除站点和吊销证书是独立动作。DNS 服务商自动化及内网发布仍属 [支持范围](../design/SupportScope.md)；不收集未接入服务商的凭据、不自动放开端口。真实 Nginx/ACME/DNS 与设备访问检查集中见 [验证要求](../development/Verification.md)。

Android 在发起发布前，将宿主、账号、应用、Web 实例、原参数摘要和幂等键写入禁止备份的本地记录，不保存域名、联系邮箱或证书正文。结果未知、取消或异常后保留记录；显式重试须使用相同原参数和原请求键，并先读取历史，不能凭另一项历史任务推断原请求成功。存在未核实原请求时，参数变化不发起新发布。

记录区域显示未核实原请求的应用和实例，并提供原操作 ID 输入与只读核实入口。用户核对历史后指定原操作；响应必须匹配该操作 ID、原应用和实例才能解除原请求门禁。已知回执先持久保存操作 ID，再写入恢复索引，最后清理原请求；本地存储失败时保留核实入口。切换宿主或账号不能使用另一身份的请求记录，重新登录不能接受旧会话回调。

历史行可打开该项操作的只读详情，详情完整展示并允许选取操作 ID，便于核对原发布和保留恢复依据。本地恢复记录在读取远端前置事实前独立加载；前置网络失败不移除已保留的原请求。

宿主已返回的成功回执或明确拒绝，不因随后本地记录读取、索引保存或清理失败而改报结果未知。页面另行显示本地恢复记录故障，保留已收到的操作 ID 和未核实请求，允许显式重试核实。请求发出前无法保存原请求时禁止发送。核实按钮绑定当前原请求快照，刷新后的旧回调失效；发布或核实期间禁止重复发起及并行任务详情读取，防止旧响应覆盖当前回执。

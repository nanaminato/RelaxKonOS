# Android 应用部署与模板目录

> 当前功能说明，对应已接入的 AD02-M1–M4、AD03-M1/M2 与 BP16 完整定义编辑。实现与验证见 [当前状态](../status/Progress.md)；后续更新能力见 [补齐计划](../plans/BuiltInParity.md)。

## 1. 能力与入口

“管理 → 应用部署”提供列表、详情、新建、完整定义编辑、日志、启动/停止/重启、修订和回滚。Git 成功构建可从 Git 页面发布到既有 Image 实例；既有实例的新镜像/归档修订入口仍待 BP16 接入。依赖 `server.application-deployments`、真实可用的 Docker Engine 及当前账号权限；API 在线不等于容器运行时可用。

共享执行语义由 [部署设计](../../../../docs/applications/RelaxKonOS.ApplicationDeployment.Design.md) 和 [实施进度](../../../../docs/applications/RelaxKonOS.ApplicationDeployment.Progress.md) 维护。Android 不执行宿主构建命令，不维护另一套运行时版本表。

## 2. 七步部署向导

应用与来源 → 代码或镜像 → 运行参数与就绪检查 → 配置与资源 → 代理站点 → 确认 → 进度。归档可来自手机系统文件选择器或受控服务器文件引用；镜像支持标签查询。配置包含普通/秘密变量、命名卷与 CPU/内存/PID 限制，摘要不回显秘密，可只保存定义或立即部署。

| 来源 | 输入与边界 |
| --- | --- |
| Image | 镜像引用、端口、工作负载；服务端固定真实镜像身份 |
| Java | JAR/受支持归档、入口与启动参数 |
| .NET | 发布归档、入口/运行时；区分框架依赖与自包含 |
| Python | 项目归档、入口及当前模板要求的锁定依赖 |

Compose 项目走 [Docker/Compose](DockerCompose.md)；Git/Dockerfile 先走 [独立受限构建](Git.md)，成功产物再交给 Image 部署。停机替换不承诺无停机更新；禁止任意宿主路径和 Docker socket 挂载。

## 3. 完整定义编辑

详情的“编辑定义”读取完整服务端定义，原样保留工作负载、就绪级别/健康路径、容器与宿主端口、绑定地址、CPU/内存/PID 上限、命名卷、普通/秘密配置和站点关联。来源、实例 ID 和模板 ID/版本不可在此编辑。内存使用字节避免截断非整 MiB 的上限；卷逐项编辑，路径中的冒号和只读状态不靠文本分隔符重新解释；普通配置保留空值、空格和等号。

未修改秘密只提交既有 `secretVersion`，空值编辑保留原版本，输入新值会轮换。秘密只在此弹窗请求期间保留，不进入持久草稿或预览，提交结束后清除新输入；未成功新增的秘密需重新输入。创建和定义保存不是数据备份，也不等同于已发布修订。

保存前展示完整摘要。保存只修改意图，不创建修订、不替换正在运行的容器；运行参数在下一次部署生效。当前 `PUT /applications/{id}` 必须携带完整 `expectedUpdatedAt`（原 `updatedAt`，保留 7 位小数），缺失拒绝，过期返回 `application-deployment.definition_conflict`；桌面与 Server 同步采用此契约，不接受旧版无版本覆盖。

每次提交及 401 重试先核对原登录和当前定义，活动操作阻断。成功回执逐字段核对后再读取完整定义，轮换只核对秘密版本而不读取秘密内容。结果丢失、回执/读回不一致时不重发保存；“加载当前定义并丢弃草稿”只读取当前事实，不把后来的相同字段推断为上一次保存成功，之后修改需重新预览并明确提交。更换实例或登录会清除旧编辑和确认。

Server 秘密存储保留当前定义/不可变修订引用的原版本以及最近三个版本；轮换只裁剪这一应用的同名秘密，不改变其他应用的引用。实际保存和多次轮换的证据见 Verification，不把此存储检查当作真实容器或数据库回滚演练。

## 4. 传输、操作与日志

部署暂存接口与 [普通文件上传](FileTransfers.md) 是不同契约。归档流式上传，不整包读入内存；文件引用受账号、有效期、大小与摘要约束，不能把普通上传的续传保证套在部署暂存上。

提交使用幂等键，超时先核实原操作，离页和断网不取消远端执行。取消请求后继续读取权威终态；操作恢复接 [任务与恢复](OperationsRecovery.md)。日志按需读取最近 20 行，可扩展到 100、500、1000 行，以新的完整尾部替换快照，不拼接重复或过期输出。

回滚显示目标修订与停机影响，复用原产物和配置；数据卷和数据库迁移不会随版本回滚。未知运行状态保留诊断，不显示为已停止或健康。

## 5. 模板应用目录

“从模板安装”消费服务端可信内置目录，包含个人网站、状态监控、文件服务和 Webhook 四类用途模板。用途目录与 Java/.NET/Python 运行时模板分层；不是桌面扩展包安装器。

目录携带 schema、模板 ID/精确版本、来源、平台、能力、最低资源与受限字段。Android 生成原生表单，拒绝未知 schema/字段、不可信来源、平台或能力不匹配；秘密字段无普通默认值，不进入草稿、列表、摘要或日志。服务端安装时再次校验版本与字段。

实例和不可变修订保留实际模板 ID/版本，详情与修订分别显示其绑定版本。刷新或撤回目录不改变、停止已安装实例。显式更新说明、差异预览与版本更新流程仍需实现（BP16 / AD03-M4），见 [部署后续计划](../plans/Deployment.md)。首批模板逐个安装、升级与数据恢复属于 [验收清单](../status/Verification.md)，不再保留“建立模板目录”的旧实施目标。

# Android 应用部署与模板目录

## 1. 能力与入口

“管理 → 应用部署”提供列表、详情、新建、完整定义编辑、日志、启动/停止/重启、修订和回滚。Git 成功构建可从 Git 页面发布到既有 Image 实例；详情的“发布新修订”支持既有 Image/Java/.NET/Python 实例的新镜像或手机/服务器归档。依赖 `server.application-deployments`、真实可用的 Docker Engine 及当前账号权限；API 在线不等于容器运行时可用。

共享执行语义由 [部署设计](../../../../docs/applications/RelaxKonOS.ApplicationDeployment.Design.md) 维护。Android 不执行宿主构建命令，不维护另一套运行时版本表。

Docker 未安装、权限不足或不可达时，服务端仍返回已保存的应用定义，实际运行状态为未知；空定义列表显示尚未创建应用。运行环境卡片独立说明 Engine 状态，不能将依赖读取异常变为空 HTTP 500 或推断容器已停止。

## 2. 七步部署向导

应用与来源 → 代码或镜像 → 运行参数与就绪检查 → 配置与资源 → 代理站点 → 确认 → 进度。归档可来自手机系统文件选择器或受控服务器文件引用；镜像支持标签查询。配置包含普通/秘密变量、命名卷与 CPU/内存/PID 限制，配置表单直接显示秘密值，可只保存定义或立即部署。

| 来源 | 输入与边界 |
| --- | --- |
| Image | 镜像引用、端口、工作负载；服务端固定真实镜像身份 |
| Java | JAR/受支持归档、入口与启动参数 |
| .NET | 发布归档、入口/运行时；区分框架依赖与自包含 |
| Python | 项目归档、入口及当前模板要求的锁定依赖 |

Compose 项目走 [Docker/Compose](DockerCompose.md)；Git/Dockerfile 先走 [独立受限构建](Git.md)，成功产物再交给 Image 部署。停机替换不承诺无停机更新；禁止任意宿主路径和 Docker socket 挂载。

## 3. 完整定义编辑

详情的“编辑定义”读取完整服务端定义，原样保留工作负载、就绪级别/健康路径、容器与宿主端口、绑定地址、CPU/内存/PID 上限、命名卷、普通/秘密配置和站点关联。来源、实例 ID 和模板 ID/版本不可在此编辑。内存使用字节避免截断非整 MiB 的上限；卷逐项编辑，路径中的冒号和只读状态不靠文本分隔符重新解释；普通配置保留空值、空格和等号。

编辑器回填并显示已有秘密值，未修改秘密保留既有 `secretVersion`，空值编辑保留原版本，输入新值会轮换。秘密只在此弹窗请求期间保留，不进入持久草稿或预览，提交结束后保留表单值供检查和重试。创建和定义保存不是数据备份，也不等同于已发布修订。

保存前展示完整摘要。保存只修改意图，不创建修订、不替换正在运行的容器；运行参数在下一次部署生效。当前 `PUT /applications/{id}` 必须携带完整 `expectedUpdatedAt`（原 `updatedAt`，保留 7 位小数），缺失拒绝，过期返回 `application-deployment.definition_conflict`；桌面与 Server 同步采用此契约，不接受旧版无版本覆盖。

每次提交及 401 重试先核对原登录会话和当前定义，活动操作阻断。成功回执逐字段核对后再读取完整定义，轮换同时核对返回的秘密值和版本。结果丢失、回执/读回不一致时不重发保存；“加载当前定义并丢弃草稿”只读取当前事实，不把后来的相同字段推断为上一次保存成功，之后修改需重新预览并明确提交。更换实例或登录会清除旧编辑和确认。

Server 秘密存储保留当前定义/不可变修订引用的原版本以及最近三个版本；轮换只裁剪这一应用的同名秘密，不改变其他应用的引用。实际保存和多次轮换的证据见 Verification，不把此存储检查当作真实容器或数据库回滚演练。

## 4. 传输、操作与日志

部署暂存接口与 [普通文件上传](FileTransfers.md) 是不同契约。归档流式上传，不整包读入内存；文件引用受账号、有效期、大小与摘要约束，不能把普通上传的续传保证套在部署暂存上。

提交使用幂等键；当前部署请求必传完整 `expectedUpdatedAt`，在定义锁内核对并预留操作，过期预览返回 409，不排队。首次创建用创建回执的版本，Git 产物用当前实例快照，桌面使用同一契约。超时先核实原操作，离页和断网不取消远端执行。取消请求后继续读取权威终态；操作恢复接 [任务与恢复](OperationsRecovery.md)。日志按需读取最近 20 行，可扩展到 100、500、1000 行，以新的完整尾部替换快照，不拼接重复或过期输出。

回滚显示目标修订与停机影响，复用原产物和配置；数据卷和数据库迁移不会随版本回滚。未知运行状态保留诊断，不显示为已停止或健康。

## 5. 模板应用目录

“从模板安装”消费服务端可信内置目录，包含个人网站、状态监控、文件服务和 Webhook 四类用途模板。用途目录与 Java/.NET/Python 运行时模板分层；不是桌面扩展包安装器。

安装表单要求显式输入宿主端口（1–65535），保持 loopback 绑定，为 HTTP 就绪检查提供真实访问地址；Server 拒绝缺少 `hostPort` 的旧请求。目录携带 schema、模板 ID/精确版本、来源、平台、能力、最低资源与受限字段。Android 生成原生表单，拒绝未知 schema/字段、不可信来源、平台或能力不匹配；秘密字段无普通默认值，不进入草稿、列表、摘要或日志。服务端安装时再次校验版本与字段。

实例和不可变修订保留实际模板 ID/版本，详情与修订分别显示其绑定版本。刷新或撤回目录不改变、停止已安装实例。详情的“检查模板更新”读取服务端精确版本预览，展示实例与目标版本、当前与目标镜像、更新/维护说明及保留的完整定义，确认按钮写明目标版本。当前内置目录仍为 1.0.0，没有新版本时明确显示已绑定，不制造更新。首批模板逐个安装、升级与数据恢复属于 [验证要求](../development/Verification.md)，不再保留“建立模板目录”的旧实施目标。

## 6. 既有实例修订与模板更新边界

新修订表单只收集独立来源，来源类型不可切换，不创建第二个应用、不保存覆盖定义。归档使用限时引用，提交时再次检查过期；镜像按当前 Server 契约要求显式非 latest 标签。基础镜像、运行时、入口与 .NET 自包含输入独立于运行定义；参数逐项保留空值、空格和等号，最多 64 项，每项 4096 字符，不把一行重新拆成 shell 参数。

确认页展示原实例端口、工作负载、就绪检查、字节资源、逐项卷、普通配置、秘密值及版本和站点。Repository 每次提交及 401 重试先核对完整定义/当前修订与原登录会话，活动操作阻断；Server 在定义锁内再次核对必传版本并预留操作，执行前再核对。成功原操作 ID 进入运维索引并观察，停止观察不会取消发布。

模板更新走 `GET/POST /applications/{id}/catalog-update`，使用精确 `templateId/templateVersion`、完整 `expectedUpdatedAt`、明确的 `expectedRevisionId`（空值也必须在正文）、当前绑定版本与显式确认。

客户端再次读取相同预览，变化后要求重新检查；Server 校验后仅选择可信目录镜像，沿用现有工作负载、配置/秘密引用、资源、卷和站点。新必填配置/秘密、端口/挂载或最低资源不满足时要求先显式编辑定义，不能静默生成秘密、挂载或默认覆盖。实例绑定只在修订激活成功时与该修订同步；失败保留旧绑定，回滚恢复所选不可变修订的真实模板版本。

新修订与模板更新共享当前登录内的结果未知门禁，关闭弹窗再打开仍阻断。只读普通刷新不解除门禁；明确“读取当前事实并丢弃来源草稿”且不存在活动操作后可准备新提交，不推断丢失请求成功。门禁不跨 Android 进程重启保存，已返回的操作 ID 仍由持久运维索引恢复；没有按请求键查询原操作的契约，不自动重放丢失请求。秘密不会进入修订来源或模板更新正文。定义备份、镜像回滚与真实卷/数据库恢复分别说明。

# Squid HTTP 代理网关

管理页的 Squid 应用控制已连接 Linux 系统模式服务器的 HTTP/CONNECT 入口。入口要求登录描述符声明 `server.gateway-proxy`，与 Mihomo 应用分开。服务器须预先安装发行版 Squid 软件包，应用内不提供安装或卸载。

## 配置与服务

概览页显示运行状态、开机启动、期望与发布修订、磁盘配置匹配状态及恢复提示。表单支持监听 IP、端口、远程客户端开关、来源 CIDR、域名允许/拒绝列表，以及可选的 HTTP parent 主机与端口。列表每行一项，支持逗号分隔；上游主机留空代表直连。来源网段和域名语义以共享 [Squid 文档](../../../../docs/proxy/squid.md) 为准。

首次读取使用服务器最后提交的结构化配置；尚无记录时使用 loopback 默认值。刷新仅更新服务器事实，不覆盖正在编辑的表单。“载入已保存配置”显式替换表单，有修改时先确认。离开页面或关闭编辑前提示丢弃未提交修改。配置预览、原生语法校验及诊断位于配置页；应用完整配置前显示替换与接管确认。应用不会自动启动已停止服务。

提供 start、stop、restart、reload、enable、disable。恢复标记存在时禁止应用和启动、重启、重载、启用，只保留停止、禁用和独立校验。非受管配置必须由用户勾选接管；不会合并已有 include、认证、缓存或其他手写指令。观察者只读，控制者且服务器允许特权操作时提供写入操作，最终授权由服务器检查。

## 操作与会话

应用和服务动作使用唯一 `Idempotency-Key`，202 表示已排队，记录页轮询操作直到终态。请求正文、原请求键和已取得的操作 ID 按服务器、账户与工作区保存在 Android 的 no-backup 私有目录。传输失败或进程重启后显示待确认操作，由用户选择继续；重试复用原正文和原请求键，不生成新变更。明确的排队前拒绝和已确认终态清除待确认记录。等待超过轮询窗口后仍保留记录，继续查询不会重新创建操作。

会话切换取消旧任务并清空旧表单和状态，旧结果不能更新新会话。不同账户或服务器的待确认记录隔离。离开屏幕停止轮询，已提交的服务器操作继续执行。未提交表单不跨进程保存。

## 边界与验证要求

磁盘摘要匹配上次发布记录只说明文件一致，不证明 Squid 运行时加载或端到端 HTTP/CONNECT 已成功。主机恢复按共享文档执行；Android 不删除恢复标记。凭据管理、日志、TLS 解密、透明代理、磁盘缓存及防火墙联动不在此应用能力内。

验证应覆盖真实 Linux Server/Helper 上的预览、原生诊断、完整替换确认、受管/非受管配置、停止状态发布、六种服务动作、恢复阻断、观察者权限、断网后原键重试、进程重建恢复记录、会话切换及窄屏/平板与三语布局。实现和文档不代表这些 Android 验证已执行。

状态契约必需字段 `packageManagementSupported` 表示服务器是否支持自动包管理，与 `supported`（网关平台支持）分别解析。Android 当前仍不提供安装／卸载入口；桌面可使用支持 Debian 12、13 等发行版的自动包管理。

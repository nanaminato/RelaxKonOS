# Android Docker 引擎与镜像源

引擎状态及生命周期操作集中为卡片，镜像源各自成卡。Docker 工作区的“操作记录”分类集中显示安装进度、取消、恢复与引擎待核实变更（安装只由组件中心发起，应用内不再提供重试入口）；容器/镜像/网络/卷的已有 ViewModel 结果与待核实标记也在此分卡展示，日志须显式展开。资源页提供记录跳转而不重复展示操作详情；记录不新增完整持久历史。

服务器明确返回 `docker.not_installed` 时，Docker 首页显示一条未安装引导和“组件依赖”入口（跳转组件中心），不展示依赖引擎的 Compose/容器/镜像/网络/卷读取错误或创建入口。引擎管理页显示未安装事实，隐藏没有运行时可执行的启停与安装按钮；读取失败、权限拒绝或运行时停止不能当作未安装。镜像源配置仍可独立管理，组件安装后的资源功能继续按已有流程展示。

## 引擎与安装

刷新与安装轮询使用固定高度的加载条占位，不插入或移除布局行，保留页面滚动位置。其他管理页面采用同一组件。

Linux 部署显式启用 `--docker-access` 时，即使 Docker 尚未安装，也先创建 Docker 系统组并授予 Server 服务账户成员资格。后续安装由 Helper 再次确认授权，Server 验证实际引擎连接；已有访问权限时完成安装，无需额外重启。旧部署缺少运行中的组权限时，显示 `docker.access_restart_required` 的明确说明：在宿主重启 RelaxKonOS Server 后刷新核验。未启用 Docker 授权的部署仍需在宿主显式配置授权。

管理 → Docker → 引擎与镜像源，入口按当前 `server.docker` capability 门控。页面读取当前 Engine 状态、版本、系统与架构，成功返回 unavailable 与请求未被核验分开显示；只有当前会话的 privilegedOperations 为真才显示写入动作。引擎不可达不自动等于未安装。

Start/Stop/Restart 调用当前 `/docker/engine/{action}`，提交结构化 confirmed。确认指出整个宿主、所有容器、Compose 与应用部署受影响。Linux 使用宿主 Helper 的固定 Docker 服务；Windows 依赖 Docker Desktop 的受支持 CLI。

引擎与镜像源变更确认绑定原登录、完整事实与动作，每次只能提交一次。暂停、隐藏页面、离页、刷新或关闭后撤销确认；旧提交、关闭按钮及外部关闭回调不能消费或撤下重新打开的确认，也不能在新登录下对相同事实提交。生命周期撤销仅影响原登录的确认。提交前模型再次核对原登录与当前事实，远端并发变化仍按仓储预检处理。

Docker 引擎安装只在组件中心进行：服务器报告系统包、未安装且组件中心具备管理资格时由组件中心提交 `DockerInstallationRequest(confirmed)` / Install，没有包、版本、升级或隐藏重装参数；Windows 显示主机侧安装/配置说明。

明确 `dockerInstall` / `docker` 提权后复用原幂等键。成功接受任务后按原 ID 查询，页面可见且记录已核验时每 1.5 秒观察；取消需要服务返回 active/cancellable 并再次确认，离页只停止观察。

安装取消确认的关闭同样绑定原确认实例；关闭后重开，旧关闭回调不能撤下新确认。当前确认只发送一次原 ID 的取消请求，关闭本身不取消远端任务。此交互规则不改变 Docker 的固定包安装范围，不提供多版本更新、修复、回退或卸载能力；这些也不在应用内提供。

已知未知提交 ID 优先只读恢复，不依赖活动列表成功；原 ID 完全丢失时可由用户明确识别原请求。任务响应必须属于 Docker / Install。未知安装结果保留恢复标记，不能以空活动列表或 Engine 当前可达证明原安装成功。

按 ID 恢复表单固定原登录、页面读取代次及打开时的待核实安装记录；字段和提交绑定该次表单，关闭后重开不能复用旧关闭或提交，修改 ID 后旧提交无效。识别勾选随 ID 修改撤销，旧勾选不能确认新 ID。暂停、隐藏、离页、刷新或换登录撤销表单；同一登录内关闭和暂停后重开可保留非秘密 ID，识别状态重新确认。

恢复表单打开时暂停安装自动观察，关闭后恢复原任务的只读观察。提交只接受当前明确输入一次；原待核实记录被替换时不查询、不清理新记录，提示重新核实。成功识别仅交由公共安装仓库核对原服务、动作及原 ID 后清理原记录，不提交安装或重放写操作。取消确认等其他决定打开时不能打开恢复表单，恢复期间也不能另开变更或取消确认。

显式恢复和原请求识别在公共仓库限定 Docker / Install。即使回执服务同为 Docker，Repair 等其他动作也不能通过本页登记或恢复隐藏索引、清理原日志；不支持的原请求动作不发起 ID 查询，继续保留待核实记录。当前 Install 的正常恢复仍可用。

刷新读取历史安装记录时，记录不存在、读取失败和历史任务失败独立于当前引擎事实。历史记录查询失败只在操作记录页显示记录 ID 与“原操作记录不可用／结果待核验”，不弹出当前 Docker 状态错误。保留原 ID 恢复入口和未知提交标记；不因引擎可用而删除或推断原安装结果。

## 用户镜像源

镜像源属于当前登录账户，为符合条件的 Docker Hub 镜像引用提供解析前缀。它不修改 daemon registry-mirrors，也不替代 [宿主出站代理](OutboundProxy.md) 的网络消费范围。显式其他 registry 引用保留原来源，已有镜像/容器不随选择变化自动重新拉取。

页面读取默认解析源、保存源和真实选择状态；默认源使用零 UUID 但不可编辑/删除，选择默认提交 `mirrorId:null`。其他源支持创建、完整名称/endpoint 编辑、选择和删除；删除当前源后重新读取默认选择。端点允许 registry host/可选端口或 HTTPS 根 URL，拒绝凭据、路径、查询和片段。点击确认后提交冻结草稿，刷新、返回、离页或打开代理设置前保护未保存字段。600 dp 可用宽度分栏，小屏切换列表与编辑。

## 同步结果未知与运维入口

引擎控制和镜像源 CRUD/选择没有任务 ID、取消或网络幂等键，不能按安装或 Compose 任务处理。提交前持久保存动作、当前宿主/账户及可选镜像源 UUID；本地 markerId 不发送到 Server，名称、endpoint、请求正文和凭据均不保存。提交、认证重试前再次读取并比较批准事实；发生变化时拒绝继续。此比较不构成 Server 原子 CAS。

写入失败、连接中断或成功后的事实读取失败保留未知记录，页面阻止继续提交引擎/镜像源变更；普通刷新不清除记录。显式读取并确认当前状态解除本地标记，不证明原请求成功，也不重放原写入。运维中心展示该待核实入口和安装原任务，按当前宿主/账户/capability 隔离；同步操作不伪造远端任务。

当前会话读取或提交被取消后，撤下旧引擎事实并撤销安装任务的已核实状态，保留原任务及未知记录供显式恢复。采用事实直接呈现该次核实结果，不另行读取以掩盖失败；结束操作时重新同步引擎、资源和安装待核实门禁。

Android 同步 Docker 结果直接使用共享契约的 `logLines/logTruncated`，不再解析旧 `messages`。详细 daemon 原始诊断不进入普通错误文案。

引擎、镜像源和操作记录栏目共享控制状态。隐藏栏目不显示失败反馈、执行确认或任务恢复弹窗；隐藏或退到后台撤销未提交的执行、安装、取消及放弃确认，保留镜像源草稿，返回后须重新确认。迟到失败保留原原因，只有当前栏目显示一个反馈；关闭提示不恢复旧事实，须显式刷新。

初次读取由可见栏目发起；切换栏目保留已有事实或失败，不自动覆盖草稿或清除错误。安装任务的定时观察只由当前可见且处于前台的栏目安排，隐藏后停止安排后续查询，返回继续查询原任务 ID，不重放安装。

观察在间隔结束后再次核对原登录、原任务 ID、读取代次、失败状态和当前前台资格。其他读取发生后重新等待完整间隔，不把旧计时器用于新任务；完全相同的运行响应仍继续观察至终态。暂停和恢复直接更新观察标记，即使两者之间没有 Compose 重绘，旧观察也失效，恢复后重新安排。已经开始的读取可以完成，不重放写入。

安装取消确认显示原任务 ID，持有打开时的登录及完整任务快照，并只能消费一次。关闭、刷新同一任务、切换任务、进入终态、变为不可取消、失去已核实状态、隐藏栏目或暂停均撤下旧确认；重新打开同一任务也不能复用旧回调。模型在确认和发送前核对原身份、当前同一确认对象、完整快照及取消资格，读取忙碌时不能确认取消。确认期间暂停自动观察，关闭后重新等待观察间隔，不重放已发送的取消。

引擎和镜像源写入回执、后置事实核验以及本地标记清理分别处理。仓库变更后只核验一次，页面直接使用该次事实，不再追加读取；已知成功先更新提交成功状态并关闭已提交草稿。后置核验异常或当前协程仍有效时的读取取消保留成功回执与恢复标记，显示专属核验提示并撤下可写事实。本地标记读取/清理失败另行提示，不把已知成功改为未知提交。用户明确读取并采用当前事实后恢复写入，不能自动重放原请求。

同一失败再次发生时采用新的反馈事件，关闭过的旧提示不能压住再次立即失败；反馈仍只由当前可见栏目显示。

## 代码

- [DockerControl.kt](../../app/src/main/java/app/relaxkonos/mobile/core/net/DockerControl.kt)：当前类型、路由、strict 读取与镜像源校验。
- [DockerControlRepository.kt](../../app/src/main/java/app/relaxkonos/mobile/data/DockerControlRepository.kt)、[DockerControlJournal.kt](../../app/src/main/java/app/relaxkonos/mobile/data/DockerControlJournal.kt)：提交前实际状态复核、会话隔离和未知记录。
- [DockerControlScreen.kt](../../app/src/main/java/app/relaxkonos/mobile/ui/manage/docker/DockerControlScreen.kt)、[DockerControlViewModel.kt](../../app/src/main/java/app/relaxkonos/mobile/ui/manage/docker/DockerControlViewModel.kt)：引擎、安装恢复和镜像源页面。

资源管理及 Compose 新提交共用 DockerMutationGate；资源未知标记也会阻止引擎/镜像源及 Docker 安装新写入。资源恢复从 [Docker 资源](DockerResources.md) 进入。

共享控制状态的提交成功事件保留原变更类型、目标和参数。镜像源编辑器仅在本次成功事件对应当前草稿的创建/更新时关闭；引擎启停、重启或其他目标的成功事件不能清除隐藏栏目中未提交的镜像源输入。

镜像源每次创建或编辑都有独立身份。字段、保存、关闭与开启回调核对原登录、当前编辑和前台代次；保存还核对当前明确点击的草稿快照，修改名称或地址后旧保存不能建立确认。丢弃后旧字段和保存不能影响新草稿；暂停或隐藏再恢复保留内存输入，旧回调失效，当前入口可以继续使用。

放弃决定绑定原编辑、原草稿和原导航，当前决定仅消费一次。重开决定后，旧继续、放弃及外部关闭不能撤下或消费新决定。变更忙碌及变更确认期间，旧编辑回调不能修改草稿。保存结果未知保留输入及原待核实标记，保存入口禁用；有草稿时点击刷新先确认放弃，用户明确放弃后才读取事实，不重放镜像源写入。

Docker 安装任务终态与当前引擎事实分别核实。已知 Docker / Install 结果先保留为已核实任务，再刷新引擎事实；后续读取异常或当前协程仍有效时的读取取消，不撤销已知终态。页面单独提示引擎事实刷新失败并撤下当前操作资格，记录页仍展示原 ID、终态和任务原因；显式刷新恢复事实，不重装或取消任务。直接查询和历史恢复后，成功的引擎事实读取均不得清除任务失败原因，安装问题码沿用公共安装文案。

# 任务管理与监控

> BP15 当前已接入（2026-10-01）。真实宿主、网络和设备的未关闭检查见 [Verification](../status/Verification.md)。

## 查看与操作

性能列表采用资源卡片，突出当前数值，CPU/内存/文件系统显示利用率进度，容量项补充总量或可用空间；磁盘与网络标明读写和收发，设备名称下显示资源分类。状态与刷新在同一行，实际采样时间独立显示。点击卡片查看趋势与完整指标。

进程筛选支持按钮与键盘搜索，清空筛选立即重新查询；排序区域提供手动刷新，读取中显示进度。详情提供返回列表入口，结束进程仍需确认原实例。新增操作均提供英语、中文和日语文案。

## 进程页

当前页面支持名称/PID/用户过滤、CPU/内存/名称/PID 排序、升降序与每页 50 项。查询在 Server 执行，不对当前一页做本地重排；筛选输入最多 512 个字符，只有搜索提交后才改变查询，自动刷新不提交未确认草稿。改变过滤/排序时清除上一查询显示，翻页失败保留上一成功页面；总数收缩导致当前页越界时回到实际末页并重读。列表显示服务端 sampledAt，行包含名称、PID、CPU、内存和可用属主。点击打开完整名称、线程数、原始启动时间及终止按钮；手机在列表/详情之间切换，足够剩余宽度和高度的平板并排显示两者。成功刷新只更新同一 PID/启动时间的选择，PID 重用、目标消失或启动时间不可验证时不沿用旧选择。

页面处于 RESUMED 时首次读取并每 6 秒查询一次，间隔长于 Server 的 5 秒采样窗口。后台、离页或原登录变化会取消只读请求，拒绝迟到响应；重新进入保留本登录的查询并重新读取。新登录清空列表、筛选、排序、页码、回执消息与确认对象。列表项以 PID/完整启动时间识别。

## 结束已确认实例

只有存在完整 startTime 的进程才提供可用终止按钮。确认包含名称、PID、启动时间，并固定原登录引用和原实例。Android 直接使用当前请求正文与四字段回执，详见 [共享任务管理协议](../../../../docs/applications/RelaxKonOS.TaskManager.md)。不会将启动时间截断到毫秒，不提供当前端点并不实现的正常/强制选项，不要求无效的应用提权密码。

HTTP 成功状态不代表进程已结束：只在 success=true 时记录最近“结束进程”操作；实例已退出/改变、实际 OS 权限不足和未确认退出分开提示。传输结果未知不自动重发；错误条重试只读取列表。明确回执后在前台刷新，离页不因迟到回执再次启动读取；已经提交的操作不因页面退出而重发。换登录后旧确认、旧请求和旧回执不能作用于新登录。

## 当前性能读取

`PerformanceModels/PerformanceWire` 直接采用完整当前 PerformanceInfo、PerformanceRealtimeSnapshot、health、文件系统容量、磁盘 I/O、网络计数/速率及地址契约。静态硬件信息与能力、snapshot、最近 60 秒 history 和网络地址已提供独立 Gateway/API/Repository 读取。

可选值要求显式 null，能力要求明确布尔值；缺字段、错误类型、畸形时间、负计数或超范围百分比返回读取失败，不投影成 0 或空列表。Long 计数保留整数精度，history 最多 60 点且 sequence 严格递增。读取绑定原登录，401 后的重新调用也复核原登录；迟到成功不能发布到新登录。

## 性能详情与实时观察

`MonitorViewModel/PerformanceObserver/PerformanceConnection` 独立于进程列表；使用当前 `/hubs/performance`、`Subscribe` 与 `OnPerformanceSnapshot`。进入前台后订阅并读取低频信息、地址、snapshot/history，Hub 使用原始 JSON 验证后才投影；不会依赖 Gson 对缺失原始数值的默认值。缓冲保留最新待处理帧，避免慢页面堆积。

显示实时、连接/重连、快照降级或数据不可用，以及实际样本时间和采样健康问题。静默订阅也有超时；只有新的有效序列才能维持实时状态。自动重新建立读订阅最多 4 次（0/1/2/5 秒间隔），401 只作一次认证重试，明确 4xx 拒绝停止重连。流不可用后每 5 秒读取明确标注的快照；刷新可以重新尝试实时订阅。所有请求和回调绑定原登录/连接代次，旧连接回调拒绝；后台、离页、登录变化或 ViewModel 清除停止读取并断开，关闭连接不改变任何宿主进程。

新连接重新建立序列基线并补取静态信息和历史，允许 Server 重启后从较小 sequence 开始。快照降级中识别序列回退/相同序列不同时间时清除旧历史与静态身份，后续重取；不永久丢弃新 Server 的样本。

CPU、内存、文件系统容量、磁盘 I/O、网络分别列为稳定目标。手机选择单项后打开详情；双栏使用剩余内容宽度/高度与字体缩放决定，左列表右详情，不用全屏宽度强行挤入外层平板面板。CPU 包含用户/内核/空闲/iowait、真实逐逻辑 CPU、频率、进程/线程/句柄、运行时间、核/插槽/虚拟化与 L1/L2/L3；内存包含可用/缓存/缓冲/Swap；文件系统包含挂载点与容量；磁盘包含读写速率/IOPS、活动/队列/响应时间和明确挂载映射；网络包含链路速度、地址、收发速率/字节/包/错误/丢包。长名称、路径、地址和完整时间在详情换行并可选择复制。缺失或能力不可用显示“—”，不伪造 0，不推测磁盘关联；当前性能 DTO 不含 GPU 实时数据，因此没有伪 GPU 卡片。

趋势取最多 60 份、最近 60 秒的服务端样本，按实际 timestamp 定位横轴。重复/旧序列不追加；无效/过期样本、时间倒序或超过 2.5 秒的间隔断开曲线，保留孤立真实点，不填造丢失秒数。CPU/内存/容量以百分比绘制，磁盘读写和网络收发分两条速率线；图表提供文字图例与样本数量说明。

## 时间边界

所有生产 Kotlin 时间读取统一使用 `IsoInstant` 的严格 Gregorian 校验，支持当前 DateTimeOffset 的 UTC/偏移与 1–7 位小数。仅显示和图表位置转换到毫秒；终止的实例请求保留原完整字符串。拒绝无时区、无效日期/时刻/偏移，不以 Calendar 宽松归一化代替验证；请求输出始终使用 Locale.ROOT 的 wire 数字。证书、FRP、Mihomo 读取也使用同一工具，保留严格时间解析规则；最低支持 Android 10 / API 29。

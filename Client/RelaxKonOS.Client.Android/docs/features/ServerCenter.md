# Android 服务器中心接入设计

## 选择性卸载

服务器维护的卸载确认框提供 SMB、Nginx、FRP、Mihomo 四项移除选择，默认全部保留。勾选删除全部数据时自动选择移除四项；取消任一组件的移除会取消数据删除。请求通过 `removeComponents` 传递固定组件标识的逗号分隔列表。Linux 用户模式不拥有系统组件，不发送组件选择。Docker Engine、容器和卷不在这四项清理范围内。

保留组件时保留整个数据根、密钥及管理记录。引擎按固定顺序清理所选组件并核验精确回执；失败保留程序、Helper 和数据供修复，不能仅凭连接断开判定成功。编译与真实主机证据分别维护在验证记录中，未声明设备交互已验收。

## 1. 体验原则

服务器维护失败仅显示本地化的传输分类或已知部署问题码，不把原始 SSH 异常、命令或凭据拼入产品提示。变更开始后连接断开且没有权威失败回执时显示结果未核实，要求先在历史中核实原操作，不提示盲目重复变更；观测状态未达到预期单独提示核验失败。维护确认与密码输入绑定主机，取消修复或卸载确认清空临时提权密码，忙碌期间不编辑密码或重复提交。

服务器中心的系统返回键与页面关闭按钮走同一清理流程：取消进行中的认证、清空表单秘密并关闭协调器会话。再次进入时没有安全保存的密码必须重新输入；工作区内部返回仍由工作区导航处理。验证期间不可切换主机。

SSH 认证拒绝清除该主机本次已验证的密码缓存，表单移除留空复用提示；用户可以重新输入正确密码恢复连接。认证方式耗尽、用户名拒绝及 OpenSSH 明确的认证次数上限断开按认证拒绝处理，普通协议断开不推断为密码错误。认证取消与网络不可达分别提示，不显示服务端断开描述原文。

SSH 文件浏览器上传/下载自动显示进度窗口与取消入口，按实际 SFTP 上传回调或成功写入下载目标的字节计数。多文件与目录上传累计字节；目录/多文件 ZIP 下载按原始文件内容累计字节，不以压缩归档大小充当分母。总量未知时不显示虚构百分比，失败与取消沿用待核实写入规则；离开或切换主机后旧进度不能更新新工作区。安装包本机上传显示累计百分比，官网/HTTPS 远端下载读取启动器的临时传输状态；传输结束后继续显示安装/更新与结果核验阶段。

操作记录复用预检平台，缺少结果时通过已验证 SSH 会话自动识别，不要求用户选择 Linux/Windows。点击每条记录的「查看详情」在弹窗中显示动作、阶段、状态、时间、问题码、摘要、安装结果与远端引擎日志；内容可滚动和长按复制，可通过关闭按钮、返回键或点击窗口外关闭。日志最多显示 64 KiB，并遮盖常见 password/secret/token/authorization 字段，仅驻留当前界面。远端最近 20 条记录的列表上限不视为核验失败。

操作记录页提供「清除已结束记录」，确认后删除当前列表中已核验为成功、失败、取消或中断的服务器回执、事件历史和日志，并同步移除手机索引。正在运行、排队、回执缺失及无法核对的记录保留；失败时保留未清除条目并提示重试。远端按固定操作 ID 执行 Linux `--clear-operation` / Windows `-ClearOperationId`，取得部署写锁后再次检查回执编号和状态；仅删除固定日志与回执路径，保留请求摘要以阻止旧请求重复执行。

不会删除安装、业务数据或主机配置；远端列表仅返回最近 20 条，刷新可读取剩余历史继续清除。

安装与维护首页分为概览、环境检查、维护操作、操作记录四个子页。概览优先显示安装、健康状态与主要入口；系统、目录、服务、安装标识放环境页，升级/修复/卸载集中在维护页，回执只在操作记录页展示，不混入安装向导。安装向导独立进入，发布目录输入框以官网默认地址作为 placeholder，留空仍使用官网；返回键先退出向导或回概览。切换子页回到顶部，详情字段可长按复制；中英日共享同一页面结构。

SSH 工作区的「部署」页以安装与维护首页为入口，自动执行 Probe/Status，并提供手动检查。首页显示预检与权威安装状态；未安装可进入三步安装向导，已安装可升级、修复或卸载，操作记录详情按需在弹窗中查看。卸载默认保留数据，永久删除受管数据必须勾选并在确认对话框中执行。修复、卸载后重新读取远端状态，分别以已安装且健康、已卸载作为成功条件。

操作执行期间禁用重复操作和向导返回。安装、更新、修复和卸载期间持续显示阶段文字与不确定进度动画；连接、环境检查、文件准备与上传、远端执行、结果核验随真实客户端阶段切换，不显示虚构百分比。进度区固定在滚动内容上方，历史回执仍只在操作记录页展示。

「安装服务器」是**开始使用 RelaxKonOS 之前就可能发生**的任务，不属于登录后的 `Manage` 能力目录。用户原本只想连接一台已安装的服务器时，登录表单仍然是首屏：地址、标识、密码和保存密码状态行不变。服务器中心作为可发现的次级入口出现；安装成功后回到同一表单。

保留现有五项顶级导航（主页 / 文件 / 终端 / 管理 / 更多）和 `TopDestination.visible(capabilities)`。不要新增第六个底栏项，也不要让 Server Capabilities 决定安装入口是否存在。未认证、服务端停止和卸载后都必须能进入服务器中心。

## 2. 现有落点与目标交互

SSH 系统页的退出工作区按钮固定在内容区底部，主机卡片和指标独立滚动，避免横屏或大字体下按钮被内容挤出安全区。SSH 文件页默认只显示当前路径、上级/后退/刷新、名称筛选、条数、上传与多选；点击路径展开地址编辑及前进操作，排序按需展开，新建文件夹和上传目录在“更多”菜单。传输限制通过“传输说明”弹窗查看，传输进行中同时显示限制与取消入口。

### 2.1 页面与自适应布局

```text
未登录：LoginScreen ─ 安装或管理服务器 ─ 宿主列表 ─ 宿主详情 ─ 步骤/进度 ─ 返回登录
已登录：更多 → 连接 ─ 当前宿主详情 ─ 步骤/进度 ─ 重新探测/重新登录
           主页异常或更新提示 ────────┘
```

- **Compact (<600dp)**：全屏详情和逐页任务；步骤标题、目标主机、阶段与主操作固定可见。手机返回键先关闭确认，再回上一层；执行临界阶段返回只离开视图，不取消远端操作。
- **Medium (600–839dp)**：沿用 rail，宿主列表与详情仍按页切换。软键盘弹出时主机指纹确认和卸载最终确认不可被遮挡。
- **Expanded (≥840dp)**：沿用左 rail，宿主列表与详情双栏，右侧可展示阶段记录。桌面式多窗口或第六导航项都不需要。
- 使用现有 `ScreenHeader`、`SectionGroup`、`ListRow`、`StatusChip`、`ErrorBanner`、`AppBackdrop`、`Spacing/Radius` 令牌和桌面镜像图标语义。主机指纹是专门确认页；卸载的「保留数据/删除数据」和输入主机名确认是两个明确步骤。英文、中文、日文字符串通过三套 `strings.xml` 同步提供。

## 3. 三种身份与本地资料

| 资料 | 用途与键 | 持有者 |
|---|---|---|
| `SavedLogin` | 键为稳定 `(serviceId, identifier)`；直连使用规范化 URL，受管连接使用安装 ID，不保存临时隧道端口 | `ConnectionProfileStore` 与 `VaultKind.Connection` |
| `ServerHostTarget` | 以规范化 `(SSH host, port, SSH user)` 为一项 SSH 目标，记录已确认主机密钥、受管安装 ID、部署模式和最近验证状态；同一服务器可保留多个管理用户，且可在没有 `SavedLogin` 时存在 | `ServerHostTargetStore` |
| SSH 凭据（可选保存） | 只用于连接宿主 SSH；按端点（主机、端口）与 SSH 用户绑定；由用户显式勾选、且只在一次成功握手之后写入，解封需一次指纹或锁屏确认 | 独立 Keystore 凭据域 `VaultKind.Ssh`（文件 `ssh-vault.bin`、alias `rk.ssh.vault`，AAD 为 `Ssh\|host:port\|user`）；不可重用 `Connection` / `Elevation` 记录，也没有 debug 明文兜底 |
| 宿主提权凭据 | Linux sudo / Windows 管理权限预检与操作；不是 RelaxKonOS API 提权 token | 本次操作的最小生命周期；如设计保存，另立规则，不自动读取现有 `Elevation` 保险箱 |

`VaultKind.Connection` 保存的是 RelaxKonOS 登录密码，`VaultKind.Elevation` 服务于现有 `/privileged/elevation`；两者的 AAD 都按稳定 `serviceId` 与账号绑定，不适用于 SSH 的主机密钥身份。

SSH 凭据已按「新增独立 kind、文件与 Keystore alias，并同步每一个 `when`、保险箱管理页面和测试」的要求落地为 `VaultKind.Ssh`。`unlockModeFor` 对它与连接凭据给出同一策略：有强生物识别就按次确认，否则退到锁屏五分钟窗口；本机两者都没有时勾选框直接禁用，不做降级。

现有 debug-only 明文登录兜底**不适用于** SSH 凭据（`ServerCenter.md` §3）。主机指纹可明文保存，但必须抗意外覆盖并在变化时阻断写操作。

### 3.2 连接页与「切换主机」

管理表单的密码留空时优先复用本次服务器中心会话中已验证的密码，其次解封可用保存凭据；手动输入仍优先。即使设备没有安全锁屏，同一次会话内也无需再次填写。复用不写入磁盘，不绕过主机密钥核对；退出服务器中心或进程结束后会话副本清零。

主机列表使用组外标题和分组行，管理目标用一行只读 `用户@主机:端口` 展示。页面避让键盘，保存选项整行可点，无安全锁屏时禁用并显示未勾选。验证与保存授权期间禁止切换主机和重复提交。明确认证拒绝会清除该主机的会话副本，允许手动更正，但不删除保险箱记录；网络失败保留副本供重试。

服务器中心是**先选主机、再添主机**的一页：

- 「已管理主机」每行整块可点，点开即连接：本会话已验证过的主机静默复核；有可解封保存密码的主机先解封再握手；两者都没有时不猜、不静默失败，就地打开同一个表单并说明原因是「未保存」「本机当前解不开」还是「已失效」中的哪一种。行内的「管理」是次级动作，只打开表单，不发起连接。
- 「添加主机」与「管理主机」共用一个表单：新增时校验主机、端口、用户与密码；管理时用只读地址行展示目标，密码留空优先复用本次已验证的会话密码，其次解封保存凭据，状态行说明当前可用的来源。
- 表单里的「在本机保存这个 SSH 密码」默认勾选，只有本机能保护它（有指纹，或退一步有锁屏）时才可点，且只在一次成功握手之后、且这份密码确实是**用户本次输入**的时才真的写入。从保险箱解封得来的、以及本会话内存里上一次已验证的副本都**不再问一次保存**（`SshPasswordOrigin`）：刚用指纹解封完立刻再弹一次一模一样的加密确认，等于让同一次授权做两遍（解封一遍、加密一遍），用户只会怀疑上一次是不是没生效；本会话的副本更是来自一次已经问过的验证，之后每次静默复核都再问就是骚扰。取消勾选**不删除**已有记录；删除是独立的「忘记已保存密码」确认动作，与删除主机记录互不替代（与 `LoginCredentials.Design.md` §6.3 同一条规则）。保存失败只读作「已连接，但密码没保存」，绝不冒充连接失败。
- 工作区的**系统页**（`SshSystemScreen`）顶部是当前主机卡片：主机名、`用户@地址:端口` 与状态标签「当前」，右上角「切换主机」是工作区里**唯一**一处主机切换入口。文件、终端与部署页都不再有主机条，也不再各留一个切换入口——一次连接之后「我在哪台主机上、换一台」是对这台主机的总览，与系统页的资源状态同源；把它挂在每一页的顶栏上，会让每条页面都背上两份互相竞争的信息（`Scaffold` 少了一条 `topBar` 之后，状态栏那一段由 `contentWindowInsets` 自动进入各页内边距，各页仍然不会被时钟压住）。选另一台主机时：本会话已验证或已有可用保存密码的主机就地切换工作区；需要输入密码的主机会**退出工作区**回到这一页的表单——密码只有一个输入位置，不做第二套。

判定本身是纯函数 `planSshHostOpen`（`servercenter/SshHostOpenRules.kt`）与 `shouldSaveSshPassword`（勾选 × 本机能保护 × 密码来源是本次输入），界面不自己发明结论；凭据的读写集中在 `ServerCenterCoordinator`，界面拿不到明文。

工作区主机切换在解封、握手及打开目标期间保留进度窗口，禁用取消、系统返回与窗口外关闭，操作结束后恢复。切换遇到首次或变化的主机密钥时，在工作区直接呈现与服务器中心共用的指纹确认窗口，替代主机列表；明确确认后接续原验证，取消只清除待核对状态并返回主机列表，不关闭当前工作区。密钥变化仍展示旧指纹及确认日期与新指纹。握手失败在列表内显示按原因分类的提示，说明与列表整体可滚动，失败后允许重新选主机或取消。

指纹确认同时显示本次观察对应的 SSH 主机与端口，允许完整换行，便于把指纹与连接目标核对；主机切换与服务器中心使用相同展示。缺少承载授权的 Activity 时禁止确认，仍允许取消返回。

握手失败按**原因**上报，不用一句话让用户同时猜主机、账号、密码和网络：分类规则是纯函数 `SshFailureRules.classify`（`servercenter/SshFailureRules.kt`），把异常归为认证被拒、认证被中止、TCP 超时、端口不可达、主机名无法解析、算法协商失败、主机密钥未接受、握手失败与无法归因，每一项对应一句可执行的文案。

判定顺序是**网络层原因优先于 SSH 库消息**：JSch 会把 `SocketTimeoutException`、`ConnectException` 包进 `JSchException`，先看库消息就会把「手机连不上主机」误报成「密码错误」。同一个分类名（`SshFailureReason.diagnosticName`）也是 `adb logcat -s RelaxKonSsh:D` 里的稳定标记，界面与诊断日志不会各说一套；异常原文、端点与用户名都不进入界面（`SshDiagnostics` 只记录阶段、SSH 配置与类型链）。

主机密钥的核对走**同一条确认路径**，但两种情形的措辞分得清清楚楚。判定是纯函数 `planSshHostKeyReview`（`servercenter/SshHostKeyReviewRules.kt`），只回答「还差哪一步」：`Trusted` 已经通过，`Failed` 该显示失败原因（**永远不弹指纹对话框**——把认证失败说成信任问题，就是让用户对一个与密钥无关的问题做决定），`NeedsTrust` 与 `KeyChanged` 都要求显式确认。

首次见面只展示新指纹；**密钥变更则必须并排展示被取代的旧指纹与它的确认日期**，因为用户要判断的是「同一台主机重装或重建了密钥」还是「这个地址现在被另一台机器占用」——在 DHCP 网段和克隆出来的虚拟机上后者是常态而非攻击信号，只给一句「密钥已变化，已被阻断」会让用户无路可走。

两种情形都只有用户点确认才写入固定（`ServerHostTrustRules.replace` 保证同端点同算法只留一条），**没有任何静默接受或跳过核对的入口**；确认后立刻用同一份密码重新握手，不需要用户再点一次。

### 3.1 稳定身份与动态隧道端口

Android 本地模型已将**稳定身份**与**请求地址**拆开：`SelectedLogin`、`SavedLogin`、`ConnectionProfileStore`、`CredentialVault` 和 debug 凭据存储只用 `serviceId` 建立身份；`AuthSession` 同时持有 `serviceId` 与 `effectiveBaseUrl`，所有已认证 API 调用使用后者。

隧道绑定的本地端口变化不再创建新的 `SavedLogin`，也不会改变保险箱 AAD。受管隧道接入已保持这些边界：

- 直连的 `serviceId` 为规范化的持久服务器 URL；受管隧道的 `serviceId` 为 SSH 主机密钥与安装清单共同验证过的安装 ID。登录与保险箱以 `(serviceId, identifier)` 为键，不以当前端口为键。
- `effectiveBaseUrl` 是当前会话的实际 HTTP 地址。直连时等于持久 URL；隧道时由连接解析器建立并持有。`AuthSession.updateConnection` 只接受不改变 `kind + serviceId` 的重绑定；文件、指标、提权和上传等调用都从会话取得当前地址。隧道断开时先重建并核对主机身份，换端口后只更新传输地址。
- 受管登录选择经 `servercenter/ManagedLoginTunnelResolution.kt` 接入隧道解析：`ManagedLoginTunnelRules.hostFor` 只按安装标识在 `ServerHostTargetStore` 中找宿主（相同 IP、URL 文本或 DNS 解析都不足以合并），`bind` 要求宿主与隧道解析结果都属于同一安装，否则拒绝——宿主重装后安装标识会变，旧登录绝不能被静默接到新安装上，否则会复用错误的保险箱记录。宿主资料缺失时登录表单说明「缺宿主资料」，不回落到猜测地址。建立隧道本身需要 SSH 凭据与一次用户确认，仍属宿主详情页与保险箱。
- 登录表单的“服务器”字段在直连模式仍可编辑原 URL；选择受管隧道时显示宿主名称和「通过 SSH 连接」说明，编辑入口回到宿主详情。不能把临时 loopback 地址伪装为用户应保存的服务器地址。
- 本地资料只消费当前稳定身份模型；格式变更直接升级，不维护旧端口键或旧布局的迁移适配器。

在宿主目标中记录由部署引擎签发/读取的安装 ID；连接到 API 后，再用经验证的安装信息把目标与一个或多个 `SavedLogin` 关联。安装和维护先选择一个明确的“服务器 + SSH 用户”目标，绝不按服务器地址猜测用户。**删除登录记录不删宿主，忘记密码不删 SSH 凭据，卸载服务端不批量删除登录记录。** 删除宿主资料时要提示其关联的登录记录和 SSH 凭据分别如何处理，不能把三件事合成一个按钮。

## 4. 操作状态的归属

`LoginViewModel` 和 `MobileNavHost` 只负责各自现有界面。`ServerCenterCoordinator` 由 `AppContainer` 持有，负责 SSH 会话、阶段事件、宿主锁/操作 ID、通知和重连；`MainActivity` 的根界面按当前流程选择登录、Shell 或服务器中心。进入服务器中心时记录来源，返回时恢复原页面。任务在页面销毁、旋转或语言切换时不因 Composable 被移除而丢失。

远端操作记录是权威结果，本地另建**不含凭据**的恢复记录：安装 ID 或待安装主机指纹、操作 ID、阶段序号、启动时间、目标版本与最近核验时间。恢复时先重新验证 SSH 主机密钥，再读取远端结果，不能用本地缓存直接宣称成功。`RecentOperationJournal` 只保存本进程内的简短成功操作，不承担部署恢复或审计；文件上传的 `UploadResumeJournal` 记录的是 API 上传会话，也不能拿来复用部署操作 ID。

Android 后台可中断客户端进程。包上传等需要持续本地传输的阶段，应仿照现有 `UploadForegroundService` 的可取消、可见通知方式实现独立传输任务；进入远端受控执行后，由远端任务存活，通知只展示进度与最终结果，不把客户端常驻当作成功条件。上传/下载包通过 Storage Access Framework 选择或保存用户文件，不申请整个存储空间权限。

状态区分 `SSH 不可达`、`SSH 已认证`、`宿主已安装`、`API 健康`、`RelaxKonOS 已登录`；`ServerEndpointDiscovery` 仍只是登录表单的地址提示，不能作为部署预检门禁。卸载后 `AuthSession` 失效是预期结果，服务器中心必须留在可访问的未登录层。

## 5. 当前边界

SSH 工作区提供文件、交互式终端、部署配置和 Windows / Linux 只读系统快照。系统页进入时和手动刷新时通过 SSH 采集 CPU 使用率、内存已用/总量、磁盘已用/总量、运行时间和系统版本。Linux 使用 `/proc` 和 `df`（排除内存文件系统），Windows 通过 PowerShell 调用原生 `GlobalMemoryStatusEx`、`GetSystemTimes`、`GetTickCount64` 和 .NET `DriveInfo`，不依赖 CIM/WMI 权限或服务；CPU 通过两次系统时间采样计算；CPU 不可用时标记暂不可用并保留内存和磁盘。

PowerShell 固定以纯文本输出，避免 SSH 默认 shell 影响输出格式；无需安装 RelaxKonOS 服务。刷新失败时保留本页上次快照并提示失败，切换主机使用独立页面状态。部署配置通过内置启动器执行安装或升级，并独立核验 SSH 状态和健康。安装回执查询只暂存 APK 内的固定启动器并执行读取，不执行安装 `--run`。

应用级观察、上传恢复与登录回填的支持边界见 [部署边界](../design/SupportScope.md)。真实 SSH、主机密钥变化、隧道换端口、后台回收及卸载检查集中见 [验证要求](../development/Verification.md)。

## 安装来源与执行

服务器维护页的“修复当前安装”打开独立确认弹窗，sudo 密码、防火墙选项和可选的“修复时重新生成局域网自签证书”均在弹窗中编辑；维护页仅保留修复入口。取消不执行修复，确认后关闭弹窗并在页面显示操作进度与结果。Linux/Windows 系统安装可编辑当前 IP 或域名（逗号分隔，默认包含 localhost、127.0.0.1 和当前 SSH 主机地址），确认目标名称及服务重启后随修复提交 `certificateMode=selfSigned` 和 `selfSignedIdentities`；普通修复保留原证书，User Mode 不提供证书修复。

表单按宿主隔离，地址为空或含非法字符时禁止提交，卸载/回滚不携带证书参数。更换后重新连接时需核对并信任新证书，不能绕过地址和有效期检查。APK 使用当前固定部署启动器；旧服务器部署引擎不支持证书修复时明确拒绝，需先升级服务器，避免报告成功却保留旧证书。

安装表单已接通 SSH 执行：官网包在服务器下载并自动核对摘要；手机选择的 ZIP 先从文档提供者复制到私有缓存，再上传；服务器选择的 ZIP 以绝对路径直接读取。自行选择的包仅检查结构、架构、必要文件和安全解压，不要求官方摘要。两种部署脚本直接包含在 APK assets 中，Linux 主机需要 Python 3，不再上传自包含验证程序。

安装前使用可信 SSH 会话预检系统、架构、权限和已有安装标识；提交前记录操作 ID，断线后可从操作记录核对结果。只有安装回执成功且独立 SSH 状态检查显示已安装、健康才显示完成。自动模式在非 root Linux 会话选择 User Mode，root 选择 System Mode，Windows 选择系统安装。

非 root 账户可显式选择 Linux System Mode，通过 sudo 验证后执行安装；独立 sudo 密码留空时使用 SSH 登录密码。密码仅经 SSH 标准输入传入本次安装器，不写命令行、请求、日志、磁盘或安全存储；部署引擎的标准输入置为 `/dev/null`，免密 sudo 也不会把密码传给引擎。

系统安装状态通过 sudo 读取，操作日志仍归原 SSH 用户，支持按原 ID 重连查询。自定义证书支持 PFX 或 PEM 证书链加未加密 PKCS#8/RSA 私钥，并在手机转换为 PFX 上传；证书口令不写入请求 JSON。

## 6. BP19-M1 手机本地 SSH 转发

已验证的 SSH 工作区在“管理”内提供“系统”“设置”“本地转发”三个顶部标签，主导航保留文件、终端、部署、管理四项。每条转发记录使用独立、重新核对固定主机密钥的 SSH 连接，仅将手机 `127.0.0.1` 监听映射到所选宿主的 `127.0.0.1` 端口；不接受任意目标主机或监听地址。

远端端口 1–65535，本地显式端口 1024–65535，留空由系统分配；端口冲突明确失败，不静默换端口。HTTP/HTTPS 与路径/查询用于服务地址描述，不注入 API 凭据，外部访问入口已接入，规则见 [服务访问](ServiceAccess.md)。

本地转发编辑器直接标出非法端口。修改端口、协议或路径后，取消和系统返回统一确认放弃；取消放弃继续原输入。忙碌期间冻结字段、协议、启动、取消及返回，页面级返回处理避免关闭请求穿透到宿主页面。点击启动后保留表单，只有实际监听创建成功才关闭；拒绝、取消或连接/端口失败保留输入并在表单内显示原因，失败反馈自动滚到可见区域，更正后需明确重试。完成反馈绑定本次编辑入口，旧反馈不关闭后来打开的表单；协程启动前取消也恢复非忙碌状态。表单滚动并在弹窗整体避让键盘。

支持创建、明确修改并重启、停止、重新启动、TCP 测试和移除，当前工作区最多 16 条。修改先停止该条，再尝试替代连接；失败保持该条停止，其他条与受管登录隧道保持独立。测试通过 SSH `direct-tcpip` 检查目标端口能否建立 TCP 通道，不发送应用数据；显示实际观察时间，不将其称为 HTTP/TLS/应用健康或本地监听端到端验证。

停止时分别尝试监听与会话清理，单条异常不跳过其他条。清理失败的行显示“停止结果待核实”，保留资源引用，禁止新建、重启及删除未确认的记录；表单内和页面均可重试“停止全部”。工作区关闭也不清空未确认的清理状态，取消后迟到的会话若无法释放同样保留以供重试。清理尚未完成时不自动观察或重连；再次清理成功才解除门禁，持续失败时明确提示完全停止应用。该机制不把异常吞掉后伪装成已停止。

离开 SSH 工作区后，登录页和服务器中心外层仍显示本地转发清理提示。提示可打开完整说明，关闭说明不移除待核实入口；重试停止全部无需再次输入 SSH 凭据，清理成功后提示自动消失。其他工作区清理异常通过外层三语反馈提示在系统设置中强行停止应用再连接。工作区关闭回调失败仍重置工作区身份和代次；服务器中心关闭回调失败仍清除会话密码。仅关闭子工作区时继续保留服务器中心会话凭据，遵守原有复用范围。

用户明确启动时开启 `SshForwardForegroundService`。其 `connectedDevice` 类型遵循 [Android 官方服务类型要求](https://developer.android.com/develop/background-work/services/fgs/service-types#connected-device)，manifest 声明对应权限和网络连接前置权限；不修改系统网络设置。

通知只显示通用连接文案和“停止全部”，不包含宿主/账号/端口/凭据；后台可继续传输，Android 或厂商仍可能中断网络。拒绝通知权限时保留应用内停止入口，不承诺通知可见。切 SSH 子页及旋转保留当前进程连接；关闭工作区/服务器中心、删除当前宿主、移除应用任务、服务停止或进程退出释放全部监听。服务非 sticky，无开机/进程重启自动恢复。

传输启用 20 秒 keepalive / 连续 3 次未回应上限，管理器每 3 秒核对已连接状态；检测断线后关闭该条并显示断线，用户核对目标后才能明确重启，不自动读取秘密重连。密码仅从当前已验证 SSH 工作区复制，握手后清除本次复制；记录和端口仅存在内存，不写本地资料或同步。用户转发从不接管或关闭受管 API 登录连接，其停止不是远端服务停止。

用户本地转发验证见 [验证要求](../development/Verification.md)。SFTP 与服务器中心逐动作对照见下一节。

受管宿主会话释放时先解除会话持有的隧道引用。隧道关闭抛出异常仍会尝试关闭 SSH 传输；原异常继续交给调用方，传输关闭的第二个异常作为 suppressed 附加，不替换原异常，也不重复关闭已标记关闭的会话。这不表示所有底层关闭异常均已恢复，调用方批量清理和实际设备释放仍须独立核验。

## 7. BP19-M2 SFTP 与服务器中心动作对照

新建文件夹与重命名的名称窗口在忙碌时禁用输入、保存和取消，系统关闭请求也不生效；写入结果未知时保留草稿并禁用保存，取消仍可用。名称按去除首尾空白后的安全单段规则校验，非法名称不可提交。控制器的新建、重命名与删除入口在清除草稿或确认目标前复查忙碌及未知状态，避免执行层拒绝操作时丢失目标。

SFTP 文件页提供绝对路径前往、上级/后退/前进（最多 64 条内存历史）、名称筛选、名称/修改时间/类型/大小升降序、目录优先、可见项计数与多选。筛选变化清除旧选择，“全选”只选择当前显示项。浏览每目录最多 1000 条，超出明确拒绝，不将截断目录伪装为完整列表。详情保留文件类型/大小/时间，文本/图片可预览；文本上限 1 MiB、图片字节 16 MiB / 4M 像素，流读取执行实际字节限制。返回列表前可明确放弃未保存文本；切子页/后台暂存当前进程草稿，新的 SSH 工作区或宿主清除旧草稿。

| 桌面动作 | Android 当前对应 |
| --- | --- |
| 地址/父目录/历史、搜索/排序、属性、选择 | 文件页同源元数据与有界历史/多选；不复制桌面键盘快捷键与窗口操作 |
| 新建目录、重命名、删除 | 新名称校验、目标存在拒绝、源元数据复核；单项及批量删除有明确确认，目录先规划再从叶子删除，不跟随符号链接 |
| 复制/剪切/粘贴 | 当前 SSH 宿主内的内存剪贴板；明确确认目的目录，拒绝自身/子目录/已存在目标；复制通过独立 SFTP 读写通道流式传输，剪切使用源重命名 |
| 文件/目录上传 | SAF 多文件或目录选择；先检查名称/目录/已报告大小，再按计划串行创建和上传；不申请广泛存储权限 |
| 文件/目录/多项下载 | SAF 单文件直接保存，目录或多项以流式 ZIP 导出；ZIP 仅包含已验证的安全相对路径，拒绝符号链接 |
| 文本保存 | 完整元数据复核后写入，读回新元数据供下一次编辑；原始 SFTP 不具备文件版本 CAS，不将复核当作并发原子保证 |
| 宿主增加/验证/主机指纹/删除、SSH 工作区 | 既有 Server Centre 目标/信任/密码会话与独立文件/终端/系统快照；新增用户转发见 BP19-M1 |
| 首次安装、升级、修复、卸载和发布获取 | 三来源 SSH 安装及回执/健康核实已接入；离页观察、上传恢复、登录回填和恢复上版等剩余工作归 AD01，不把 SFTP 传输当安装完成 |

每批最多 1000 个文件/目录、32 层和 2 GiB。复制/导出计划核对来源元数据、同名根、所有子路径和链接；实际字节预算继续防止来源变大。目录/批量传输不是事务，任何中断都可能留下部分文件。创建/上传/粘贴/重命名拒绝已知存在的目标，但当前 SFTP/JSch 没有原子“不覆盖”版本条件，仍存在与外部写入的竞争；不声称支持原子目录事务或跨宿主复制。目录检查和复制只执行 SFTP 原语，不拼接远端 shell。

SFTP 请求捕获宿主、工作区代次、路径和源快照；文件选择器注册按宿主/工作区代次隔离，返回前台并结束当前读取后才消费选择。每次重新核对主机密钥，密码复制只用于当前握手并清除。文件页使用应用持有的 `SshFilesController`：上传、下载、复制/剪切批次在切 SSH 子页、旋转或后台后继续，返回页面显示同一批次进度且不重发；浏览、预览及其他页面操作仍在离页时停止。传输进度在页面内展示，不用阻挡导航的弹窗。

传输开始时启动独立 `SshTransferForegroundService`（`dataSync`），通知展示通用传输状态、字节百分比和取消入口，不包含宿主、账号、路径或凭据；未知总量及复制/剪切阶段使用不确定进度。通知更新最多每秒两次，批次结束即停止服务。拒绝通知权限时仍保留页面取消入口。

服务处理 [Android 前台服务超时](https://developer.android.com/develop/background-work/services/fgs/timeout)，服务停止、移除应用任务、明确取消、关闭工作区或切主机时关闭活动连接；与用户本地转发的服务相互独立。系统或厂商仍可能中断进程/网络，服务非 sticky，不在重启后自动重试。

已发送写入失败/取消保留当前进程内按宿主隔离的受影响路径门禁，不自动重发；旧请求结束前禁止采用事实，随后必须明确读取受影响路径并确认采用当前事实。存在性核实不证明文件完整，目录内容仍须另行检查，也不清理残留或宣称原批次成功。进程退出后不提供持久传输恢复。部署包浏览器使用独立页面控制器，不覆盖后台文件传输的状态。浏览器观察打开时的账户会话；归属失效即停止读取并关闭，恢复前台、目录导航、刷新和包选择均核对原会话，不沿用另一账户的选择上下文。路径行最多显示两行，整行可打开可滚动的完整路径详情；关闭详情继续原目录浏览。列表、空状态和读取失败重试在独立滚动区域显示；读取失败或忙碌时不提供旧包选择。

## 安装选项与部署引擎

安装向导支持官方 HTTPS 发布目录、本地 ZIP、服务器 ZIP 与自定义 HTTPS ZIP（必填 SHA-256）。端口、系统模式程序／数据根、用户模式数据／配置／状态／缓存根、TLS、文件白名单、Linux 管理员与 root 的独立文件范围、Docker 授权及非标准 Linux 选择使用共享部署请求；系统选项受模式门控，用户模式固定 loopback 且不安装特权助手。语言自动跟随客户端，证书与密码通过私有暂存文件传递。审阅页列出配置与授权，不显示密码。

宿主侧目录定位与安装记录使自定义根在重连后的预检、更新、修复、回滚和卸载中继续生效。脚本参数逐项对应及维护者入口见 [`deployment/README.md`](../../../../deployment/README.md)。真实设备与主机安装验证仍以 `docs/development/Verification.md` 为准。

当前安装向导按请求阶段恢复：准备阶段失败可修正后明确重试；安装/升级执行后尚无回执或回执仍在排队/运行时，禁止再次提交，页面内提供“核实原安装操作”。已收到成功回执而后续健康读取失败时保留已成功结论，禁止重复安装并要求核实当前状态。核实使用原主机、主机密钥、平台与 operationId，只查询原回执；成功后执行只读 Status 检查，快照必须已安装且健康，并与原回执结果的 installationId 和安装模式一致；回执自身的安装标识或模式有冲突时不作为新的成功证据，首次读取仍保留结果未知门禁。读到其他安装时保留成功回执和待核实门禁，不清理原记录。失败或仍运行不生成新的安装/升级请求。明确终态拒绝允许修正后重试，缺少 SSH 会话密码或核实读取失败保留门禁。原操作上下文在安装执行前原子写入应用的 noBackup 私有目录，仅保存主机、密钥指纹、平台、安装模式、操作类型、operationId、是否需要提权与持久发送阶段，不保存密码、包路径或请求正文。进程重建和每次提交入口均先读取待核实记录；已进入发送阶段、读取损坏或更新失败时保留门禁。记录保存后还必须持久标记进入发送阶段，标记成功才执行安装；确认从未进入发送阶段的记录可在取消或重建时清理，不发送远端请求。尚未核实的记录不能被另一操作覆盖，清理必须匹配原操作、密钥与发送阶段；终态拒绝或成功后的健康核实完成且本地清理成功后解除持久门禁。

安装/升级向导及系统安装的修复页提供默认关闭的“添加服务器 TCP 端口防火墙规则”。用户选择后仅修改已开启的 Windows/Linux 防火墙，为当前监听端口添加持久化规则；防火墙未开启时提示且不添加规则，也不启用防火墙。Linux User 仅本机监听，不提供该选项。部署请求使用 `addFirewallRule`，终态结果以 `firewallStatus` 区分 `ruleAdded`、`disabled`、`notRequested`、`notApplicable`；只读检查不修改防火墙。

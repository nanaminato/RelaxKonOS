# AD01：Android 服务器初始化计划

> 状态：待开始本计划的端到端交付；已有基础件可复用。优先级：P0。工作量：中。
> 总入口：[无电脑部署路线图](./RelaxKonOS.Mobile.Deployment.Roadmap.md)。

## 1. 目标与边界

用户从登录页进入服务器中心，用 SSH 管理连接完成干净主机的预检、Server 安装、健康确认和登录。首轮验证选定的 Linux OS/架构组合；Windows 扩展沿用共享服务器中心契约，未验收的平台不显示为可安装。

安装模式必须符合主机权限。User Mode 保持账号范围，不能以安装成功推断具有系统 Docker、站点和防火墙能力。完整模式规则以 [共享服务器中心 Goal](../../../docs/platform/RelaxKonOS.ServerCenter.Goal.md) 与 [User Mode 文档](../../../docs/services/RelaxKonOS.UserModeServer.Goal.md) 为准。

本计划落实 [Android 服务器中心设计](./RelaxKonOS.Mobile.ServerCenter.Design.md) 的阶段交付，不重复定义身份键、SSH 信任和部署协议。

## 2. 现有基础与缺口

现有 `ui/servercenter/ServerCenterScreen.kt`、`ServerCenterCoordinator` 支持宿主资料与 SSH 验证；`ServerCenterDeploymentClient`、`ServerReleaseArchiveVerifier` 及 SSH/SFTP、隧道基础件可复用。尚需将预检、可信包获取、固定部署启动器、回执查询和登录回填接入完整 UI 与应用级恢复协调器。

首次交付前必须解决正式发行信任配置和发布资产可获取性。不能将开发测试签名、公钥任意替换或未经核验的下载 URL 当作正式发布方案。

## 3. 手机流程

1. 登录页选择“安装或管理服务器”，新建或选择宿主。
2. 输入 SSH 密码或私钥；核对首次主机指纹，变化时阻断并展示处理入口。
3. 预检 OS、架构、权限、磁盘、已有安装及连接方式，显示可选安装模式和缺失前置。
4. 选择经验证的发布版本或通过系统文件选择器选择签名包；展示目标、版本和变更摘要。
5. 授权后上传并调用固定启动器，显示上传与远端执行的独立阶段。
6. 读取远端最终回执和健康状态；建立直连或受管隧道，返回既有登录表单。

SSH 已认证、Server 已安装、API 健康与账号已登录是不同状态，不能一次握手成功便全部标绿。安装失败留在服务器中心，支持查结果、重新预检或明确的重试。

## 4. 实施阶段

| ID | 工作 | 完成条件 |
| --- | --- | --- |
| AD01-M1 | 确定宿主矩阵、发行信任及资产路径；接入远端预检 | 未安装、已安装、不支持、权限不足有真实结果与文案 |
| AD01-M2 | 版本/包选择、签名校验、SFTP 上传、首次安装页面 | 安装由固定受控操作驱动，参数与当前共享契约一致 |
| AD01-M3 | 应用级协调器、最小恢复记录、健康与登录衔接 | 离开页面后可观察原操作；隧道换端口不改变身份 |
| AD01-M4 | 更新、修复、恢复上版、卸载入口 | 核对安装标识，默认保留数据，显示最终核验结果 |

R1 要求 M1–M3；M4 在首次安装稳定后交付。脚本执行、安装布局和机器可读输出由共享部署引擎维护，Android 不内嵌另一套 shell 安装器。

## 5. 恢复与依赖处理

- 上传中断可重新取得凭据并恢复或安全重传；远端已执行时先查原操作，不能重复提交安装。
- 恢复记录只保存宿主身份、安装/操作 ID、版本和阶段信息；凭据遵守现有独立凭据域规则。
- 服务器安装成功后展示可用能力与前置缺失。若 Docker 缺失，明确下一步及支持范围；自动安装 Docker 必须有单独的共享宿主操作与授权，不能隐藏在登录动作中。
- 签名错误、架构错误、启动器缺失、磁盘不足、锁冲突和健康失败分开呈现。包传完或启动器退出不等于安装成功。
- 通知权限拒绝不阻断远端执行；任务详情保留可查询入口。手机进程被回收后的恢复按 [AD08](./RelaxKonOS.Mobile.OperationsRecovery.Plan.md)。

## 6. 验收清单

| ID | 场景 | 预期 |
| --- | --- | --- |
| AD01-T1 | 干净的受支持 Linux 主机，只使用手机 | 预检、安装、健康确认、登录全部完成 |
| AD01-T2 | 无 sudo 的 User Mode | 不触发系统安装或开放端口，不声称支持系统管理域 |
| AD01-T3 | 未信任/变化的 SSH 密钥、无效签名或错误架构 | 写操作被阻断，原因可理解 |
| AD01-T4 | 上传断网；执行后断网；旋转与进程回收 | 可核实原操作，不重复安装、不误报成功 |
| AD01-T5 | 升级失败、修复、卸载保留数据 | 真实结果可查；卸载后仍可进入服务器中心 |
| AD01-T6 | 隧道端口变化或主机重装 | 同安装保留稳定身份；新安装不复用旧安装信任与登录绑定 |

T1–T4、T6 为 R1 必需，T5 随 M4 验收。执行证据写入 [Mobile Progress](./RelaxKonOS.Mobile.Progress.md)，不以基础件单测替代真实主机验收。

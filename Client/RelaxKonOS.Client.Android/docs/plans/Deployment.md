# Android 部署后续工作

> 更新：2026-10-01。这里只记录尚需实现的交付；已接入功能见 [当前状态](../status/Progress.md)，缺少设备/宿主测试的事项见 [验收清单](../status/Verification.md)。

“只有手机也能部署”指 Android 操作用户已有的远端主机；不包含手机运行生产容器、购买云资源或集群。既有 AD 编号保留用于关联历史证据，不再重复建立已实现阶段的计划。

## 1. 服务器首次安装（AD01）

[服务器中心](../features/ServerCenter.md) 已有 SSH 信任、SFTP、隧道、部署选项和回执读取。缺口是可信首次安装执行闭环，不只是未做真机测试。

| 编号 | 剩余交付 | 完成条件 |
| --- | --- | --- |
| AD01-M1 | 受支持宿主/架构矩阵、可信发布源、完整预检 UI | 未安装/已有安装/不支持/权限不足有真实结果；下载资产可取得并受信任 |
| AD01-M2 | 发布包/服务器 ZIP 选择、可信校验器打包、SFTP 上传与固定启动器安装调用 | 摘要、清单、架构与布局通过校验后才执行，不把选择草稿当安装完成 |
| AD01-M3 | 应用级安装观察、上传恢复、健康核实和登录回填 | 离页/回收后查原操作，不重复安装；安装 ID 稳定，隧道端口变化不改变登录身份 |
| AD01-M4 | 更新/修复/恢复上版/保留数据卸载 UI | 核对安装标识、目标与数据影响，最终回执可查 |

流程：进入安装或管理服务器 → 验证 SSH 与主机指纹 → 预检权限/磁盘/模式 → 选择可信包 → 确认上传和执行 → 读取回执/API 健康 → 回填既有登录。

安装模式沿用 [服务器中心契约](../../../../docs/platform/RelaxKonOS.ServerCenter.Goal.md) 和 [User Mode](../../../../docs/services/RelaxKonOS.UserModeServer.Goal.md)。SSH 已认证、包上传、安装完成、API 健康和账号登录分开核实；主机密钥变化阻断，执行后失联先查原 ID，通知权限拒绝不阻断远端任务。Server 安装成功不代表具备 Docker/站点/防火墙能力，运行时安装走独立受控授权。

## 3. 内置应用补齐与交付顺序

新功能统一沿用 [BP00–BP24 补齐计划](BuiltInParity.md)，本表只补充首次安装和既有部署领域的剩余工作，不建立重复任务。优先补通 AD01 与安装/网络公共能力，再完成 Nginx、证书、FRP、Mihomo 等管理任务；其他领域按依赖推进。

首次安装到可访问应用的全手机流程尚未验收。旧 R0–R3 / V1-A–E / M0–M4 阶段表从当前文档移除；退出条件由集中验收清单与当前功能表追踪，不因删除旧路线图将未测项目标为通过。

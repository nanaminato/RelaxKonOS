# PostgreSQL DB-05：指定来源 TLS 远程访问

更新：2026-11-16。状态：Ubuntu 24.04 x64 / PostgreSQL 16 的指定来源 TLS 开启、关闭、桌面入口及隔离异机验收已实现。真实主机完整 Core/Helper/GUI 联调仍待验收。

## 支持范围与前置条件

在现有 DB-02/03 托管实例上，仅开放一个明确的本机非回环 IP、一个托管数据库和一个普通只读/读写账号。迁移账号不能对外开放；处于远程策略中的账号不能直接提升为迁移权限。IPv4、IPv6 均有真实异机验收。

来源为最多 16 个规范 CIDR：IPv4 前缀 /8–/32、IPv6 /32–/128，拒绝任意地址、回环、多播、链路本地、带 scope 的地址、主机位不为零的网段和 /0。监听 IP 必须已分配给该宿主，不接受 `*`、任意监听、域名解析或任意原生配置。首轮需要宿主已安装并可使用 `/usr/sbin/nft`（nftables）；应用不会暗中安装或替换宿主防火墙管理器。

证书来自既有证书中心，客户端选择证书并填写其覆盖的 DNS 名称。请求冻结证书 ID 和 SHA-256 指纹；Server 读取内部 PEM 材料，经私有 Helper IPC 传递，Helper 再核对证书/私钥配对、指纹、SAN 名称、有效期（至少剩余一天）及服务器 EKU。TLS 最低版本 1.2，远程 HBA 仅允许指定库/账号/来源的 `hostssl ... scram-sha-256`。

客户端必须使用受信 CA 和 `sslmode=verify-full`，不能把加密连接等同于服务器身份可信。自签名证书仅在客户端明确安装对应信任材料后使用。首轮不接受通配符 SAN 作为匹配依据，不提供仅 IP 名称证书的入口。

## 开启、关闭与恢复

使用独立 `PostgreSqlRemoteAccess` 安装服务及 `DatabaseRemoteAccess` 提权能力，复用实例与安装资源锁、幂等键、原操作回执和恢复入口。普通实例/账号/管理员恢复入口不能提交或接续远程访问事务。

开启顺序：

1. 核对包、配置、实例修订、账号身份、证书及来源。相同名称的外部 nft 表没有本实例证明时拒绝接管。
2. 在 root 管理根中保存原 postgresql.conf、HBA 和摘要。先发布只拒绝该数据库端口外部流量的防火墙脚本，再停止实例并确认 postmaster 已退出。
3. 写入托管 TLS 文件（postgres 所有、0600）及固定监听/HBA 配置，保存配置检查点。保留本机 peer 管理和原回环连接方式。
4. systemd 启动前执行本实例的防火墙 guard；启动后验证正常管理认证、配置身份及 TLS 设置，最后才向指定来源放行。成功保存原操作回执。

关闭顺序：先收紧本实例防火墙，再停止数据库、恢复原配置并核对摘要，删除自有 TLS 证书/私钥文件。**关闭后保持停机**，需从实例页显式启动；全部既有连接会断开。这样管理员认证失效时，也不会因无法执行 SQL 健康检查而阻止关闭外部访问。

失败维持端口隔离并停止数据库，保存原待恢复事务；显式恢复使用原请求、证书指纹和检查点。启动 guard 持久保存，排在 nftables/ufw/firewalld 启动之后、数据库监听之前。正常服务重启时，即使内核中该实例的表已丢失，也会先恢复规则。配置、TLS 文件和规则漂移通过读取检查报告为待处理，不宣称健康。

## 防火墙所有权与边界

每实例使用 `inet rkpg_<instance>` 独立表，input 链只处理该数据库 TCP 端口：回环保留、指定来源允许、其余来源计数并丢弃。规则通过 nft 原子批次更新；绝不 flush 全局 ruleset，也不修改无关表、默认策略或管理端口。

其他防火墙管理器仍可阻断允许流量，不能靠本表的 accept 绕过其他链的 drop。因此服务端验证不代表异机可达。宿主管理员重载全局规则造成的漂移不会被隐藏；当前没有持续后台自动修复所有第三方防火墙重载的守护任务。关闭后保留本实例的拒绝规则及启动 guard，避免历史开放意图在重启后重新生效；最终移除这些资源属于 DB-06 卸载。

原配置及 guard 只由 root 控制，原配置副本有摘要核对。Helper 台账和普通客户端操作记录不包含 PEM 私钥或密码；TLS 文件内容也纳入配置身份核对，查询会检查私钥 0600 权限。正常关闭删除 TLS 副本，证书中心原材料不受影响。

## 客户端与异机探测

桌面新增“TLS 远程访问”页，包含监听地址、DNS 名称、来源、账号及证书选择，独立确认/提权、开启、关闭、原事务恢复、同请求重试和操作日志；提供脱敏的 `verify-full` 连接参数。确认文本明确会断开连接及关闭后停机。viewer、失效会话和并发实例操作被阻断。

[外部探测工具](../../Tools/postgresql-remote-probe.py)在真实来源主机上运行，需要 Python 3 和 psql。请求从 stdin 读取，密码通过临时 passfile 提供，不进入 argv 或结果；输出只包含检查结果。示例结构（示例占位值不能直接用于验收）：

```json
{"host":"db.example.test","hostAddress":"192.168.10.5","port":55432,"database":"appdb","account":"appuser","caFile":"/path/to/trusted-ca.pem","password":"<supplied privately>","expected":"allowed"}
```

从允许来源运行 `expected=allowed` 检查真实 TLS 登录、非 TLS 拒绝、错误名称拒绝、错误密码拒绝；从拒绝来源运行 `expected=denied`，关闭后运行 `expected=closed`。失败连接本身不能定位是哪一层拒绝，需结合宿主规则计数和正常来源结果。桌面不伪造“已完成外部探测”，也不把人工或服务端本机检查计为异机证据；本轮 CLI 结果尚未自动回传到桌面。

## 当前边界

修改策略或部署更新证书须先关闭再开启，重新确认当前证书指纹。证书续期/吊销不会自动把新材料同步到 PostgreSQL；需要显式关闭或重新部署，客户端仍须校验证书。没有开放全公网、客户端证书认证、任意 HBA 编辑、多实例、多目标角色、任意 firewall 命令或共享外部实例接管。DB-04 管理身份恢复前须先关闭远程访问；关闭后的本机管理身份恢复仍沿原专属入口执行。

本次涉及 Shared Protocol、Core 授权/证书读取、Helper 和客户端，部署时需协调更新 Server/Helper/客户端，不能仅替换某个 ModuleHost 包。当前内置协议直接升级，不提供旧请求兼容解析。

## 官方语义依据

- [PostgreSQL 16 TLS](https://www.postgresql.org/docs/16/ssl-tcp.html)：TLS 配置、密钥文件权限及证书使用。
- [HBA](https://www.postgresql.org/docs/16/auth-pg-hba-conf.html)：hostssl 匹配加密连接，普通监听本身并不强制 TLS。
- [libpq SSL](https://www.postgresql.org/docs/16/libpq-ssl.html)：verify-full 的证书信任和名称检查。
- [nftables](https://www.netfilter.org/projects/nftables/manpage.html)：独立 base chain 的 accept 不覆盖其他链的 drop。

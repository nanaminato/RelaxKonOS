# 文件浏览器 Windows 11 体验优化进度

更新日期：2026-09-06。当前阶段：第一轮界面与操作逻辑已实现，编译和自动化回归已验证；真实桌面交互验收待完成。

## 目标与边界

让内置 RemoteExplorer 的常用操作尽量贴近 Windows 11 文件资源管理器，继续使用 RemoteOS 的窗口、主题、本地化、认证与宿主 OS 权限机制。允许增加文件 API，但需要同时落实 Protocol、Server、Client 和测试，不能仅放置不可用的 UI 入口。

本轮没有新增服务端 API。现有 drives/list/info、文件操作和上传接口足以支持本轮改动。搜索框为**当前已加载目录的名称筛选**，不递归搜索，不建立索引。现有删除仍为永久删除，并保留确认流程；尚无回收站或撤销能力。

## 验证记录

```bash
dotnet build Client/RemoteOS.Client/RemoteOS.Client.csproj --no-restore -m:1 -p:MSBuildEnableWorkloadResolver=false -v minimal
dotnet run --project Client/RemoteOS.Explorer.Tests -p:MSBuildEnableWorkloadResolver=false -m:1 --verbosity quiet
git diff --check
```

客户端编译（含 AXAML）通过，零警告、零错误；27 项自动化回归检查通过，`git diff --check` 通过。自动化用假文件客户端和本地化键替身验证状态逻辑，不连接真实服务器，不执行真实文件修改。SDK 默认构建曾无诊断退出；使用上述单进程构建并关闭 workload resolver 后通过。

尚未在真实桌面会话中做截图、鼠标、键盘、主题及真实服务端传输验收，因此下列项目不能视为已验证：

## 后续里程碑（尚未实现）

### P1：完成桌面交互验收与一致性

1. 先执行上面的手工验收清单，修复布局与事件路由问题。
2. 统一全部文件操作的远端路径工具：旧代码仍有 `Path.Combine`、`Path.GetDirectoryName` 和基于客户端 OS 的大小写策略；本轮仅保证面包屑与向上路径解析独立于客户端 OS。
3. 用一致的图标资产替换字符图标；加入排序菜单、自然名称排序、列排序后文件夹优先、列表/图标视图切换。
4. 支持框选、多项拖放、Ctrl 拖动复制、剪切项淡化、行内重命名；当前拖放仍是单项移动。
5. 将视图模式、列宽、隐藏项与排序选择保存为应用设置；目前是窗口内状态。
6. 增加标签页、主页快捷访问/最近项目；目前保留现有多窗口、导航树快捷入口，未实现标签页。

### P2：新增文件 API（候选设计，尚未冻结）

| 能力 | 建议契约 | 必须解决的行为 |
| --- | --- | --- |
| 大目录与递归搜索 | 扩展 list 分页/排序/过滤；新增 search 查询或搜索任务 | 稳定游标、目录变化一致性、结果上限、取消、权限不足、符号链接循环 |
| 批量复制/移动/删除 | POST files/operations + GET 状态 + 取消 | 每项进度、部分失败、冲突策略、取消后结果、幂等请求；UI 不伪装成原子事务 |
| 回收站/还原 | recycle、trash/list、restore | Windows/Linux 平台能力协商、原路径冲突、永久删除区分、无回收能力时明确提示 |
| 撤销 | 基于操作结果的可撤销记录 | 不承诺不可恢复操作可撤销；覆盖、跨盘移动与失效记录的处理 |
| 文件夹更改通知 | 文件目录订阅/事件 | 断线恢复、合并事件、权限边界与刷新节流 |
| 缩略图与预览 | thumbnail/preview（限尺寸、类型） | 缓存版本、大小限制、不可信文件解析隔离 |

每项 API 必须同步修改 `Shared/RemoteOS.Protocol/Files`、`RemoteOS.Server/Endpoints/FileEndpoints.cs`、`RemoteOS.Server/Files`、`IExplorerClient` / `ExplorerClient`，并继续复用 JWT、现有提权机制和宿主 OS 权限。

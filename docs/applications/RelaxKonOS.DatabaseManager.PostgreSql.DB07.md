# PostgreSQL DB-07A：自动停机恢复点与保留策略

更新：2026-11-17。范围：DB-07 的“PostgreSQL 备份自动化与保留策略”首轮切片。实现、桌面接线与隔离验收已完成；主版本迁移、多实例、MariaDB、Redis/Valkey 仍属 DB-07 后续子项。

## 范围及前置条件

沿用 DB-06 的 Ubuntu 24.04 amd64 / systemd / PostgreSQL 16 受管单实例，不新增安装源或版本。自动备份是**同安装内的停机物理恢复点**，使用完整数据/WAL/配置副本与隔离恢复验证。依据 [PostgreSQL 16 文件系统备份要求](https://www.postgresql.org/docs/16/backup-file.html)，普通逐文件复制必须停机并覆盖整个集群，不能把拒绝连接或在线文件复制视为一致性。

它不属于 APP-001 的可移植加密对象备份，不提供在线 pg_basebackup、PITR、异机导出、密钥迁移或灾难恢复保证。APP-001 的数据库适配、可恢复加密密钥域及跨安装身份/秘密重绑定仍须单独实施。DB-06 的版本、账号、凭据引用和恢复门禁保持。

前置条件：受管安装及目录/服务归属有效、无其他待恢复事务、关闭指定来源远程访问、无外部集群/表空间/未支持扩展或复制、空间充足。总备份上限仍为八份，为自动保留数量外至少预留一个新副本位置；手工备份占用位置不足时明确阻止，不自动删除手工恢复材料。

## 持续授权和客户端

使用独立 `PostgreSqlBackupAutomation` 安装服务和 `DatabaseBackupAutomation` 提权能力。策略绑定原实例、当前软件包版本及配置操作 ID；启用、修改、停用都经用户确认、提权和安装队列。普通维护、账号或实例权限不能配置或恢复自动备份事务。

策略包含启用状态、1–168 小时间隔、保留 1–6 份自动备份、是否授权停机。默认只在已停止的实例上备份；运行中跳过并显示原因，不停止服务。明确授权停机时，成功后恢复备份前的运行状态；原先停止的实例保持停止。远程访问开启时跳过，不自动关闭远程策略。失败可能保持停机待恢复，客户端确认明确说明这一影响。

启用后第一时段立即到期。持续授权在客户端关闭/退出登录后继续有效，直到停用；不保存用户密码或依赖登录提权缓存。停用阻止未来时段，已受理事务仍必须完成或恢复。更新和卸载停用策略，重新启用需核对当前版本。桌面显示下一时段、最近结果和共享安装任务 ID/状态；已受理但结果未知时保留原请求与幂等键。删除所选备份是独立确认的维护操作，不删除当前实例数据。

## 调度与中断

Core 每分钟使用轻量 Helper 策略查询，不刷新 APT 来源、不加载数据库驱动或读取备份树。只有 root 台账存在启用且到期的策略才通过共享 InstallationCoordinator 派发。幂等键绑定策略 ID 和 UTC 时段；请求固定，不因实例普通修订变化重新生成任务。

每次成功或明确跳过后，下一次为当前 UTC 加间隔。不补跑离线期间错过的历史时段；系统时钟回拨只延后未到期任务，前跳最多合并成一次到期工作。旧策略、未到期请求或禁用策略在 Helper 拒绝。UTC 运算由纯规则测试覆盖。

队列受理后丢失响应，下一轮返回原任务。原事务失败/中断时不更换键盲重试。Helper 有原待恢复检查点时从专属入口接续；如果 Core 在派发 Helper 前中断，原时段任务继续显示中断，需显式停用/重新配置策略建立新授权。新策略不能越过 Helper 原待恢复责任。

授权停机的原运行状态先写入 root 检查点，再停止服务。沿用 DB-06 的持久 systemd mask、无 TCP 私有恢复实例及清理。备份验证后再执行保留清理。恢复普通启动前保存派发阶段；未知启动结果只在原服务身份、配置及连接均有效时对账，不重发未知启动。

## 保留、删除与恢复引用

自动备份带明确来源标记。新备份完成校验前，不删旧副本。新副本有效后优先保留本次副本（即使系统时钟回拨），其余按时间和稳定 ID 排序，仅淘汰超出数量的**已验证自动备份**，不淘汰手工或更新/修复前备份。

删除前把准确备份所有权写入持久清理清单，并从可恢复列表移除，再删除受管备份目录。中断后的同一事务继续清理；不跟随链接或跨挂载点。清理失败保留原事务和清理责任，不删除当前数据、不报告全部完成。手工删除支持清理损坏备份，但仍须具备 root 台账中的准确备份归属。

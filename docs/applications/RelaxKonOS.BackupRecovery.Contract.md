# 共享备份与恢复契约（AD08-M3）

状态：服务端已实现运维提供恢复密钥的 AES-GCM 数据密钥封装、受管加密对象存储、持久清单及应用定义/修订快照；Android 可在能力门控下读取清单并执行只读预检。无卷、无秘密的定义备份可经显式确认恢复为新的停机应用实例；卷、数据库、秘密跨安装重绑定和真实恢复演练尚未实现。本文是跨客户端的服务端契约，不定义 Android 页面布局；移动端实施见 [AD08 计划](../../Client/RelaxKonOS.Client.Android/docs/RelaxKonOS.Mobile.OperationsRecovery.Plan.md)。

## 1. 权威记录

备份是服务端持久操作，不依赖发起请求的客户端继续在线。每次请求使用独立幂等键，得到不可变备份 ID 与操作 ID。客户端断线后按原 ID 读取状态，不能因 HTTP 结果未知重新创建备份或恢复。状态至少区分排队、执行中、已校验、失败、中断；“文件已写出”不是“已校验”。

清单记录来源安装 ID、应用 ID、当前修订 ID、每个对象的种类、版本、字节数、SHA-256、获取时间、一致性方法、加密密钥引用及校验结果。密钥材料、明文秘密、数据库连接密码和任意命令行不得进入清单、事件或诊断。保留与删除必须有上限和独立授权；删除备份不删除来源数据。

## 2. 支持对象与一致性

| 对象 | 允许的首轮方法 | 明确拒绝的情况 |
| --- | --- | --- |
| 应用定义与修订 | 从同一个目录事务读取定义及其当前修订；普通配置可归档，秘密只保留版本引用。 | 当前修订不一致、秘密版本缺失或目标无法重新绑定秘密。 |
| 受管命名卷 | 停止并核实所有引用容器已退出后取得离线快照，或使用经验证的应用专用快照适配器；清单注明方法。 | 活跃引用、非本应用拥有的卷、无法证明一致性、空间不足。在线逐文件复制不能标成数据库一致。 |
| 数据库 | 引擎专用在线备份/转储适配器，记录引擎和数据格式版本并执行读取校验。 | 没有适配器、未知版本、密钥或空间不足。通用 Docker 卷复制不替代数据库方法。 |
| Server 安装配置 | 由服务器中心的共享安装恢复契约单独处理，保留安装身份和密钥可用性检查。 | 仅凭应用修订回滚推断服务器配置或数据库已恢复。 |

目前 `IDockerEngineService` 没有卷导出/导入接口，也没有数据库原生备份适配器；应用秘密使用 Data Protection 保护，单独复制 `secrets.json` 不能保证在另一安装上解密。恢复密钥域只接受运维显式提供、可在替换安装中保留的 256-bit 密钥；未配置时对象写入立即拒绝，绝不回退到 Data Protection。因此服务端和 Android 都不得把卷、数据库或带有秘密重绑定要求的对象显示为“可恢复”，直到相应适配器及密钥恢复路径通过验证。当前定义备份会在写入后重新读取、校验认证标签、长度和摘要才进入 `Verified`；进程启动时未完成项被显式标为 `Interrupted`，绝不自动重放写入。

## 3. 存储与密钥

备份写入服务器受管、与应用数据分离的目标；不接受客户端提供的任意宿主路径。先计算对象大小和剩余空间，限制单对象、总容量、并发和保留数量。对象以独立数据密钥加密，密钥由可恢复的密钥管理域封装；清单只保存密钥 ID 和算法。创建后重新打开对象并校验认证标签、长度与摘要，才可转入“已校验”。密钥丢失必须报告不可恢复，不得降级为明文备份。

外部导出需要用户显式选择目标，且必须连同密钥可迁移方案一并设计；仅把密文文件发到手机不构成可恢复备份。秘密版本引用在原安装可解析，不代表跨安装可解析。

## 4. 恢复预检与提交

恢复先读取并验证完整清单、所有对象和密钥，再检查来源/目标安装身份、应用所有权、目标名称与卷冲突、磁盘空间、镜像/修订可用性、数据库引擎及数据格式兼容性。预检返回将创建或覆盖的对象、停机影响和无法满足的前置条件；预检结果绑定清单摘要与目标当前版本，提交时重新核对，变化则拒绝。

首轮优先恢复到新应用实例和新卷，核验数据、启动健康和服务路由后再由用户另行确认切换。覆盖原实例必须独立授权和可读的影响清单。恢复失败保留原实例以及持久诊断状态；不能因为容器启动就宣称数据库校验通过。应用镜像回滚不撤销卷或数据库的数据迁移。

当前定义恢复路由要求 `confirmed: true` 和独立 `Idempotency-Key`，并只接受预检无阻止条件的清单。它会创建一个**新且停止**的应用定义；宿主端口和站点绑定不会被继承，旧实例、卷和秘密绝不被覆盖。该最小恢复不构成数据库或数据卷恢复成功的证明。

## 5. 验收门槛

AD08-T6 必须在活跃数据库、损坏对象、空间不足和密钥丢失场景中证明一致性或明确失败；AD08-T7 必须在新实例上读取真实数据，并阻止不兼容格式覆盖。测试需要记录备份 ID、对象摘要、恢复操作 ID、数据库版本、读回验证和故障结果。单元测试、模拟 Docker 或只读清单检查均不能代替真实恢复演练。

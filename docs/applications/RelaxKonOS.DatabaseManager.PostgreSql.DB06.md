# PostgreSQL DB-06：补丁维护、备份恢复和卸载

更新：2026-11-16。状态：Ubuntu 24.04 amd64 / systemd 的 DB-06 切片已实现并完成隔离原生验收；真实主机完整 Core/Helper/GUI 联调仍待验收。

## 已开放的路径

桌面维护计划可同时显示宿主报告的软件包状态问题与当前实例的精确修复候选。候选仍须匹配实例和修订，同版本修复继续使用原确认与 Helper 复核。

| 操作 | 范围 |
| --- | --- |
| 同主版本更新 | 已实测官方 Ubuntu `16.2-1ubuntu4` → `16.15-0ubuntu0.24.04.1`；含由旧版 initdb 建立的数据、托管数据库及最小权限账号 |
| 同版本修复 | `16.15-0ubuntu0.24.04.1` 重装；实际损坏 postgres 可执行文件后恢复，并核对数据保持。此操作不计作跨版本更新 |
| 备份与恢复 | 停机完整物理副本；包含 WAL、系统角色、授权和配置。恢复要求同实例、同精确软件包版本、同配置摘要及同账号/凭据引用 |
| 保留数据卸载 | 仅移除 `postgresql-16` 引擎包；保留实例、配置、备份和 Server 加密凭据，重装后显式启动 |
| 删除数据卸载 | 必须确认完整实例 ID；删除该实例的数据、配置、备份和托管凭据，保留删除记录。重装不隐式创建实例，需显式初始化 |

仅接受已有官方 Ubuntu noble/main、noble-updates/main、noble-security/main 来源及既定 Ubuntu 签名密钥。维护计划单独刷新签名索引，冻结精确版本、依赖、URI、长度和 SHA-256；下载后及包变更前再次校验制品。未来候选版本不会因被发现而自动开放。

首轮拒绝其他原生集群、其他 PostgreSQL 主版本/扩展软件包、未托管逻辑库、除 plpgsql 外的扩展、复制槽、订阅、外部表空间、符号链接和数据树内挂载点。关闭 DB-05 远程访问后才能维护。拒绝任意源、参数、SQL、路径或外部实例接管。

## 一致性与维护顺序

采用 PostgreSQL 官方的[停机文件系统备份要求](https://www.postgresql.org/docs/16/backup-file.html)与[次版本升级规则](https://www.postgresql.org/docs/16/upgrading.html)。

1. 核对归属、修订、原生包状态、配置、外部实例、空间和冻结目标。预留至少当前数据大小四倍加 512 MiB；首轮最多保留八份备份，达到上限会拒绝新增备份的维护，不静默淘汰恢复材料。
2. 持久化原事务，发布实例专属 systemd mask，停止普通服务并确认 PID 为零。维护中的 PostgreSQL 仅使用私有 Unix socket，`listen_addresses=''`；不创建 trust HBA。
3. 完整复制停机数据和配置，保存逐文件 SHA-256 清单并同步文件系统。复制独立恢复目录，执行 `pg_checksums --check`、真实启动、全体普通表读取，以及托管数据库/角色 OID、归属、成员关系和权限核验；停止并删除演练实例和临时 socket 后，才将备份记为可恢复。
4. 更新在已验证备份后安装冻结目标。损坏二进制修复先保存并同步原始停机副本，重装可信程序，再验证该副本与隔离恢复；验证失败不开放服务。保留数据重装不执行 initdb。
5. 对旧集群执行发行说明要求的官方 `fix-CVE-2024-4317.sql`（包含 template0/1），并对数据库重建索引和 ANALYZE。template0 的临时连接设置在 finally 中恢复；事务中断后仍在持久隔离下接续该幂等步骤。依据：[16.3](https://www.postgresql.org/docs/16/release-16-3.html)、[16.10](https://www.postgresql.org/docs/16/release-16-10.html)、[16.15](https://www.postgresql.org/docs/16/release-16-15.html)。
6. 完成验证和临时配置清理后，移除自有 mask 并提交回执。所有维护成功后保持停止，用户显式启动。

恢复先为当前数据生成另一个已验证备份，再在同一实例父目录暂存所选副本、隔离旧目录、切换并验证，最后清理旧目录。版本或配置不一致，以及备份后改密、增删账号或授权变化，均在派发前拒绝；不会复活已撤销的凭据。备份不能作为跨版本降级入口。

## 卸载与归属

不使用 purge/autoremove，不移除共享客户端、common 包、依赖库或全局来源。外部集群会使软件包移除在派发前拒绝。保留数据时台账明确表示引擎已移除，仍保有该实例责任。

删除操作只作用于已证明归属的实例路径及对应备份根；不跟随链接或跨挂载点。清理自有远程 guard/规则时核对专属名称，其他防火墙规则不在删除范围。Helper 提交删除后，Server 按实例清理全部加密凭据引用；此步骤可幂等重试，未完成时不得报告安装事务成功。外部消费者的凭据更新并未自动化。

## 中断和失败

独立 `PostgreSqlMaintenance` 安装服务和 `DatabaseMaintenance` 提权能力复用组件中心的持久安装队列、实例/包锁及原幂等键。普通生命周期、账号、管理员恢复和远程访问权限不能提交或接续维护。

Helper 保存停机、备份、软件包派发、软件包完成、恢复目录切换和清理阶段。真实 Helper 终止后、systemd 重启后，持久 mask 继续阻止普通启动；恢复只能接续原事务。已完成的包操作通过冻结目标、dpkg 状态、审计及文件完整性核验后接续，不盲目重复未知原生变更。目录切换保留旧目录及阶段证据；清理失败继续保留责任。

这不是跨补丁自动降级：不确定或部分完成的 dpkg 状态继续隔离，需修复原生包状态后核验；不会宣称已回滚或自动启动旧二进制。真实断电、磁盘损坏、离线旧包降级、主版本迁移和任意扩展均未验收。

## 客户端和验收

Avalonia 的“组件与恢复”页提供候选核实、更新、修复、备份选择恢复、两种卸载及重装。删除须输入无连字符的实例 ID；持有独立持久任务键。丢失响应时冻结原请求与幂等键；会话失效、只读角色、其他数据库事务繁忙或未关闭远程访问时禁用相应操作。提供中英日文状态与提示。

验收容器 `relaxkonos-db06`：Ubuntu 24.04.5 amd64、真实 systemd，标签 `relaxkonos.task=db06`，无宿主挂载、无公开端口。16.2 仅在一次性容器内用 Ubuntu 官方旧包构造旧实例夹具；产品首次安装不允许降级，测试台账改写不是产品接管或迁移能力。旧实例使用真实 16.2 initdb，然后使用维护产品入口升级至 16.15。

- 基线安装/初始化/启停与恢复：29 项；旧版账号/授权/改密：44 项。
- 真实跨补丁更新：8 项，包含恢复演练、行数据与索引保留、新版进程版本及跨版本恢复拒绝；分别在无应用账号和有托管账号的实例通过。
- 备份恢复、外部集群保护、损坏二进制修复、保留/删除数据卸载与重装：26 项。
- 备份阶段真正终止 Helper：3 项；重启 systemd 后接续：8 项。恢复目录切换阶段终止 Helper：5 项；重启后接续：8 项。均含双栈关闭、普通启动拒绝及数据保留。此证据不是物理断电测试。
- 备份后正常改密恢复拒绝：6 项；真实备份验证失败及原操作恢复：4 项；符号链接/挂载点边界与后续完整生命周期：29 项。
- 服务端聚焦检查：76 项；桌面聚焦检查：74 项，含维护授权隔离、按实例凭据清理、原请求重试和三语言渲染。

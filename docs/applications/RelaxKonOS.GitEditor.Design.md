# 内置 Git → IDEA 风格项目编辑器改造设计

状态：**设计中**。2026-10-24 建立；本文描述目标与实施顺序，不代表功能已实现。

## 1. 定位与范围

将内置 Git 从按页面操作的版本控制客户端，改为以项目和文件编辑为中心、同时提供完整现有 Git 操作的编辑器。参考 IntelliJ IDEA 的工具窗口组织和 MyGit 的变更审阅流程，沿用 Avalonia 与现有远程 API，不引入 JVM、Web IDE 或另一套 Git 引擎。

首版保留 `relaxkonos.git` 作为该应用的唯一 App ID，显示名称调整为“项目编辑器 / Project Editor”，三语言同步。它是现有 Git 应用的直接演进，不新增旧入口别名。独立 `relaxkonos.codeeditor` 继续提供轻量文件编辑，两者共享编辑组件，不合并应用身份或默认文件关联。

目标闭环：打开项目 → 浏览全部文件 → 多标签编辑和保存 → 查看真实磁盘变更 → 暂存/取消暂存 → 提交 → 推送；同时保留分支、历史、远程和冲突处理。普通非 Git 文件夹也可编辑；只有执行初始化命令并确认后才运行 `git init`。

首版不含 LSP、智能补全、调试、插件市场、任意拖拽停靠、交互式 rebase、按行暂存、可编辑 Diff、后台项目索引和嵌入终端。它们分别为计划中能力，不用不可操作按钮或模拟数据占位。已有独立终端和构建能力不因视觉参考而扩展权限或执行机制。

## 2. 参考与现状依据

- [MyGit](https://github.com/Binaryify/MyGit)：借鉴紧凑变更列表、审阅与提交的连续流程；不照搬其技术栈。按行暂存、评论导出等是参考项目能力，不作为 RelaxKonOS 当前能力声明。
- [IntelliJ IDEA 用户界面](https://www.jetbrains.com/help/idea/guided-tour-around-the-user-interface.html)：借鉴项目选择、分支入口、中央编辑器、侧边工具窗口和底部工具窗口的关系；不是复刻全部 IDE 功能或商标素材。
- [GitClient 现有说明](./RelaxKonOS.GitClient.md)、[Code Editor 现有说明](./RelaxKonOS.CodeEditor.md)、[内置应用约束](../development/RelaxKonOS.BuiltInApplication.Conventions.md)。

## 3. 信息架构与视觉布局

```text
┌ 项目菜单 / 项目名 ─ 分支与同步状态 ─ 保存 / Git 操作 ─ 窗口控制 ┐
│工具条│ Project / Commit  │ 文档标签：源码、Diff、历史文件           │
│      │ 可折叠侧工具窗口  │ 路径面包屑                             │
│      │ 文件树或变更列表  │ 中央编辑器 / 预览 / 只读 Diff          │
│      │                  ├───────────────────────────────────────┤
│      │                  │ 底部 Git：日志 / 分支 / 远程           │
├──────┴──────────────────┴───────────────────────────────────────┤
│ 状态 / 任务 / 错误                         行列 / 编码 / 换行符 │
└────────────────────────────────────────────────────────────────┘
```

编辑器是持续存在的主工作区，Project 与 Commit 切换只更换左工具区；Git 日志在底部展开，不替换或卸载中央文档。首版支持侧栏、底栏显示/隐藏和分隔条缩放，尺寸按当前窗口记忆。概览信息移入项目空态/详情，远程和分支移入 Git 工具区，冲突继续使用现有三方解决流程。

这是内置应用约束 §8 默认“左导航 + 内容页”的有意例外：编辑器需要同时查看源码和变更，并持续保留编辑状态。每个工具区仍采用独立 AXAML；不在一个页面堆叠所有功能，也不把已包含标题和活动栏的 `CodeEditorView` 整体嵌入 Git 壳形成两层工具栏。

宽度 ≥1100 DIP 默认显示左栏与底栏；760–1099 DIP 底栏默认收起，工具条可换行；低于 760 DIP 侧栏改为覆盖式工具区，保留当前文档与工具切换入口。初始窗口沿用现有 1180×760，最终尺寸用预览与手工验收确认。恢复尺寸需按可用空间限幅。使用现有主题资源、图标与字体，支持浅色/深色、高 DPI、键盘焦点和工具提示，不硬编码 IDEA 配色。

## 4. 关键交互

### 4.1 项目与文件

每个窗口拥有一个项目根目录；多个项目通过多窗口并行。项目身份包含连接/服务器与服务端规范化根路径，不能只用目录名区分。打开普通文件夹时不强制注册 Git 仓库；探测失败、权限不足、Git 缺失与确实非仓库必须分别提示。

文件树延迟加载，包含未跟踪和未修改文件，不能拿 Git 变更列表替代目录树。单击选择、双击/Enter 打开持久标签；首版不引入会自动替换的预览标签。相同远程文件复用同一文档，路径相等性遵循服务端语义，不能根据客户端 OS 决定。

文本复用 AvaloniaEdit、基础高亮、查找替换、编码与换行符；图片复用现有预览，二进制保留只读说明。标签显示未保存标记和完整路径提示。保存、全部保存、关闭标签和关闭窗口拥有明确结果；全部保存部分失败时保持失败文档的脏状态并阻止后续依赖操作。

### 4.2 Git 与编辑联动

Commit 工具区分别展示已暂存、未暂存、未跟踪和冲突；同一文件同时存在 index 与 worktree 变化时显示两个对应项。选择变更打开可复用的 Diff 标签，键必须包含项目、路径、比较类型和提交 SHA；历史版本与已删除文件不得误当当前文件编辑。

“在编辑器中打开”在当前窗口打开工作树文件；历史记录另提供“打开此版本（只读）”，与“打开工作树版本”分开。已删除文件只提供可用的历史/Diff 操作。选择文件不隐式暂存，打开 Diff 不保存编辑器内容。

保存成功后刷新相关文件状态与活动 Diff；暂存、提交、checkout、pull 等成功后按影响范围刷新。提交只包含界面明确选择的磁盘文件，沿用并核实当前服务端提交语义；不把全部 index 内容或未保存缓冲区悄悄加入提交。

Git 工具区必须保留现有 fetch、pull、push、分支和远程操作、历史筛选、revert、冲突继续/中止的可达入口；操作能力随真实仓库状态启用。缺失 Git 时仍可编辑文件，安装入口复用既有面板。本次不改安装、版本、修复、更新、卸载或发布源；后续涉及这些行为须先遵循受管运行时设计。

### 4.3 草稿、外部修改与危险操作

| 场景 | 规则 |
|---|---|
| 关闭脏标签/窗口、切换项目 | 列出受影响文档，保存/放弃/取消；取消不改变项目和标签；保存失败不继续关闭 |
| checkout、pull、merge、revert、冲突继续/中止、文件还原 | 首版保守检查当前项目全部脏文档，先处理草稿，再执行原有 Git 预检与危险确认；保存草稿不表示 Git 必然允许操作 |
| 暂存/提交与相关脏文档并存 | 明示磁盘版本与缓冲区不同，保存后重新读取状态再提交，或取消；首版不提供容易误解的静默跳过 |
| 外部修改命中干净文档 | 重新读取，尽量保留光标/滚动；文件消失则标记删除，不偷偷新建 |
| 外部修改命中脏文档 | 保留草稿并标记冲突，提供重新加载/比较；覆盖必须再次确认并使用最新版本令牌 |
| 写请求断线、结果未知 | 保留草稿，重连后核对内容/请求结果；不得无限自动重试覆盖 |

仅“保存前重新读取”仍有检查与写入之间的竞争。首版安全保存需要 Files 协议提供不透明版本令牌及条件写入，由服务端在同一文件写入协调范围内比较并更新；不匹配返回稳定冲突问题码。外部进程并不受应用内锁控制，因此实际保证边界与平台文件替换能力必须在实现中验证，不宣称对所有外部工具提供事务隔离。

## 5. 架构、协议与存储

建议结构为 `GitClientApp → ProjectEditorWorkspaceViewModel → EditorSession + GitClientViewModel`。命名为设计建议，实施时可按现有约定调整，但职责必须分离：

- `EditorSession`：文档、路径身份、草稿、保存、关闭与外部版本状态；从 Code Editor 提取公共能力，独立编辑器同步改用该能力，不复制一份 ViewModel。
- `EditorPane`：编辑标签与内容，不创建窗口、不拥有另一个应用标题栏；独立编辑器与项目编辑器共享。
- 项目协调层：打开项目、工具窗口、文件定位、保存后刷新、Git 操作前的草稿检查；不把所有逻辑继续塞入 `GitClientViewModel`。
- Git 领域层保留 `IRemoteGitClient`、现有服务、Diff 和冲突模型。跨区域事件采用可取消的显式回调/接口；不依赖全局事件总线。

Client 只负责 UI 与窗口会话；所有远程文件访问经 `IExplorerClient`，Git 经 `IRemoteGitClient`；Server 保持认证、有效宿主身份、权限、规范化路径与边界检查。路径组合、符号链接/重解析点逃逸、大小限制不能只在 Client 检查。Git 进程继续传递结构化参数，不拼接 shell。

首版唯一预期新增的服务端能力是 Files 条件读取/写入契约及其验证；DTO、版本字段、路由使用 `Shared/RelaxKonOS.Protocol` 定义。直接更新所有桌面、Android、服务端、测试和示例调用者，不添加双格式解析或旧 API 适配。实施前核查文件读取返回形式，确定版本元数据应使用响应头还是 DTO，避免为了该设计引入与现有传输重复的协议。

窗口会话保存打开文档与草稿，不将正文持久化到共享偏好或日志。项目最近记录沿用现有用途与作用域；工具区尺寸仅保存非敏感布局偏好。Git 状态与历史以服务端实时结果为准，不另建提交数据库。本阶段不新增数据表或同步未保存文本；重启草稿恢复为计划中，不承诺当前可恢复。

## 6. 并发、错误与安全

文件加载、Diff、状态查询都有取消令牌与项目代次校验；晚返回的项目 A 请求不能修改项目 B。窗口关闭取消请求、停止刷新并释放文档/图片、订阅和会话；工具区折叠不销毁文档。保存与更改工作树的 Git 操作通过项目协调门避免同窗口交错，服务端继续负责跨窗口写入协调。

首版刷新入口为显式刷新、窗口重新激活、保存成功与 Git 操作完成；需要合并重复刷新并限流，不扫描整个项目。监听与后台轮询为计划中。列表与历史使用已有分页/虚拟化，目录按需加载；二进制和过大文本应明确降级，限制以现有服务端能力为基线并在实现时记录。

断线保留已加载的草稿和只读缓存，禁用依赖服务端的写操作；重连先验证连接身份与项目路径，再刷新状态。权限错误、文件消失、编码失败、版本冲突、Git 忙/冲突/凭据缺失分别映射本地化问题，不以空列表假装成功。凭据继续委托已有宿主机制，不新增凭据保存、SSH 通道或客户端直接访问宿主文件。

所有文案、空态、菜单、确认、工具提示同步 `en-US`、`zh-CN`、`ja-JP`，支持运行时语言切换。危险操作沿用目标明确的确认与审计；日志只记录动作、对象与结果，不记录源码、草稿、令牌或凭据。应用权限声明随新增文件读写行为更新，服务端认证和宿主权限检查不因 UI 整合而弱化。

必须覆盖的验收：

1. 普通目录与仓库均可打开；不隐式初始化；多窗口与同名跨服务器文件不串状态。
2. 文件树打开多个文本/图片/二进制；标签去重、查找、编码、保存及独立 Code Editor 无回归。
3. 保存后变更列表与 Diff 更新；同一文件的 staged/unstaged 比较正确；历史文件只读；删除文件不被误创建。
4. 暂存、取消暂存、选择性提交、推送、分支、远程、历史筛选和三方冲突原有入口均可用。
5. 关闭后台脏标签、窗口、切换项目、checkout/pull、部分保存失败和用户取消都不丢草稿。
6. 条件写入冲突、多窗口保存、外部删除/修改、保存断线结果未知、项目切换后旧请求返回均有验证。
7. 双平台覆盖路径越界与链接、只读/权限错误、二进制/大文件降级；关闭后无刷新与订阅泄漏。
8. 三语言动态切换、浅深主题、键盘焦点、高 DPI 与三档宽度完成预览；未实测平台明确记录为设计中。

代码阶段执行相关 Client/Protocol/Server 构建与有实际行为断言的测试，包括 `Tests/Client/RelaxKonOS.GitDiff.Tests`、相关窗口预览检查及文件写入集成测试。本次 D0 仅检查文档差异与链接，不将其作为代码或平台验证结果。

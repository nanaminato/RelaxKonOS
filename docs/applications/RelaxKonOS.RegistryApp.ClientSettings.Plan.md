# 客户端体验属性的注册表扩展计划

记录日期：2026-10-13。状态：第一批已实施；后续批次待实施。本文记录当前字段、实施顺序与验收要求。

## 目标与范围

优先增加影响客户端显示与交互的属性，让修改效果容易观察、容易恢复。服务端可以负责保存、同步、校验和权限检查；这些属性不修改服务器进程、PTY、shell 环境、系统注册表或服务配置。

首批聚焦桌面终端和注册表应用，延续当前的内容边距、紧凑布局、窄滚动条和 JSON 树交互。其他应用按后续批次推进。Android 的具体界面和实现说明由 [Android 文档](../../mobile/README.md) 所链接的 Android-owned 文档维护；修改共享契约时仍需同步更新 Android 调用方，避免保存时丢失新字段。

## 存储与生效原则

- 工作区偏好随工作区同步，适合光标风格、历史滚动行数、显示隐藏文件等行为偏好。
- 当前设备的客户端偏好按用户和客户端设备隔离，适合内容边距、控件尺寸、侧栏宽度和窗口几何信息。不得误用服务器宿主设备作为客户端设备。
- `Workspace\Terminal` 继续使用其唯一权威文档。`Device\Client\Terminal` 和 `Device\Client\Registry` 已作为当前客户端设备的托管配置入口，在 HKCU 下显示；设备 ID 来自登录 JWT 的 `device_id`，其他用户的设备范围不可访问。
- 设备级属性统一使用客户端设备身份、存储范围、键树入口、默认值、读取和写入路径；不临时放入工作区后再保留第二份副本。
- 每个属性声明类型、默认值、合法范围、描述与生效方式。数值单位采用 Avalonia 逻辑像素，数量采用整数。
- 注册表与常规设置界面共用同一数据源、校验和写入逻辑，不增加配置副本。优先复用已经存在的字段，避免相同功能出现两个属性。
- 仅在属性已接入实际行为后开放编辑。支持恢复默认；写入保留文档 revision 和其他属性，遵循现有用户、设备及提权边界。
- 外观属性尽量立即生效。确实需要重新打开应用时明确显示生效方式，不要求重新启动服务器。
- 尚未正式发布：采用当前契约，更新全部仓库内调用方、测试和示例，不增加旧字段别名、双格式解析或迁移适配。

## 第一批：终端和注册表

下列字段已实施。设备布局使用当前视觉表现为默认值；两种终端引擎均支持光标样式及闪烁，共同默认值为 block 和 true。

### 终端

| 注册表入口 | 字段 | 类型 | 默认值 | 合法范围 / 候选值 | 生效方式 |
|---|---|---|---|---|---|
| `Device\Client\Terminal` | `paddingTop` | Integer | 8 | 0–32 | 立即 |
| 同上 | `paddingBottom` | Integer | 4 | 0–32 | 立即 |
| 同上 | `paddingHorizontal` | Integer | 6 | 0–32 | 立即 |
| `Workspace\Terminal` | `scrollbackLines` | Integer | 10000 | 0–100000 | 立即，缩小时可丢弃最旧历史 |
| 同上 | `cursorStyle` | Enum | block | block / underline / bar | 立即 |
| 同上 | `cursorBlink` | Boolean | true | true / false | 立即 |

实施要求：

1. 内置终端和 xterm.js 均读取同一组偏好，边距影响实际布局与终端行列计算。
2. 历史行数应用到新建、恢复和切换引擎后的屏幕，不能只修改控件初始化值。
3. 光标样式和闪烁必须验证两种引擎均能控制；不通过反射尝试后静默忽略，也不把无效控件暴露给用户。
4. 不把渲染器输出传输缓冲大小当成可滚动历史行数；它们用途不同。
5. 修改纯外观设置不重建、停止或重启 PTY。引擎切换继续遵循现有会话生命周期。

### 注册表

| 注册表入口 | 字段 | 类型 | 默认值 | 合法范围 | 生效方式 |
|---|---|---|---|---|---|
| `Device\Client\Registry` | `treeRowHeight` | Integer | 24 | 20–40 | 立即 |
| 同上 | `valueRowHeight` | Integer | 26 | 22–44 | 立即 |
| 同上 | `iconSize` | Integer | 16 | 12–24 | 立即 |
| 同上 | `scrollbarThickness` | Integer | 6 | 4–12 | 立即 |
| 同上 | `sidebarWidth` | Integer | 280 | 180–600 | 立即，并受当前窗口可用宽度限制 |

实施要求：

1. 主键树和 JSON 编辑树使用一致的滚动条、图标和行高规则。
2. 缩窄滚动条不隐藏或禁用滚动：溢出时保留横向、纵向滚动条，支持拖动滑块和滚轮。
3. 修改布局保留树展开状态、选中项和可保留的滚动位置，不重新请求整棵树。
4. 拖动侧栏分隔条更新同一 `sidebarWidth` 偏好，避免启动后又覆盖用户调整的宽度。
5. 编辑注册表自身外观时，当前编辑对话框保持可用；恢复默认能够撤销过小或过大的设置。

### 当前生效边界

同一桌面客户端通过注册表或终端设置成功保存后，已打开视图立即更新。打开应用及显式刷新会重新读取配置；有打开视图时每 30 秒修复外部写入或遗漏的更新，读取失败保留最后一次成功设置，不排队重放写入。此周期性读取不替代写入时的 revision 冲突检查。未登录、本地终端和 SSH 桌面终端继续使用本地默认布局，不读取其他登录上下文的工作区偏好。

内置终端使用模拟器输出接口应用 DECSCUSR 光标控制序列，xterm.js 使用其 options；两者都不会把外观设置发送给 shell。终端传输输出缓冲仍保持内部固定上限，不作为用户偏好暴露。

## 后续批次

| 批次 | 应用 | 建议属性 | 备注 |
|---|---|---|---|
| 第二批 | 文件浏览器 | 图标大小、列表密度、显示隐藏文件、显示扩展名 | 已有 `ShowHiddenFiles`、`IsCompactView` 等字段先复用；区分列表密度与图标尺寸 |
| 第二批 | 浏览器 | 默认缩放、新标签页地址 | 缩放先明确设备级范围；地址校验沿用浏览器安全和导航规则 |
| 第三批 | 桌面 | 图标大小、图标间距、标签显示 | 复用已有桌面显示/外观配置，不建立第二份布局数据 |
| 第三批 | 窗口 | 默认尺寸、记忆位置与尺寸 | 优先复用现有窗口布局，明确设备、显示器和应用的定位，恢复时限制到可见区域 |

实施每个后续批次前核对已有设置，列出确定的字段、默认值、范围、生效方式和验收项；不一次性开放尚未实现的全部候选属性。

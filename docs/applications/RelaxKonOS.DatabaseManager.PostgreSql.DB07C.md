# PostgreSQL DB-07C 多实例管理

首轮范围为 Ubuntu 24.04 amd64、systemd、同一受管 PostgreSQL 主版本和两个本机实例。一个宿主共享引擎软件包，实例各自持有配置、数据、Unix socket、端口、服务、账号、凭据引用、备份和恢复责任。实例从已有可信受管安装创建，初始化前核对软件包、目录归属和实际端口。远程访问及混合主版本纳入后续矩阵。

| 隔离对象 | 前置条件和验收 |
| --- | --- |
| 端口 | 在宿主锁内同时核对已登记的端口、原生集群配置以及 IPv4/IPv6 绑定。停止实例仍保留端口。两实例同时验证连接，重复端口拒绝且原实例继续服务。 |
| 目录和服务 | 根据实例 ID 派生固定数据、配置、socket 和 systemd 单元。启停核对实际 PID 与数据目录，未知目录、链接和外部集群触发拒绝。停止 A 后 B 保持服务。 |
| 账号和凭据 | 管理请求绑定实例 ID 和修订，SQL 固定走目标 socket。两个实例允许同名库及账号，使用不同密码。分别检查本实例登录成功、交叉密码拒绝、另一实例的授权和数据保持。 |
| 备份和策略 | 恢复引用由实例 ID 与备份 ID 共同识别。A 备份与清理期间 B 连续读写，B 的恢复入口拒绝 A 的备份，随后在各自实例实际恢复不同的代表性数据。 |

共享包的更新、修复、卸载和主版本迁移会影响所有使用该包的实例。首轮启用多实例后须阻止这些单实例包动作，直到有覆盖全组的计划和恢复门禁。停止、备份与恢复使用目标实例单元和私有 socket。Helper 存储宿主包身份和按实例索引的持久状态，操作回执仍按原操作 ID 核对。桌面工作区按显式选择切换目标，清除上一个实例的账号、备份选择和未提交草稿，已受理事务保留原目标供恢复。

Helper 保留已有主实例台账，并为第二实例单独写入由实例 ID 派生的 root 私有台账。读操作可以显式选择实例，写操作从结构化命令读取实例 ID，恢复与回执查询定位原操作。共享锁串行化实例写入。另一个实例有未完成事务时，新写入等待原操作处理。主实例保留原有自动备份和远程访问能力，第二实例开放本机生命周期、建库、账号、手工备份和恢复。实例新增后，共享包操作禁用。本轮没有独立删除第二实例的入口。两个 PostgreSQL 服务共用系统 postgres 身份，因此以上是连接、管理事务和数据归属的隔离，不能用作不互信租户的宿主权限边界。

## 隔离验收

一次性 Ubuntu 24.04 amd64 / systemd 容器 `relaxkonos-db07c`，标签 `relaxkonos.task=db07c`，无宿主挂载和公开端口。使用 Ubuntu 官方 PostgreSQL 16 软件包。真实 Helper 基线 29 项通过。双实例检查 15 项通过，覆盖停止后保留端口、拒绝后没有留下登记、分别核对实际端口与数据目录、同名账号可各自登录并双向拒绝错误实例密码、双向拒绝跨实例备份 ID。两个实例的备份都通过原生恢复演练，第二实例实际恢复了修改前的数据。第一实例备份后第二实例仍能认证并读取原数据。共享包拆除被拒绝。容器 systemd 重启后的 4 项检查通过，两套台账、服务、数据和备份清单保持独立。验收容器已核实归属并清理。

桌面聚焦检查 88 项通过，含实例切换请求的目标与显示的实例一致。服务端聚焦检查 103 项通过。原生脚本通过实际 Helper 调度，桌面检查独立运行。完整桌面、PAM 和真实主机联调仍待验收。

# 桌面设置 Windows 11 风格改造进度

更新日期：2026-10-05。本文追踪桌面端设置应用的增量交付；当前行为以 [设置应用](RelaxKonOS.Settings.md) 为准，领域契约和安全边界以 [设置设计](RelaxKonOS.Settings.Design.md) 为准。

## 目标与约束

采用固定分类导航、分类概览、详情卡片与面包屑，降低查找和编辑负担。沿用 Avalonia、现有主题资源、Workspace 偏好服务与宿主领域服务。每个新增设置必须有真实效果、明确范围和可靠保存反馈；只有经过验证的宿主能力才开放写入。

主题颜色、系统风格、桌面布局保持独立。界面导航不授予写权限；本机、Workspace、远程用户和远程主机的配置不得混淆。变更 API 时直接更新所有仓库内调用者，不保留兼容适配。

## 本轮路由与数据生命周期

- `relaxkonos://settings/home`：首页。
- `relaxkonos://settings/personalization`：个性化概览。
- `relaxkonos://settings/personalization/colors`：颜色与模式，包括调色板、强调色、导入导出。
- `relaxkonos://settings/personalization/style`：系统风格。
- `relaxkonos://settings/personalization/layout`：桌面布局。
- `relaxkonos://settings/personalization/background`：背景图片。
- `relaxkonos://settings/default-apps`：应用分类下的默认应用详情，保留其有效语义。

分类集合与全部页面集合分离。详情页对应父分类保持选中，面包屑展示父分类，显式上级入口返回概览；返回历史保留实际详情路由和搜索词。个性化详情页引用同一个 `PersonalizationPageViewModel`，不创建独立保存状态或重复加载偏好。移除没有实际设置页面的 `image-mirrors` 激活项；镜像源仍由 Docker 管理器负责。

## 第二阶段交互与目录规则

- 本地 XAML 使用 `SettingsSearchTarget.Id` 登记定位目标。远程目录不能提交任意控件名或激活地址；只能导航到已注册页面，并定位到视图持有的设置 ID。
- 搜索结果显示完整分类路径。定位到控件后滚动并聚焦；所属卡片高亮三秒。导航、搜索、连接变化或视图脱离会清理装饰与临时焦点属性，避免改变正常 Tab 顺序。
- 禁用控件不会因为搜索而启用；焦点落到可访问的设置分区。未显示的权限按钮等只打开所属页并说明先选择应用或查看可用性提示，不显示虚假的成功定位。
- 返回历史包含路由与搜索词，支持同页搜索；连接变化清理旧历史、缓存位置与待执行定位。延迟 UI 操作检查导航代次，避免把旧结果带到新页面。

## 第三轮：导航、保存来源与完整窗口验证

- 窄窗口使用左侧导航抽屉，包含分类图标、账号/工作区、连接地址和关于入口。打开时焦点进入抽屉；Escape 或关闭按钮恢复菜单按钮焦点，选择分类后关闭并聚焦页面标题，切到宽窗口自动收起。
- 页面标题、范围说明、反馈和设置内容共用一个滚动区域。低高度窗口不会因为固定标题占满空间而失去设置控件；详情页切换继续恢复该页面的滚动偏移。
- 修复完整窗口测试发现的搜索返回缺陷：进入搜索前先记录位置，返回搜索结果时将焦点恢复到可见搜索框，Escape 能恢复搜索前页面位置。
- `WorkspacePreferencesEditor.Schedule` 现在必须携带可空的 `PreferencesEditSource`。设置窗口传入应用 ID 与实际详情路由，其余调用者显式传 `null`；全部仓库调用者已同步更新。来源只用于内存中的反馈归属，不进入偏好 DTO 或 HTTP 载荷。
- 保存来源页显示就地状态和可用的重试/放弃动作；离开来源页后仍显示未完成或失败操作，并可直接返回修改页。已完成且无关的保存不占用其他页。来源为未知时显示通用反馈，不继承上次页面。
- 保存成功仍区分服务端接收与持久化读回，未到 durable revision 时继续显示等待状态。切换登录/Workspace 或登出清理来源信息，包括已经完成保存时留下的信息。
- 完整窗口测试使用实际 `SettingsView` 和根 VM、受控偏好服务及禁止 HTTP 的测试处理器；没有修改开发机的宿主配置、开发模式或安装应用。

### 代码与数据边界

- 设备偏好真源为当前用户本地 `RelaxKonOS/desktop-device.json`，由 `DesktopDevicePreferences` 读取、规范化和原子替换写入。不包含凭据，不进入 Workspace DTO、HTTP 载荷或同步流。
- 写入失败保留当前运行态并显示重试入口。首页固定项写入失败也显示页内反馈；原有 Workspace 保存反馈继续独立处理，不混用状态。
- 设备偏好启动时接入 `DesktopAccessibilityService`；`AppearanceService.SetAccessibility` 只覆盖渲染资源，不修改已保存的 Workspace 配色。改变通知或固定项不会重复重建桌面缩放变换。
- 新增 `relaxkonos://settings/accessibility` 和 `relaxkonos://settings/system/preferences`；后者归属“系统”分类，包含上级导航和完整分类搜索路径。所有新控件登记搜索目标。
- `DesktopNotificationService` 直接取代只写诊断的自动化通知 sink；保留不含正文的长度诊断。切换 Workspace/登出清理横幅并使旧排队通知失效，关闭桌面清理当前横幅。
- 新选项和操作文案同步提供中文、英文、日文；长标题使用可换行标签与独立开关，保留可访问名称。

### 简化后的范围

本轮交付日常可用的设备设置，不增加独立待办中心、逐字段冲突编辑器、全量宿主操作历史中心、通知中心或自动启动任意应用。通知目前覆盖自动化任务发送的通知；启动恢复目前覆盖仍在运行的服务端终端。这些明确的边界不能被描述为完整系统通知或任意应用恢复能力。原设计中的 DNS、Workspace 环境覆盖等服务端能力仍是独立设计项，不属于本次桌面界面三阶段改造。

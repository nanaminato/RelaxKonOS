# 应用内组件入口迁移计划

> 状态：迁移实施完成（实现与自动化验证），2026-10-29。桌面端 8 个组件与 Android 端 7 个应用的入口均已按本计划落地：通用启动门禁、共享依赖入口、应用内安装入口删除、组件中心归档/文件安装。实机安装/卸载与设备 UI 复查尚未执行，不得写成已完成；FRP 升级/修复/回退/卸载与 Nginx Windows 卸载受服务端组件计划能力限制，仍保留在应用内并已记录边界。
>
> 目标：**组件中心是唯一安装/更新/修复/回退/卸载入口**（桌面与 Android）。业务应用只保留组件依赖事实、业务配置、服务启停、日志与健康检查；未安装必需组件时，进入应用先给出提示并跳转组件中心，而不是在应用内安装。

## 1. 已确定的交互规则

1. 应用内不再提供组件安装、更新、修复、回退或卸载表单/命令。
2. 应用有“设置”页时，依赖入口放在设置页的“在组件中心管理依赖”；没有设置页的应用需要新增一个设置页（或在现有配置页内增加“组件依赖”区），不能只留一个常驻顶部横幅。编辑器型应用（Project Editor）用“工具 → 组件依赖”打开同一区域。
3. 进入应用时检查该应用的必需组件：
   - 未安装 → 提示“需要组件 X”，提供“前往组件中心”与“取消”；取消不打开应用。
   - 待恢复/执行中 → 提示原因并提供“任务与恢复”，不启动业务操作。
   - 外部安装 → 不自动接管；按领域能力决定只读打开或提示。
   - 已安装但服务停止/故障 → 仍可打开业务控制台（状态不等于缺失）。
   - 宿主平台不提供该组件 → 视为“无需组件”，应用照常打开，不把它当作未安装。
4. 组件中心接受 `appId`、`componentId` 与目标页，定位但不自动安装；安装完成后应用重新检查依赖。
5. 权限、提权、幂等、恢复台账全部沿用组件中心与安装台账，应用不新增第二条安装通道。

### 桌面端待办

1. **实机验收**：在真实 Linux/Windows 宿主上逐应用验证“组件缺失时应用不打开且提示可跳转”“安装后返回应用可打开”“应用内不再出现组件安装/版本选择”。
2. **回归**：`--component-installs-only`、`--component-center-only`、`--readiness-only` 与真实进程检查持续通过；本轮已运行通过，但仍属本地/模拟证据。
3. **权限提示**：新增的 `server.components.read` 在首次进入这些应用时会请求一次授权；拒绝时应用不打开并提示无权限。需要在实机上确认提示文案与可恢复路径。
4. 组件中心为 nginx/Docker/Squid/Samba/Git/frpc/frps 的安装能力仍受各领域事务成熟度限制，迁移入口不等于这些生命周期已全部完成。

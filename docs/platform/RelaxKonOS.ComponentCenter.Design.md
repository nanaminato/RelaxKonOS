# RelaxKonOS 组件中心设计

> 状态：桌面端首批接入实施中；已新增组件中心并迁入 sing-box 生命周期入口，完整 CC 验收尚未完成。
> 更新：2026-10-24。
> 定位：统一管理宿主组件的安装、版本、更新、修复、回退、卸载与发布源。借鉴 Windows 功能的树形选择，但提供完整生命周期管理。

## 1. 职责与文档边界

组件中心是系统内置管理入口，不是新的安装后端。原 TaskOrchestration 中的 Component Installer / Workloads 产品设计由本文拥有。

- 本文拥有组件目录、应用可用性、来源选择、生命周期交互、批量变更和交付跟踪。
- [TaskOrchestration](RelaxKonOS.TaskOrchestration.Design.md) 拥有冻结计划、审批、执行、恢复和审计。
- [ManagedRuntimes](RelaxKonOS.ManagedRuntimes.Design.md) 拥有版本、信任、所有权和领域生命周期事务。
- [InstallationManagement](RelaxKonOS.InstallationManagement.Design.md) 继续拥有 RelaxKonOS 自身部署与维护，组件中心仅聚合其入口和状态。
- Android 交互与实施文档由 [Android 文档目录](../../Client/RelaxKonOS.Client.Android/docs/) 拥有。

集中的是产品入口，领域安装器、Helper 验证和原生服务适配器继续由各领域维护。本文不将任何计划中的来源或平台能力标记为已实现。

## 2. 应用、组件与工作负载

三者分别建模：

| 对象 | 示例 | 生命周期 |
| --- | --- | --- |
| 内置应用 | 代理服务端、Web Server、Docker 管理器 | UI 随 RelaxKonOS 发布；宿主组件缺失不删除客户端代码 |
| 宿主组件 | sing-box、Nginx、Docker Engine | 独立版本、安装所有权、来源与运行状态 |
| 工作负载 | 代理服务器基础环境 | 引用组件、功能和可选业务动作；本身不伪装成独立软件包 |

应用与组件是多对多关系。组件分为必需和可选依赖；安装可选组件只解锁对应功能。证书申请、容器镜像更新和业务配置发布不是应用本身的安装更新。没有独立组件的应用不增加虚假的安装状态。

组件描述至少包含 componentId、领域 action/runtime ID、分类、必需/可选依赖、冲突、应用关联、平台约束及展示元数据。描述不能包含任意 shell、可执行路径或安装命令。版本和可执行能力由宿主可信适配器返回，UI manifest 不授予权限。

## 3. 应用显示与打开策略

默认采用“应用可发现，未就绪时引导安装”：有权限且平台支持的应用仍可在应用列表找到，缺失必需组件时标注“需要安装组件”。点击后显示统一对话框：

```text
代理服务端需要 sing-box
当前服务器尚未安装所需组件。
[取消] [前往组件中心]
```

跳转携带 hostId、appId、componentId/工作负载 ID 和受控返回目标；只定位与预选，不自动安装或授权。安装成功后提供“打开代理服务端”，重新检查当前宿主和依赖状态。若应用支持独立的离线编辑功能，可提供明确的受限打开入口，由应用声明能力。

允许用户选择“仅显示已就绪应用”，过滤可启动入口；组件中心仍列出可安装组件。快捷方式、搜索、收藏和深链接即使被过滤也走统一可用性检查，不能报“应用不存在”。组件中心、设置和恢复入口不得因该过滤隐藏。

未安装、停止、故障、未知、外部安装、不支持、无权限分别显示：服务停止不等于未安装；查询失败不得触发安装；待恢复提供恢复入口；平台不支持不给安装按钮；外部安装按领域能力决定仅检测或可管理，不自动接管。权限不足时显示申请管理员处理的原因，不展示无权访问的宿主细节。

状态按 hostId 和实际安装身份缓存并订阅/刷新，切换服务器、断线重连和卸载后重新核对，不能沿用另一服务器的应用可用性。

## 4. 信息架构与页面

组件中心为单窗口系统应用，顶部明确当前目标服务器、平台、架构和连接状态。主要页面为“全部组件”“已安装”“可更新”“工作负载”“任务与恢复”“发布源”。

主体左侧为搜索、分类及可展开的组件/功能树，右侧为详情。树的三态勾选表示功能组的选择聚合；是否已安装、是否运行、版本和故障使用独立状态标记，不能用一个勾选框同时表达。

详情展示：组件用途、关联应用、所有权、当前实测版本、目标版本、来源、平台、安装模式、健康、开机启动、数据位置摘要、依赖、版本支持与验证证据，以及最近操作。更新、修复、回退和卸载使用明确命名的动作，不通过反复勾选猜测意图。

页面底部是“待应用变更”摘要和“预览变更”按钮。选择和取消选择只编辑本地草稿，不执行安装、卸载或信任变更。关闭有草稿的窗口提示保留或放弃；草稿不是已批准计划，重新打开后重新规划。

## 5. 操作流程

| 操作 | 交互与约束 |
| --- | --- |
| 安装 | 选择组件/功能、可信来源、明确版本及必要选项，解析依赖并预览 |
| 更新 | 比较当前与目标版本、配置能力、数据兼容和重启影响；默认仅列当前支持的稳定版本 |
| 修复 | 验证或重新安装同版本，展示会恢复的文件和服务；不能报告为升级 |
| 回退 | 仅列可恢复且当前信任允许的版本，展示配置/数据限制；不保证所有包管理器可回退 |
| 卸载 | 默认保留业务数据，预览程序、服务、自有规则及关联应用影响；删除数据独立确认 |
| 恢复 | 对已有领域事务重试、紧急停止或关账；不以重新安装掩盖结果未知 |

统一流程为“编辑变更 → 解析依赖和来源 → 冻结计划 → 预览 → 审批 → 执行 → 结果/恢复”。执行中的任务可关闭窗口，状态和取消能力由宿主提供。完成页列出成功、no-op、失败、跳过、补偿和保留资源，支持回到关联应用。

更新不默认切换来源或安装模式。切换来源必须显示新发布者、信任和制品身份；不允许的模式转换提示专用流程。批量更新只包含用户明确选择的组件，不自动更新所有发现的新版本。

## 6. 版本与来源选择

“发布源”与“文件从哪里传来”是两个维度，必须分别展示。上传文件、输入 URL 或计算出一个 SHA-256 都不等于可信发布者。

| 输入方式 | 处理规则 |
| --- | --- |
| 已登记网络发布源 | 选择 sourceId、目录中的 releaseId；依赖签名、修订、撤销和平台规则验证，不提交任意下载命令 |
| 服务器文件 | 通过文件选择获得 actor/host 绑定的短期文件引用；宿主在保护暂存区读取并验证，UI 不把任意路径交给 Helper 执行 |
| 本机文件 | 流式上传到目标服务器保护暂存区，限制大小与有效期，返回文件引用；本机路径不被误认为服务器路径 |
| apt 等系统包源 | 使用明确发行版、仓库身份、签名和包集合的领域适配器，冻结精确版本与依赖影响；不运行用户输入的 apt 命令 |
| 镜像/离线介质 | 更换传输位置，仍匹配已受信任的制品身份；镜像不能重定义版本摘要 |

文件导入只能选择该组件支持的包格式，并匹配可信目录或独立签名元数据、平台、长度和完整文件清单。缺少可信依据时阻止安装并说明原因；第一版不提供“仍然运行未知程序”。新增来源和密钥是独立的宿主信任管理操作，先审查并提交，再重新生成安装计划，不能在同一未经确认的导入中静默授信。

网络源新增遵循 SSRF、重定向和凭据隔离规则；普通输入网址不能成为 Helper 信任依据。apt 适配器需声明 package-managed 与外部资源所有权、全局包管理器锁、模拟/解析结果和提交前复核；仓库变化或额外依赖扩大影响时重新计划。禁止全局 purge/autoremove。尚无适配器的平台或组件显示“该来源暂不支持”。

目录刷新失败保留缓存并标明过期，不显示“已是最新版”。版本列表分别显示来源可信度、目标支持、配置能力和验证证据。默认安装版本由可信目录及明确策略选择，规划时冻结 releaseId，执行时不能再解析 latest。

## 7. 依赖与卸载影响

工作负载展开为具体组件和功能。选择父节点可以勾选推荐子项，但必需项、可选项及原因必须可见。共享依赖去重；互斥版本或安装模式不能靠最后一个选择覆盖。

卸载前读取真实依赖、业务配置与运行中消费者，列出受影响应用和服务。默认阻止破坏仍有消费者的必需依赖；若领域支持级联停止/移除，必须将其作为明确步骤单独预览审批。取消某个工作负载不默认删除它曾引用的共享组件。自动带入的新增依赖与用户原有资源分别记录，不因一次后续失败就卸载原有组件。

组件卸载不删除应用入口代码；应用进入依赖未就绪状态。默认保留草稿、业务数据及必要保护密钥，删除数据须遵循领域规范并列出不可恢复项、关联秘密和备份影响。停服、禁用开机启动、卸载程序和删除数据是不同意图。

## 8. 各应用保留的职责

各应用移除独立生命周期管理 UI，保留简短依赖摘要及“在组件中心管理”入口，可深链到指定组件、版本、更新、恢复或来源页。业务配置、配置发布、服务启停、业务日志和健康检查继续留在应用。

例如代理服务端管理 inbound、principal、credential 和发布；组件中心管理 sing-box 程序版本。配置回滚仍属于代理领域，程序版本回退属于组件生命周期，预览说明它们的关联。Docker 镜像和 Compose 业务管理也不移入组件中心。

实施时直接替换各应用旧 UI 和调用入口，更新全部调用者、测试与说明，不保留两套规范或旧路由兼容层。领域 API 可以继续作为当前统一服务被组件中心调用；“移除应用安装页”不等于删除成熟领域事务。

## 9. 自身组件维护

Server、Guardian、PrivilegedHelper 单独分组，复用服务器中心既有部署、升级和修复流程。组件中心不能假定能够用正在被替换的 Server Executor 完成自身升级。连接将中断时，交由现有宿主部署通道及外部维护协调者执行，并显示重新连接和验收状态。

保持各安装模式的实际能力：不支持的 Guardian、系统权限或服务宿主不显示为可安装。当前连接故障不能被解释为维护成功，恢复入口应在服务器中心仍可达。

### 桌面首批接入（2026-10-24）

新增内置应用 `relaxkonos.component-center`（单窗口）。当前目录仅开放 sing-box；右侧复用既有可信来源、版本选择、宿主状态、安装/更新/修复/回退/卸载及恢复面板。代理服务端移除运行时页面与卸载按钮，保留业务配置、配置回滚和服务启停，以及组件中心跳转。读取到明确未安装状态时提示前往组件中心；状态读取失败或不支持不按缺失组件处理。

每次版本变更先取得领域冻结计划，再确认服务器、操作、版本、来源及数据保留意图；缺少确认宿主或用户拒绝均不提交安装台账。会话更换会使旧窗口失效。此阶段仍使用领域 RuntimeChangePlan，未实现 TaskPlan 批量编排、跨进程草稿持久化、全应用依赖目录、来源信任编辑、离线文件导入或 apt 适配；不能据此宣称 CC-01～CC-03 全部完成或 Windows 生命周期已实测。

首批入口接入检查：`dotnet build Client/RelaxKonOS.Client.Desktop/RelaxKonOS.Client.Desktop.csproj --no-restore -m:1`；`dotnet build Tests/Client/RelaxKonOS.Installation.Tests/RelaxKonOS.Installation.Tests.csproj --no-restore -m:1` 后运行 `dotnet run --project Tests/Client/RelaxKonOS.Installation.Tests/RelaxKonOS.Installation.Tests.csproj --no-build --no-restore`，46 项通过。新增检查覆盖冻结计划缺少审批宿主、用户拒绝、确认目标版本，以及删除数据确认与冻结计划确认分别执行。测试使用模拟 HTTP，不替代真实安装、主题与交互验收。

### 桌面草稿与受控导航（2026-10-24）

组件元数据与工作负载分别建模在 `ComponentCatalog`，当前只开放首批 sing-box，不把应用清单当作执行权限。组件中心中的版本动作和卸载动作只暂存 `ComponentChangeDraft`；底部预览入口才重读安装/恢复、来源和目录，再规划、预览并审批。草稿记录精确组件、宿主安装身份、来源、releaseId、变更意图与数据保留选项，不保存冻结计划、提权凭据或审批。实际宿主、安装身份或操作种类发生变化时拒绝旧意图。版本冲突不以最后一次选择覆盖，用户先移除旧变更。

草稿按稳定服务器连接身份和用户 ID 保存在桌面进程内。关闭时明确选择保留或放弃；关闭确认框本身默认保留。再次打开只恢复意图，重新预览才请求宿主计划；退出桌面进程后的持久化尚未实施。取消工作负载或移除草稿不会触发组件卸载。

受控链接为 `relaxkonos://components/sing-box?hostId=…&appId=…`，可携带已登记的 `workloadId`。导航中的 hostId 是当前认证连接的稳定服务器身份（不是隧道临时端口）；领域草稿和计划另绑定宿主返回的实际 HostId/InstallationId。路径、查询键、重复键、关联应用和工作负载均检查目录；拒绝任意动作参数和返回应用，跨服务器链接只提示连接目标服务器，不切换宿主、不选择变更、不安装或授权。代理服务端跳转已使用此路由。

已有受管安装优先匹配其 active release 所属来源，无法匹配时要求明确选择，不默认换源。安装观察失败即清空可执行状态，保留错误，不将旧观察当成新安装依据。

布局专项：`dotnet build Tests/Client/RelaxKonOS.WindowPreviews.Tests/RelaxKonOS.WindowPreviews.Tests.csproj --no-restore -m:1` 后运行 `dotnet run --project Tests/Client/RelaxKonOS.WindowPreviews.Tests/RelaxKonOS.WindowPreviews.Tests.csproj --no-build --no-restore -- --component-center-only`，中文/英文/日文 × 明/暗共六组未知安装状态与草稿布局通过；检查搜索、未知状态禁止执行、草稿栏不越界及可见文案解析。已查看中文浅色、英文深色实际渲染图并修正未知所有权文案键。此专项不证明所有安装/恢复状态、窄窗口、树形半选或真实键盘导航已经验收。

### 公共应用启动检查（2026-10-24）

桌面运行时通过 Host 提供的 `IApplicationLaunchGuard` 在创建窗口或复用已有单窗口之前检查依赖。普通启动、Shell/外部 URI、文件打开、文本回退及终端入口均经过同一门槛；检查中返回 `AvailabilityCheckPending`，调用方按已受理而非已打开处理。重复启动共用一个检查并保留最后的导航请求，检查期间移除的应用不会延迟打开。既有窗口不会绕过检查自动恢复。

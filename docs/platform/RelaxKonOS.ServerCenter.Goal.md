# RelaxKonOS 服务器中心：桌面与手机端部署体验（Goal 执行文档）

> 状态：设计完成，待实施。本文描述目标行为，不代表客户端已具备远程安装能力。
>
> 范围：桌面客户端、Android 手机客户端、Windows Server / Linux System Mode / Linux User Mode 服务端，以及发布与部署工具。iOS 客户端不在当前代码基线中；实现 iOS 时须遵循同一交互与安全契约。
>
> 关联：[部署说明](../../deployment/README.md)、[User Mode Goal](../services/RelaxKonOS.UserModeServer.Goal.md)、[登录](./RelaxKonOS.Login.md)、[安全](./RelaxKonOS.Security.md)、[端口转发](../applications/RelaxKonOS.PortForwarding.md)。

## 1. Goal

用户只安装 RelaxKonOS 客户端，即可从桌面或手机完成服务端的**发现、首次安装、连接、更新、修复、卸载和结果确认**，不需要另装 SSH 客户端、终端或文件传输工具。产品入口称为 **「服务器中心」**：同一张服务器卡片随状态变化提供适当动作，用户无需先理解“维护模式”。

安装前没有 RelaxKonOS Server，因此首次部署必须从客户端与宿主机已有的管理入口建立信任。远程路径使用**客户端内置 SSH/SFTP 能力**；已登录后的服务端 API 只提供版本、健康及会话信息，不承担自身停机、替换或卸载的最终执行。安装、更新、卸载的控制通道始终独立于即将重启或删除的 Server 进程。

成功的定义不只是脚本退出码为 0：客户端须能确认目标主机身份、包来源与架构、部署结果、健康状态及最终连接方式，并在断线后恢复可理解的操作结果。

## 3. 产品结构与入口

### 3.1 服务器卡片是唯一主线

每台服务器在客户端本地拥有一个 `ServerProfile`，包含显示名称、SSH 目标、已确认的 SSH 主机密钥、可选 API 地址、部署模式及最近一次已验证状态。资料属于设备本地；不把 SSH 凭据、主机指纹或当前操作日志同步到服务端 Workspace。一个主机的不同部署实例须通过安装标识与规范路径区分，不能只靠相同 IP 合并。

| 已验证状态 | 卡片主操作 | 次级操作 |
|---|---|---|
| 未添加 | 添加服务器 | 扫描局域网仅作地址建议 |
| 可达但未安装 | 安装 RelaxKonOS | 查看主机与权限预检 |
| 已安装且健康 | 连接桌面 / 打开手机工作区 | 更新、检查状态、卸载 |
| 有可用更新 | 更新 | 继续使用、查看变更 |
| 服务异常 | 修复或恢复上次版本 | 查看阶段、诊断、卸载 |
| 操作进行中 | 查看进度 | 安全阶段允许取消 |
| SSH 不可达 | 重试连接 | 查看上次结果与连接资料 |

状态必须标注来源与时间，例如“通过 SSH 于 14:32 验证”。离线缓存不可显示为实时健康。API 可达、SSH 可达、服务已安装是三个独立事实；不能仅因 `/healthz` 无响应就建议重新安装。

### 3.2 桌面端

- 登录前：将现有服务器地址输入升级为「服务器中心」的服务器列表，保留手动输入地址作为高级入口。空列表首屏提供「添加服务器」和简短说明。
- 服务器详情：顶部显示名称、宿主系统、安装模式、版本与状态；主操作固定在标题区。下方按「概览 / 操作记录 / 连接设置」组织。安装与更新走同一个侧边步骤面板，详情页在后台保留上下文。
- 已登录后：连接栏或设置的「当前服务器」可返回同一详情页；更新和卸载前明确告知当前会话会中断。操作期间自动保存可保存的客户端状态，结束后重新探测、再登录。
- 桌面窗口可呈现更完整的预检清单和阶段日志；主路径只露出需要用户决定的字段，诊断日志折叠。

### 3.3 手机端（首期 Android）

- 首屏为服务器卡片列表；未安装、已安装、异常共用同一视觉语言。卡片点入后使用全屏步骤页，不在窄屏堆叠桌面表格。
- 首次添加只问地址、SSH 用户及认证方式；主机指纹在单独的信任确认页展示。安装方式与网络方式使用带解释的选择卡；高级选项折叠。
- 进度页展示当前阶段、完成的阶段和下一步；离开页面后操作继续，重新进入时从远端操作 ID 恢复。系统通知仅用于用户主动开始的长操作及最终结果。
- 触控上的卸载为两步确认：先选保留或删除数据，再输入服务器名称确认；绝不用滑动误触直接执行。手机端离线时清楚标记最后一次检查时间。
- Android 不依赖外部 SSH App 或用户的 Shell；SSH/SFTP、密钥存储与隧道由客户端实现。未来 iOS 复用协议和文案语义，采用系统安全存储与平台后台执行限制对应实现。

### 3.4 统一操作步骤

```text
选择服务器 → 验证主机身份 → SSH 认证 → 宿主/权限预检
  → 选择操作与来源 → 核对影响 → 执行与可恢复进度
  → SSH 侧核验服务/文件/健康 → 给出连接或恢复动作
```

已信任的主机再次操作时只在主机密钥变化、身份或权限变化时重新确认。SSH 密码可由用户在本次操作输入；保存密钥须用户明确选择并交给设备安全存储。RelaxKonOS 登录密码与 SSH/sudo/Windows 管理员凭据分别标注用途，不能暗中互用。

### 3.5 界面层次示意

桌面端用稳定的列表与详情布局，手机端把同样的信息压缩成一张主卡和逐页任务。两端都把“下一步”放在最显眼的位置，把远端命令与原始日志放入诊断区。

```text
桌面                                  手机
┌ 服务器中心 ────────────────┐          ┌ 服务器 ───────────┐
│ 我的服务器      + 添加     │          │ + 添加服务器      │
│ ┌ 家里的 NAS  健康 ─────┐ │          │ ┌ 家里的 NAS     ┐ │
│ │ v0.2.0  Linux System  │ │          │ │ 健康 · v0.2.0  │ │
│ │ [连接]  更新可用       │ │          │ │ [打开工作区]   │ │
│ └────────────────────────┘ │          │ └───────────────┘ │
│ 概览  操作记录  连接设置   │          │ 最近操作  详情    │
└────────────────────────────┘          └───────────────────┘

安装步骤：主机 → 信任 → 预检 → 选项 → 确认 → 进度 → 连接
```

色彩只辅助表达状态；每个状态同时有文字与图标。破坏性操作收在详情页，不能与「连接」按钮并排成为同级主操作。进度中始终显示当前阶段、主机名称和可以安全离开的说明。

## 4. 三条完整任务路径

### 4.1 首次安装

1. **找到主机**：输入域名/IP 和 SSH 端口，或选择发现结果。发现结果不得自动信任；DNS 名称、IP、端口、指纹在核对页明确展示。
2. **建立信任**：内置 SSH 验证服务器主机密钥。首次连接展示指纹并要求用户核对；已保存的指纹变化时阻断部署，提供明确的人工核对与更新入口。禁止静默接受未知或变化的密钥。
3. **权限预检**：读取 OS、架构、磁盘、依赖、已有安装标识、服务管理器、可用端口、SSH 会话的实际权限。Linux System Mode 需要 root 或可完成受控 sudo 提权；User Mode 只用当前 UID；Windows Server 需要可用于服务安装的已提升管理员 SSH 会话。不能获得权限时在执行前停止并说明宿主侧需要完成的前置条件，不能假装远端 UAC 会出现在手机上。
4. **选部署方式**：Linux 默认推荐 System Mode；无 sudo 时建议 User Mode。Windows 使用 System Mode。展示默认仅 loopback 的网络选项；需要从其他设备直连时必须配置可信的 TLS 入口，或者使用客户端内置 SSH 隧道。不得把局域网 HTTP 作为无说明的默认选项。
5. **选来源与确认**：默认官方稳定版；离线包可由客户端本地选取并经 SFTP 上传；指定 URL 作为高级选项。确认页列出版本、包大小、目标路径、将创建的服务与网络监听、数据保留位置和所需权限。
6. **执行**：客户端在远端受控暂存目录写入经过验证的包和部署启动器，调用固定的安装动作。初次安装无 Server API；进度来自 SSH 控制通道和远端操作记录。
7. **验收**：校验 install-state 与服务状态，经 SSH 访问 `127.0.0.1` 的 `/healthz`，读取实际版本与监听信息。若为 loopback，则自动建立内置 SSH 隧道并生成连接资料；随后引导 RelaxKonOS 账号登录。SSH 认证成功不等于 RelaxKonOS 登录成功。

若目标没有 SSH 服务且客户端也不在目标机上，远程首次安装无法开始。桌面端在目标机本机运行时可提供本机提升安装路径；手机端显示一次性的宿主侧 SSH 启用说明，并在满足前置条件后继续同一流程。

### 4.2 更新与修复

1. 通过 SSH 取得安装标识、模式、当前版本、磁盘和服务状态；签名发布目录给出可选目标版本。先显示变更、兼容性与预计服务中断。
2. 下载或上传目标包并完成签名、完整性、RID、manifest 和空间校验；创建安装与数据备份/快照点。用户可选择保留或跳过额外备份，但不能跳过部署引擎要求的恢复点。
3. 获取单主机独占操作锁，停止服务，按平台执行固定升级动作。Server API 断开是预期现象，SSH 操作 ID 和日志仍可查询。
4. 重启后在 SSH 侧检查服务与 loopback 健康，并核对报告版本。失败时自动执行可安全回滚的程序版本切换；数据库迁移若不可逆，必须在开始前阻断或有经过验证的数据恢复方案，不能只回滚二进制。
5. 更新成功后重建隧道/会话并提示重新登录。修复仅重放已验证的当前版本与配置，不任意修改宿主资源；“恢复上次版本”作为独立操作显示其数据兼容性。

### 4.3 卸载

1. 在 SSH 侧识别**由 RelaxKonOS 管理的安装**，读取实际安装根和数据根，不接受客户端随意提供的删除路径。列出将停止的服务、将删除的程序文件与可保留的数据。
2. 默认「卸载程序并保留数据」。选择「同时删除数据」时，显示数据库、密钥、配置及日志的不可恢复范围，提供导出备份入口，并要求输入服务器名称二次确认。
3. 部署引擎先验证安装标识、路径所有权与删除范围，再停止服务、移除服务注册和程序文件。删除数据须由同一受控引擎完成，且仅限安装清单记载的根。当前 User Mode 卸载逻辑必须增加保留数据路径，再接入此流程。
4. 由于 Server 已不存在，完成证明由 SSH 侧服务状态和安装清单检查给出；客户端记录本地回执。保留数据时卡片显示「已卸载 · 数据已保留」，可从该状态重新安装；删除数据时移除连接凭据和隧道资料前提示用户。

## 5. 组件与职责

```text
桌面 Avalonia UI ─┐
                  ├─ ServerCenter 领域状态机 / 操作 DTO / 错误码
Android Compose UI ┘                  │
                          客户端内置 SSH/SFTP 传输
                                      │
                    远端受控部署启动器 + 操作日志/锁
                                      │
            现有 Windows / Linux System / Linux User 部署引擎
                                      │
                         OS 服务管理 + loopback 健康检查
```

- **共享契约**：定义操作种类、预检能力、阶段事件、结果及稳定错误码，明确协议版本。C# 与 Kotlin 可由一份 schema 生成或分别实现并运行契约测试；不要求 Android 依赖 .NET UI 工程。
- **客户端传输**：封装 SSH 主机密钥验证、密码/密钥认证、交互式 sudo 所需 PTY、SFTP、loopback 转发、重连与取消。选用跨桌面平台和 Android 可维护的库或平台实现，最终能力必须以真实平台验证；不调用系统 `ssh/scp/sftp` 命令作为必需路径。
- **远端启动器**：执行有限枚举动作 `probe / install / upgrade / repair / uninstall / status / rollback`，参数采用结构化 JSON 与固定枚举，不接受任意命令、脚本路径、服务名或删除路径。启动器校验请求、取得锁、写入仅目标账号可读的操作记录，调用已有部署引擎并输出机器可读事件。
- **部署引擎**：System Mode Windows/Linux 与 Linux User Mode 各自负责原子替换、服务管理、安装清单和数据策略。SSH 层只传输并启动，不能成为第二套部署实现。
- **Server API**：已安装时可提供只读版本/能力信息，不能作为自更新或自卸载的唯一执行者。所有最终核验走独立 SSH 通道。

建议的操作事件字段：`schemaVersion`、`operationId`、`installationId`、`kind`、`phase`、`state`、`sequence`、`timestampUtc`、`progress`、`problemCode`、`safeMessage`、`result`。阶段顺序单调，重连后按 `operationId + sequence` 补取。原始 stdout/stderr 仅作为受限诊断附件，默认不展示或上传；不得包含密码、token、私钥和完整环境变量。

## 6. 安全与失败边界

1. **发布信任**：官方目录和包使用离线发布密钥签名，客户端内置可信公钥并验证签名、包清单、各文件摘要及目标 RID。HTTPS 与 SHA-256 继续用于传输完整性，但不足以单独证明发布者身份。离线包也必须签名；开发构建只能在显式开发配置中允许自签源。
2. **SSH 信任**：按主机+端口保存已确认的主机密钥；主机密钥变更阻断所有写操作。隧道连接也使用同一信任决定。不得以 `StrictHostKeyChecking=no` 等配置绕过。
3. **最小权限**：User Mode 始终使用当前 UID；System Mode 仅在确有系统服务/受保护路径动作时请求提升。Linux sudo 密码仅送入当前 SSH 交互会话，不写命令行、日志或磁盘；Windows 必须验证远端令牌确有服务管理权限。权限不足直接失败并显示修复条件。
4. **有限执行面**：UI 不提供“自定义远程命令”作为部署选项；SFTP 暂存目录私有，拒绝符号链接、路径穿越和不受信任的包布局。远端启动器及安装清单共同限定删除范围。无论客户端传什么路径，部署引擎都必须自行复核。
5. **断线与取消**：网络断开不推断操作失败；重连后查询持久记录与宿主实际状态。取消只在下载、上传、预检等安全点生效；停服务至回滚完成的临界阶段显示“正在完成安全恢复”，不强杀进程。客户端退出后操作应继续并可恢复。
6. **并发与幂等**：每台安装实例同一时刻只有一个写操作；重复提交相同 `operationId` 返回既有结果，冲突返回明确错误。安装成功但响应丢失时再次探测不得创建第二份安装。
7. **数据与隐私**：SSH 凭据只在设备系统安全存储中按用户选择保存；服务端登录凭据与 SSH 凭据分开。操作日志脱敏、按期限清理；卸载删除数据后不再依赖远端日志证明完成。
8. **客户端能力缺口**：手机后台执行被系统中断时通过远端持久操作恢复；不能承诺进程一直在前台。若宿主防火墙、SSH 或权限配置导致无法远程操作，展示可执行的宿主侧前置步骤，不把部分完成伪装为成功。

## 7. 分阶段执行

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| G0 部署契约 | 固定安装标识、操作 schema、错误码、签名发布规范、保留数据策略及三个模式的能力矩阵。 | 契约测试覆盖合法/错误 manifest、路径、并发与中断。 |
| G1 部署引擎 | 现有脚本提供非交互机器接口、原子更新/回滚、持久操作记录、受控卸载；修正 User Mode 默认卸载数据语义。 | CLI 独立完成安装/更新/卸载与断线后状态查询。 |
| G2 共享连接 | 桌面和 Android 分别接入内置 SSH/SFTP、主机密钥固定、设备安全存储、loopback 隧道；统一契约测试。 | 在全新客户端设备上不安装外部 SSH 工具也能完成预检和文件上传。 |
| G3 桌面体验 | 服务器中心列表/详情/步骤面板与现有登录/连接栏整合，三条任务路径接通。 | Windows、Linux 桌面客户端对支持的宿主模式完成端到端验收。 |
| G4 Android 体验 | 新建可发布的 Android 客户端源码、卡片列表、全屏步骤、进度恢复与通知；接通同一部署契约。 | Android 真机完成三条任务路径，无外部 SSH App。 |
| G5 发布验收 | 签名稳定版/离线包、跨平台故障注入、文档和多语言文案。 | 所有验收项通过，并更新中英日用户文档及部署说明。 |

仓库处于首次正式发布前。若调整内置 API、wire 契约或包 manifest，直接采用新接口，并在同一变更更新所有仓内调用者、测试、示例和文档；不增加旧格式双解析或兼容别名。

## 8. 验收场景

- [ ] 新桌面客户端和 Android 真机在未安装外部 SSH 工具时，均能通过内置连接首次安装 Linux System、Linux User 和 Windows Server；每种模式都核对架构、权限、版本、服务与健康。Windows 远端缺少已提升管理员令牌时在预检阻断。
- [ ] 首次连接、主机密钥变化、认证失败、SSH 不可达、sudo 拒绝、磁盘不足、端口占用、错误架构、包签名错误均在修改宿主前给出明确状态和下一步。
- [ ] 默认 loopback 安装后桌面与手机均能通过内置隧道连接；RelaxKonOS 登录单独完成；隧道不会把服务公开到非 loopback 地址。
- [ ] 更新期间 Server API 断开、客户端退出、手机切后台或网络断开后，重新进入可以恢复同一操作的阶段和最终结果；健康失败时按策略回滚或明确停在可修复状态。
- [ ] 卸载默认保留数据，重新安装能识别并复用；显式删除数据需二次确认且只删除清单中的目录。卸载后的完成状态通过 SSH 验证，不依赖已消失的 Server API。
- [ ] 两个客户端同时操作同一安装时只有一个获得写锁；重复请求不会重复安装或重复删除。日志和本地存储中没有明文密码、token、私钥。
- [ ] 桌面端键盘导航、屏幕阅读器标注和手机端触控/大字号布局可用；中文、英文、日文的操作、风险和错误文案语义一致。

## 9. 实施前需锁定的产品决策

1. 官方发布签名的密钥轮换与撤销机制，以及开发包的显式信任入口。
2. System Mode 的数据快照格式、数据库不可逆迁移的阻断规则和可恢复范围。
3. 手机端首发是否只发布 Android；本 Goal 以当前仓库可实现的 Android 为交付对象，iOS 使用相同协议时另做平台验收。

这些决策不妨碍先实现 G0 的契约与原型，但 G1/G5 完成前必须固定并在发布文档中说明。

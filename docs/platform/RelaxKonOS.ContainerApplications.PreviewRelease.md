# 容器应用平台首版预览发布评审

状态为实机矩阵通过、待发布确认。建议先面向受控试用环境交付，平台限定 Linux x64、同机 Unix socket Docker Engine、随 Server 一起交付的官方目录，以及默认回环的 Web 入口。双服务验收开关 `ApplicationDeployments:EnableManagedComposePreview` 默认关闭。Server 仅在支持该范围时声明安装能力。

## 开放路径

| 范围 | 预览开放路径 |
| --- | --- |
| 单服务有状态应用 | 目录安装、实际业务读写、清单声明的精确兼容升级、保留数据卸载和从原记录重装。 |
| Web＋数据库 | 结构化拓扑预览、目录安装、服务身份和网络及卷核验、Web 就绪后激活、按原操作恢复。数据库留在项目网络。 |
| 权限和归属 | 观察者读取，控制者安装。Docker 管理器对受管项目和卷执行归属保护，受管容器环境值和原始日志不从管理器交付。 |
| 目录更新 | 同一套 Server 和客户端可加载新增清单。Server 启动时读取目录，客户端重连后从 Server 获取当前包、字段及能力。 |

目前证据来自独立 WSL2 Ubuntu x64、专用 Docker Engine 29.1.3 和 Compose 2.40.3。实际业务验证使用 ntfy 2.37.0、2.37.2 和 Web＋PostgreSQL 夹具。新增包用固定 Server 和桌面程序集在真实 PAM 登录与实际 API 上验证。桌面表单通过无头 Avalonia 驱动。第 7.1 节强制终止复验用修正后的单独 Server 构建，在同一 Engine 上执行原回执和缺失副本两条路径。验收制品、操作 ID、脱敏日志及复验记录见[平台进度](RelaxKonOS.ContainerApplications.Progress.md)。

验收夹具通过专用回环 Registry 交付。正式候选目录应从已评审的镜像生成不可变引用，并作为 Server 发布内容一并登记。确认候选镜像仓库和包名单后，按候选摘要重跑矩阵。试用包清单只登记已通过的能力和兼容边。

## 已知限制

- 双服务只开放已验收的安装和恢复路径。启动、停止、保留重装、升级、回退和永久删除各自需要后续验收。
- 自动恢复只采用可核实的原回执和资源观测。底层回执缺失或资源核验失败会保留待核验状态，并拦截该实例的新写入。
- 使用环境变量注入时，宿主 Docker 管理权限可以读取运行中容器的值。平台通过受保护秘密版本保存输入，普通客户端检查和诊断输出遮蔽受管值。
- 共享数据库、跨实例依赖、数据迁移、备份恢复和独立签名目录均在后续范围。首版仅对声明过的单服务兼容升级承诺保留原数据。
- 测试使用专用回环网络。对外访问、反向代理、其他 Linux 发行版组合及其他客户端需取得对应证据后再列为支持。

## 运维与故障恢复

发布前先核对 Docker Unix socket 指向专用本地 Engine，记录 Engine ID、架构、Compose 版本、包摘要及空闲回环端口。部署时使用同一套 Server 制品与匹配的官方目录。开启验收开关后重新启动 Server，并让客户端重连以刷新能力。每次变更保留应用操作 ID、目标修订、底层 Docker 操作 ID、项目和卷名。

| 现象 | 处理 |
| --- | --- |
| 登录后没有双服务安装入口 | 核对 Linux x64、Docker 模块、验收开关以及登录描述符。用目录拓扑预览检查 Compose 解析和端口。 |
| 请求已发送但客户端未收到回执 | 使用原请求和原幂等键重试。随后按返回的原操作 ID 继续观察。 |
| Server 在派发后退出 | 用同一数据目录、Data Protection 密钥、官方目录和 Engine 重启。应用账本按原键查 Docker 账本，核对镜像、网络、卷、端口与业务就绪后才提交原修订。 |
| 原操作保持待核验 | 保留原实例、数据卷、两个账本及秘密版本。记录原应用 ID、已知 Docker 回执、Engine 资源与问题码。该状态需要人工核对证据，完成前继续保持写入门禁。 |
| 保留卸载后需恢复服务 | 在目录实例页选原保留记录和修订，显式重装。以业务接口确认原数据可读。 |
| 需要停止扩大试用 | 关闭验收开关并重启，保留工作负载和账本以便复验。保留数据实例按已验证生命周期操作。 |

证据归档应包含操作 ID、摘要、资源清单和脱敏诊断。应用操作账本位于应用部署根目录的 `operations.json`，Docker 账本位于 Compose 数据目录的 `stack-operations.json`。保护存储与 Data Protection 密钥按 Server 安装范围保存。报告中只记录秘密版本编号及计数。

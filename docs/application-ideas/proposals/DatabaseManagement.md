## 1. 定位与常用引擎

管理数据库服务的完整使用流程：选择引擎与版本 → 安装 → 创建实例和应用账号 → 配置连接范围 → 交给外部客户端使用 → 查看服务、备份和维护状态。复杂 SQL、表结构编辑及数据浏览继续交给成熟外部工具。

以下是常见工作负载下的候选，不是市场占有率排名。支持顺序是产品建议，不代表平台或版本已经受支持。

| 引擎 | 常见用途 | 建议阶段 | 适配注意点 |
| --- | --- | --- | --- |
| PostgreSQL | 通用业务、自托管应用、需要扩展能力的项目 | 首批 | 实例/集群目录、角色、监听与客户端认证规则分别管理 |
| MySQL | Web 应用和已有 MySQL 生态项目 | 首批 | 账号包含用户与来源主机身份，区分管理账号与应用账号 |
| MariaDB | 自托管 Web 应用、MariaDB 指定依赖 | 第二批 | 独立适配认证、版本和升级路径，不视为 MySQL 可互换版本 |
| Redis / Valkey | 缓存、会话、队列等键值工作负载 | 第二批 | 分开声明引擎身份、版本和许可；按 ACL/用户能力管理，不套关系库授权模型 |
| MongoDB | 文档型业务及明确要求 MongoDB 的应用 | 后续 | 认证数据库、角色、绑定地址及副本集需求 |
| SQL Server | .NET 与企业业务系统 | 后续 | 版本/版本类别、许可、资源要求和平台支持分别确认 |
| ClickHouse | 日志、事件与分析查询 | 后续 | 资源、存储增长与分析型备份策略 |
| SQLite | 嵌入式应用、单文件数据存储 | 文件工具扩展 | 不提供虚构的服务启停、监听端口或服务账号重置 |

首批建议 PostgreSQL + MySQL。它们分别适配，不因 UI 相似而共享原生命令或认证假设。Redis/Valkey 适合作为后续配套服务，具体选择在立项时重新核实许可和目标应用兼容性。

## 2. 安装与实例

数据库管理应用展示依赖状态并跳转组件中心；软件安装、版本选择、更新、修复、回退、卸载和发布源维护统一复用[组件中心](../../platform/RelaxKonOS.ComponentCenter.Design.md)与[受管运行时规则](../../platform/RelaxKonOS.ManagedRuntimes.Design.md)。快速安装是预填当前引擎上下文后进入统一计划，不建立第二套安装入口。

建议安装向导包含：

1. 引擎、具体版本、主机和受支持安装模式。
2. 实例名称、数据目录、端口、资源预检及开机启动选择。
3. 管理身份初始化与应用账号创建，密码可生成或输入。
4. 默认本机访问；如选容器模式，明确容器网络、宿主映射与应用来源。
5. 展示下载、服务、目录、端口与重启影响，执行后验证实际版本和认证连接。

需要区分程序安装、数据库实例和逻辑数据库。多实例可以共享程序版本，但其数据、服务、端口和账号独立。首版可限定每引擎一个受管实例，模型仍保留实例身份。

### 安装模式与来源决策

产品决定（2026-11-04）：Windows 直接安装，Linux 可选直接安装或 Docker；具体引擎/版本/平台组合仍需实现与验收，不能默认为已经支持。宿主模式复用包或安装器事务，容器模式复用 Docker/应用部署事务；两者不能通过同一“解压并启动”实现伪装。跨应用模型、Nginx 改造与 ND 跟踪见[直接安装与 Docker 统一设计](../NativeAndDocker.md)。

优先评估 Linux 已配置的签名软件仓库、各引擎官方发行渠道以及容器模式的经审核官方镜像来源。不自动加源，不使用任意上传包或标签名称建立信任。容器计划冻结不可变镜像身份；宿主安装冻结具体包/制品。准确版本范围、OS/架构、默认源身份及验证方式在 DB-01 完成前不得声明受支持，Windows 与 Linux 分别验收。

已有外部安装先识别所有权和可管理范围，不静默接管数据目录或服务。系统包按[包所有权规则](../../platform/RelaxKonOS.PackageOwnership.Design.md)处理，外部实例配置写入仍需明确授权与边界。

## 3. 密码与账号管理

提供应用账号创建、允许访问的数据库/角色、修改密码、禁用或撤销、连接测试，以及依赖应用列表。密码不进入日志、普通操作回执、命令行参数或默认明文连接串。

必须区分两种操作：

| 操作 | 前提 | 行为 |
| --- | --- | --- |
| 修改/轮换密码 | 有有效管理身份，或引擎允许的本人修改权限 | 通过引擎原生账号接口修改，再以新凭据验证；显示受影响应用 |
| 忘记管理密码后的恢复 | 有经确认的实例所有权及相应宿主管理权限 | 执行该引擎、版本和安装模式专属恢复流程，展示停机及影响，核实恢复完成 |

普通应用密码遗失时，若受保护管理身份仍有效，可通过管理通道重置，无需进入离线恢复。OS 登录权限不自动等于数据库管理权限；具备主机恢复权限也不允许对身份未知的实例任意重置。

不承诺所有引擎都能无停机恢复。某些数据库使用本地 socket/peer 等身份认证，不能把“没有数据库密码”判定为故障，也不能未经说明改变其认证方式。

若恢复流程需要临时改变认证，必须隔离外部连接、限定实例范围、保存原配置并跟踪每个步骤；恢复失败进入待恢复状态，禁止遗留对外免认证服务。不能把临时禁用鉴权作为常规改密方式。

应用凭据更新与数据库密码变更可能无法原子提交。记录各步骤结果，支持按引擎能力分阶段轮换；失败时不能自动恢复已撤销密码，也不能在新密码实际生效而应用更新失败时报告整体成功。

## 4. 外部访问控制

提供本机、指定私网/VPN、指定 IP/CIDR、明确公网开放等策略。普通外部客户端可优先通过 SSH 转发或现有组网连接，避免反复手工填写连接配置。

“允许外部访问”展开为可审查计划，分别展示：

- 引擎监听地址、端口、IPv4/IPv6 与需重启或重载的动作。
- 数据库账号/角色的来源限制与认证方法。
- 宿主防火墙规则；容器模式的端口发布与实际网络路径。
- TLS 是否启用、证书身份与客户端应使用的连接方式。
- 云安全组、上游防火墙或 NAT 等尚未由平台管理的阻塞项。

PostgreSQL 的监听与 `pg_hba.conf` 是不同配置层；MySQL 的来源主机账号不能简单转换成 PostgreSQL 规则。Redis 类服务按可信网络与 ACL 管理，不能仅为连接成功关闭 protected mode。

展示“已配置”和“已验证”两组状态。服务器本机探测成功不能证明公网可达；从外部客户端验证时记录实际来源和目标。关闭外部访问只撤销本应用拥有的规则，并说明既有会话是否仍存活；需要断开会话时作为明确操作处理。

## 5. 维护和数据生命周期

- 服务启停、重启、开机启动、健康、日志、端口和实测版本。
- 创建逻辑数据库和最小权限应用账号，导出脱敏连接信息，支持复制字段及通过隧道连接。
- 后续关联 APP-001 数据库一致性备份与 APP-003 迁移，不能用运行中数据目录的普通复制冒充可靠备份。
- 同版本重装属于修复，不重建或覆盖数据目录；保留数据重装重新核对数据格式、权限和保护密钥。
- 更新区分补丁变更与主版本数据迁移。主版本升级需引擎专属预检、备份与迁移方案。
- 二进制回退不等于数据格式回退。仅在具备可验证恢复路径时提供回退；否则明确不支持。
- 卸载默认保留数据、备份与必要密钥，单独选择删除数据并展示范围；只操作可证明属于该实例的资源。

管理应用或模块卸载/休眠不能顺带停止数据库引擎或删除实例数据。

## 7. 验收方向

验证实际版本、持久化数据、服务身份、监听归属、新凭据登录及授权范围。覆盖错误密码、端口冲突、目录非空、权限不足、部分规则失败、客户端断线、执行中重启、轮换后应用更新失败和恢复期间网络暴露。

特别核对：新密码实际有效；旧密码对新连接的行为符合引擎语义；未授权来源被拒绝；关闭访问后的既有连接行为如实展示；安装失败不会覆盖外部数据库；更新和回退不会把不可读数据标记为健康。

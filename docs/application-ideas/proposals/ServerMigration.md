# APP-003 服务器迁移助手

> 状态：候选。更新：2026-11-04。建议形态：原生编排应用。依赖：APP-001 备份、APP-002 同步及健康验证能力。

[返回方案索引](README.md) · [推荐顺序](../Priorities.md)

## 场景与价值

用户更换服务器时，需要把应用、配置、数据和入口一起迁移。平台已掌握部分应用关系，可提前指出平台、路径、权限、运行时、端口和容量冲突，减少人工遗漏。

流程：选择应用与目标 → 盘点依赖 → 检查阻塞项 → 预复制 → 用户选择停机同步 → 验证目标 → 用户选择切换入口。

## 首版范围

- 同平台、单应用，明确支持的部署类型与数据来源。
- 迁移前计划、源目标检查、复制记录和目标健康验证。
- 切换时机由用户选择，保留源端状态及回退说明。

整机迁移、跨操作系统迁移、零停机、数据库自动复制及自动 DNS 切换后置。未纳入范围的秘密、外部依赖和数据必须明确列出，不能默认已迁移。

## 现有基础与边界

复用应用部署、备份、同步、站点、证书及[任务编排](../../platform/RelaxKonOS.TaskOrchestration.Design.md)。迁移计划引用各领域操作及其结果，不另写安装器或绕过组件中心。

源与目标分别授权，秘密转移必须有明确范围。多阶段失败不能推导整体成功。切换后目标的新写入会影响回退可行性，需要给出数据处理方案，不能承诺无条件一键回滚。

## 验收方向与待决问题

用真实应用验证文件、配置、访问入口和业务行为。覆盖复制中断、目标启动失败、部分切换、权限变化和重启恢复；确认未验证目标不会被标记为迁移成功。

待定：首批应用类型、停写与一致性策略、证书及秘密转移、切换后的源保留期限和回退数据策略。

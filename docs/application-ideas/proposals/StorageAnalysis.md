# APP-007 存储空间分析与清理

> 状态：候选。更新：2026-11-04。建议形态：原生应用 + 现有领域扩展。

[返回方案索引](README.md) · [推荐顺序](../Priorities.md)

## 场景与价值

磁盘将满时，用户需要知道空间被什么占用，以及通过哪个应用安全处理。目录大小应能关联应用、容器、日志、缓存和备份，而不只是一张文件大小排行。

流程：选择磁盘或目录 → 有界扫描 → 查看占用与归属依据 → 跳转文件或领域管理入口 → 操作后复查实际空间。

## 首版范围

- 只读目录扫描、占用分布、最大项目和扫描时间。
- 明确权限不足、未扫描范围、取消和数据可能变化的情况。
- 提供已知应用归属及现有清理入口跳转。

自动清理、重复文件删除、快照和挂载变更后置。不能因为目录名称像缓存就判定可删除。

## 现有基础与边界

复用文件管理、Docker 和应用部署元数据。扫描对象与清理执行者分开，容器资源清理由 Docker 领域执行，应用数据由所属领域定义保留规则。

设置扫描并发、内存与 I/O 预算。明确符号链接、挂载边界、硬链接及逻辑大小/实际分配空间的统计口径；无法识别的归属显示未知。

## 验收方向与待决问题

覆盖大目录、无权限、链接、扫描时文件变更和用户取消；验证扫描不会越出授权范围。清理预估与实际释放量分别展示。

待定：首批平台、统计口径、缓存有效期和跨挂载扫描默认行为。

# APP-013 网络诊断工作台

> 状态：候选。更新：2026-11-04。建议形态：原生应用。

[返回方案索引](README.md) · [推荐顺序](../Priorities.md)

## 场景与价值

用户遇到站点打不开时，需要定位 DNS、端口、证书、代理、隧道或后端服务中的具体问题。复用已有服务上下文，减少在多个应用间手工拼接信息。

流程：从站点或应用点击诊断，或输入网址 → 选择探测位置 → 分阶段测试 → 展示证据 → 跳转对应管理入口。

## 首版范围

- DNS、TCP、TLS、HTTP 检查，显示目标地址、耗时、错误阶段和探测时间。
- 对照客户端与服务器结果，保留探测位置和网络环境说明。
- 关联已知站点、证书和后端端口；区分配置推断与实际探测。

自动修复、通用抓包及互联网全路径拓扑后置。仓库现有 [Network Inspector](../../applications/RelaxKonOS.NetworkInspector.md)主要检查客户端与 Server 的 API 通信，本提案面向业务服务可达性，不能混淆采集范围。

## 现有基础与边界

复用站点、证书、防火墙、代理、FRP 和 Tailscale 领域信息，通过契约读取，避免聚合入口持有各模块实现。

探测目标、端口、重定向和出站访问必须受用户及宿主权限约束，设置超时与并发上限。业务诊断不得成为绕过访问边界的任意网络请求入口。响应中的凭据和敏感内容不进入共享结果。

## 验收方向与待决问题

构造 DNS 错误、连接拒绝、超时、TLS 名称不匹配和后端 502，确认显示真实失败阶段。客户端成功、服务器失败及反向情况应能明确区分。

待定：代理路径选择、IPv4/IPv6 策略、受保护站点认证、重定向规则及历史结果保存期限。

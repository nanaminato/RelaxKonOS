# APP-025 项目工作区

> 状态：候选。更新：2026-11-04。建议形态：原生聚合入口。

[返回方案索引](README.md) · [推荐顺序](../Priorities.md)

## 场景与价值

用户围绕一个项目工作，而现有仓库、终端、部署、日志和站点入口分散。工作区保存这些对象的关联，让用户按“编辑 → 提交 → 发布 → 查看运行结果”的流程操作。

## 首版范围

- 手动建立项目，关联仓库目录、终端工作目录、已有部署与站点。
- 展示仓库和部署实际状态，打开已有 Git、编辑器、终端和日志入口。
- 对不可用、已删除或无权限的关联给出明确说明。

发布流水线、临时预览环境、远程 IDE 和自动发现后置，分别对应 APP-026、APP-028、APP-030。完整编辑和调试允许交给成熟外部 IDE。

## 现有基础与边界

复用[Git 项目编辑器](../../applications/RelaxKonOS.GitEditor.Design.md)与[应用部署](../../applications/RelaxKonOS.ApplicationDeployment.Design.md)。项目元数据只拥有对象关联，不另建 Git 状态、发布执行器、秘密存储或服务控制权威。

每次打开或执行操作时重新核对对象权限；项目访问权不自动授予所有关联资源的权限。切换项目不关闭应继续运行的终端或发布任务。

## 验收方向与待决问题

验证同一项目在多设备上打开、关联对象移动或删除、部分领域不可用和跨主机权限差异。聚合状态必须与来源领域一致。

待定：项目身份、关联存储位置、多仓库支持、共享范围，以及一个项目跨多个服务器的表示方式。

# APP-019 统一日志与故障时间线

> 状态：候选。更新：2026-11-04。建议形态：原生聚合应用。关联：APP-036 操作审计时间线。

[返回方案索引](README.md) · [推荐顺序](../Priorities.md)

## 场景与价值

用户从故障应用进入，自动找到相关日志，并在同一时间窗口看到部署、配置和重启记录。例如“发布新版本 → 容器启动失败 → 后端不可达 → 站点 502”。关联表示时间和对象上的联系，不自动证明因果。

## 首版范围

- 聚合 Docker、进程守护、站点和部署操作的已有日志与记录。
- 按应用、来源和时间范围查询，保留原始来源、时区与时间精度。
- 有界分页和实时查看；展示缺失区间和来源不可用原因。

首版复用已有日志源，集中历史检索平台后置。自动根因分析、全量采集和任意日志正文长期留存另行评估。

## 所有权与边界

原始日志和操作状态继续由来源领域拥有；聚合入口通过契约查询，不把现有存储搬进第二套事实权威。APP-036 可共享时间线组件，但审计记录与普通业务日志的权限、保留规则分别处理。

每个来源独立核对权限，日志脱敏，设置条数与字节预算。实时订阅纳入模块租约；切换窗口、取消和断线后正确关闭订阅。

## 验收方向与待决问题

验证跨来源时序、时钟偏差、来源中断、日志轮转、长行截断及权限差异。不能把未查到日志显示为“没有故障”。

待定：时间标准化、来源关联键、脱敏规则、查询预算和未来外部日志平台接口。

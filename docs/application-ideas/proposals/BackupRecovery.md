# APP-001 备份与恢复中心

> 状态：候选。更新：2026-11-04。建议形态：外部适配 + 原生应用。

[返回方案索引](README.md) · [推荐顺序](../Priorities.md)

## 场景与价值

用户部署好应用后，需要知道哪些数据受到保护、最近一次备份是否可恢复。入口从应用详情或文件管理器进入，复用目录、卷和应用身份，减少手工整理备份对象的成本。

典型流程：选择应用或目录 → 确认保护范围和目标仓库 → 设定计划 → 查看快照 → 选择文件 → 恢复到新目录并检查结果。

## 首版范围

- 目录备份、计划执行、执行记录、快照浏览和单文件恢复。
- 展示最近备份与最近验证时间，两者分别记录。
- 恢复到新目录，显示目标路径、权限和空间预检。

数据库一致性备份、运行中容器卷保护、整应用恢复及自动恢复演练后续按领域适配；不能把文件复制成功作为数据库可恢复的证据。

## 外部工具与现有基础

优先评估 restic。其官方文档覆盖[仓库快照与检查](https://restic.readthedocs.io/en/stable/045_working_with_repos.html)及[按文件恢复](https://restic.readthedocs.io/en/stable/050_restore.html)。具体版本、许可与目标平台适配在立项时核实。

仓库已有 `RelaxKonOS.Server/BackupRecovery/`，包括应用定义备份等代码。先审计其范围与权威，不能假设它已经提供本提案的通用数据保护能力，也不另建冲突的恢复台账。

## 所有权与边界

备份任务、仓库访问和恢复记录需要明确领域所有者，凭据复用既有秘密保护能力。客户端断线不取消已受理任务；后台工作结束或可靠交接前不能释放执行者。运行时安装维护遵循[受管运行时设计](../../platform/RelaxKonOS.ManagedRuntimes.Design.md)。

## 验收方向与待决问题

验证真实备份后恢复的文件内容及约定元数据；覆盖空间不足、仓库不可达、取消、凭据失效和执行中重启。仓库检查通过与恢复演练通过分别展示。

待定：目标存储首批范围、文件变化时的一致性规则、密钥保管与恢复方式、保留策略和清理权限。

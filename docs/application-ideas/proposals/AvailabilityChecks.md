# APP-016 服务可用性巡检

> 状态：候选。更新：2026-11-04。建议形态：外部适配 + 现有告警集成。

[返回方案索引](README.md) · [推荐顺序](../Priorities.md)

## 场景与价值

进程存活不等于业务可用。用户从现有站点、端口或应用创建检查，失败后进入告警、日志及网络诊断，跨设备查看持续检查结果。

## 首版范围

- HTTP、TCP 和证书到期检查，明确探测位置与最近成功时间。
- 失败阈值、恢复通知、维护窗口及检查历史。
- 复用现有事件告警入口，跳转 APP-013 网络诊断与 APP-019 日志时间线。

先评估服务器视角，再评估独立探测节点；同机检测通过不能作为公网可用证明。用户访问流程模拟和复杂业务断言后置。

## 外部工具与边界

可评估 [Uptime Kuma](https://github.com/louislam/uptime-kuma)作为外部方案，立项时核实可用集成接口、身份方式、许可、平台与实际资源成本，不预设所有 UI 能力都有稳定管理 API。

巡检执行与通知投递各有明确所有者。管理模块休眠时，已承诺的检查仍应执行，或如实报告监测中断。服务端失联也可能使本机监测停止，需要区分被监测服务故障和探测器不可用。

## 验收方向与待决问题

验证失败、抖动、恢复、维护窗口、证书临期、通知失败、执行者重启及探测器失联。不得因没有采样而显示健康。

待定：部署位置、外部接口稳定性、通知去重、检查凭据、历史保留和跨主机探测授权。

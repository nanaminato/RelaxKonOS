## 建议推进方式

2026-11-04 补充：[APP-005 数据库引擎管理](proposals/DatabaseManagement.md)已被用户明确提出需求，进入重点评估。重点为快速安装、账号密码修改与管理员恢复、外部访问控制，不扩展为完整 SQL 查询客户端。建议首批评估 PostgreSQL、MySQL，随后 MariaDB 和 Redis/Valkey；具体平台与安装模式待确定。该补充不表示已启动代码实施或数据库生命周期已通过验证。

首发三项选择备份恢复、文件同步、网络诊断。它们分别解决数据安全、数据流动和服务可达性，能复用现有文件、任务、站点及网络上下文。

数据能力按“备份恢复 → 文件同步 → 迁移”推进；网络诊断与只读空间分析可穿插交付。日志与巡检随后接入统一故障处理流程。项目工作区先聚合现有能力，流水线和临时环境另行评估。

这不是三个应用必须同时开工的要求。正式立项前应核对现有基础、目标平台、实际用户需求和外部工具适配成本。

## 共用约束

- 持久任务由明确所有者调度、执行、取消和恢复；客户端断线、关闭窗口与任务结束分开处理。
- 模块闲时释放不能取消巡检、同步、备份等已经接受的后台责任，也不能假设外部服务随模块一起停止。
- 计划、进度、执行成功与实际验证分别表示。未知结果不能显示为成功，也不能自动重放具有副作用的操作。
- 凭据、安装生命周期、审计与权限复用既有领域权威，不因新增聚合入口而建立第二套实现。
- 原生入口必须提供比直接打开外部工具更方便的上下文；没有这种价值的候选降为部署模板或暂缓。

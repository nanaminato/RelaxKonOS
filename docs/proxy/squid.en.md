# Squid HTTP gateway

The backend, Avalonia built-in Squid application and Android management application are implemented. Package installation and host recovery remain administrator tasks; runtime adoption and real Linux acceptance remain unverified. The detailed design, API examples, recovery procedure and Linux acceptance checklist are maintained in [squid.md](squid.md).

Squid has a separate `GatewayProxy` contract and Server service. It does not implement the Mihomo-oriented outbound `IProxyEngine`. A manually configured HTTP parent can point at Mihomo's actual HTTP/mixed listener. Parent routing uses `never_direct` to prevent silent direct fallback; see the official [cache hierarchy documentation](https://wiki.squid-cache.org/Features/CacheHierarchy).

Implemented:

- Default loopback listener, explicit remote opt-in, required source CIDRs without `/0`, source-constrained domain allow/deny lists and final deny-all.
- HTTP forwarding and HTTPS CONNECT restricted to destination ports 80/443 and CONNECT 443 respectively. Manager, loopback, link-local and multicast destinations are denied first.
- Structured preview, independent native parse with bounded diagnostics, explicit existing-configuration adoption, backup, atomic publication, reload failure rollback and a pending recovery marker.
- Fixed Linux package paths and squid.service lifecycle through closed Helper operations. Root ownership, non-writable paths and symlink checks apply to managed configuration files.
- Status, existing authorization policies, durable operation ledger, idempotency keys and auditing. Linux User Mode blocks this API family. Windows mutation is unsupported, but the contract still answers there with an authoritative unsupported status.

API root: `/api/v1.0/gateway-proxy/squid`. GET `/status` requires `ProxyRead`. POST `/configuration/preview`, `/configuration/validate`, `/configuration/apply` and `/lifecycle` require `ProxyManage`. Apply and lifecycle require a unique `Idempotency-Key` of at most 160 characters and return 202; poll the returned Location under `/api/v1.0/proxy/operations/{id}`. Preview and validate accept `SquidConfiguration`; apply accepts `{ "configuration": { ... }, "adoptExistingConfiguration": false }`. Lifecycle accepts an action such as `{ "action": "reload" }`.

The full `/etc/squid/squid.conf` is owned after explicit adoption. Existing includes, authentication and caching configuration are not merged. The previous version is stored as root-private `/etc/squid/relaxkonos.previous.conf`. A pending marker blocks further mutations except stop/disable; native validation remains available. Recovery is manual after an interrupted transaction: stop Squid, inspect the marker and backup, restore the previous configuration or remove a first publication, verify ownership/permissions and native parsing, then remove the marker and start as appropriate. Do not merely delete the marker.

Stopped services remain stopped after publication. Successful reload plus systemd active is only a service-level check, not proof of applied configuration or working HTTP/CONNECT traffic. The reported SHA-256 identifies the on-disk config. There is no Configuration Registry desired/applied integration, directory-fsync/power-loss guarantee, automatic crash recovery or configuration history yet.

Package installation/removal, Basic credentials, access-log ingestion/SignalR, firewall integration, automatic Mihomo endpoint discovery, and runtime adoption verification are subsequent work. Squid writes its own standard access.log, but RelaxKonOS does not expose it yet. Disk caching, transparent proxying, TLS interception and multiple instances are outside this phase. Android documentation belongs exclusively in the Android-owned docs directory.

Configuration syntax targets Squid 5–7 and every application is gated by the installed native parser. See [ACL](https://www.squid-cache.org/Doc/config/acl/) and [http_access](https://www.squid-cache.org/Doc/config/http_access/) for native semantics. The first phase accepts ASCII domain names; use a leading dot for the domain and its subdomains rather than `*.`.

Run `dotnet run --project RelaxKonOS.Server.Tests/RelaxKonOS.Server.Tests.csproj --no-restore -- --squid-only` for focused renderer, injection, ordering, wire and Helper boundary tests. Server builds and the focused backend/workspace checks pass in the Linux development environment; actual Linux parse, permissions, service lifecycle, HTTP/CONNECT, rollback and interruption acceptance remain unverified and must pass before production rollout.

The editor backend now persists host-wide structured intent in private `squid-configuration.json` state. GET `/api/v1.0/gateway-proxy/squid/configuration` requires `ProxyRead` and returns `state`, live `status`, and `matchesPublishedConfiguration`; Helper unavailability returns 503. Each valid apply records a new desired revision before dispatch, and successful publication records its revision and rendered SHA-256. Failures preserve the previous publication receipt; interruption leaves `squid.publication.unconfirmed`. The match flag compares the managed on-disk file with the last publication and requires no recovery marker. It proves neither runtime adoption nor publication of the latest desired revision. Before the first submission the configuration is null. This shared host state is separate from the existing user/device/workspace Registry. Focused checks cover persistence across service recreation, failure receipts and drift.

Avalonia registers `relaxkonos.squid` (`squid` built-in key) and requires the `server.gateway-proxy` capability. Squid 5–7 ships only for Unix-like hosts and has no maintainable Windows port, so a Windows host cannot install, configure or control the gateway. The Server therefore advertises `server.gateway-proxy` on every host that can answer the contract (all Windows hosts, Linux System Mode; never Linux User Mode, which has no privileged Helper). The entry stays in the desktop and Start menu on those hosts instead of silently disappearing, and the window renders its "unsupported server" state with every configuration and service action disabled while the privileged Helper answers; a missing or unreachable Helper reports unavailable instead, so a broken deployment is never described as a platform limitation. It provides structured listener/CIDR/domain/HTTP parent editing, native previews and validation, explicit whole-file replacement confirmation, lifecycle actions and terminal operation polling. Refresh preserves edits; explicit saved-state reload confirms discarding them. Application read/manage grants and controller role gate mutations. Recovery blocks unsafe actions but permits stop/disable/validation. Uncertain requests retain their original key and body within the open desktop window; resume polls an existing operation or resubmits the original request. Session changes clear host data and disable the stale window. Preview and native validation return HTTP 200 for both valid and invalid domain outcomes; apply still rejects invalid input with HTTP 400.

Android has its own catalog entry and persistent, account/server/workspace-scoped pending request journal. See the canonical [Android Squid documentation](../../Client/RelaxKonOS.Client.Android/docs/features/Squid.md). Android tests have not been run for this implementation.

The desktop workspace follows the mihomo manager navigation with runtime, listener, domain rules, HTTP upstream and configuration preview pages. Blocking notices live on the runtime page; the bottom status bar remains visible across pages. Draft fields persist across navigation, and generating a preview opens the publishing page, which also contains configuration ownership. Below 620 pixels, the sidebar becomes a compact menu. Load, validate, preview and apply actions remain pinned.

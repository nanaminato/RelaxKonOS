# Mihomo runtime

Managed Mihomo installations are selected only from the fixed Server manifest and verified before activation. Releases use immutable version directories with active/previous rollback state. External runtimes are detection-only unless an administrator explicitly chooses a RelaxKonOS-managed instance.

The controller binds locally and its secret remains in the Proxy-scoped protected store.

The Server uses the fixed Data Protection application identity `RelaxKonOS.Server`, independent of its release directory. Upgrades and backup restores must preserve both protected data and the service account's Data Protection key ring. An unreadable controller secret rolls back first-time installation and produces an explicit secret-read diagnostic; it does not establish archive corruption or invalid user YAML. The service never automatically discards or regenerates an existing secret it cannot decrypt.

System proxy controls use the required `platformCapabilities.systemProxy` fields (`supported`, `supportsPac`, `loginEnvironment`, `desktopSession`), rather than an OS-name check. Windows retains interactive-user HKCU support. Linux System Mode uses the fixed Helper 1.4 operations to manage uppercase/lowercase HTTP_PROXY, HTTPS_PROXY, ALL_PROXY and NO_PROXY in `/etc/environment`, plus currently logged-in local GNOME/KDE users. HTTP/HTTPS use HTTP CONNECT; ALL_PROXY uses SOCKS5. PAC is Windows-only.

The environment file affects new PAM logins that read it, not existing terminals or independent systemd services. Docker and managed downloads retain their separate outbound-proxy settings. GNOME dconf and KDE kioslaverc changes execute as the desktop user; KDE receives a KIO reload signal. Discovery accepts non-root, non-remote user sessions with x11/wayland and GNOME/Ubuntu or KDE/Plasma identifiers from loginctl. Standard `$HOME/.config` is supported; arbitrary session process environments are not read. Newly logged-in desktop users are included on a settings save or a configured guard iteration.

Original proxy keys and pending writes are recorded in a root-only journal before mutation. Changing the endpoint retains the first snapshot; disabling restores only still-owned keys and preserves later external edits. Unguarded conflicts return `proxy.system_proxy_conflict`; explicitly enabling the guard enforces the selected proxy keys. Partial failures compensate; failed compensation keeps the journal for recovery. Startup reconciles saved settings and retries failures; settings saves serialize with guard iterations. Failed application rolls back YAML, and failed settings persistence compensates both host settings and YAML. Linux defaults bypass localhost, 127.0.0.1 and ::1; custom hosts, domains and networks use commas/semicolons and consumer-specific matching, without Windows wildcards or `<local>`.

Server, Helper and clients must be updated together. Deterministic transaction and capability checks pass; live Linux desktop/terminal networking remains unverified.

The Server samples Mihomo NDJSON with `ResponseHeadersRead`: traffic and memory each return their first complete record; logs observe at most one second, with a 64 KiB line bound. Quiet logs return an empty list and caller cancellation propagates. Connection protocol comes from `metadata.network`; endpoints include ports and prefer the destination hostname. Mihomo `connections: null` means zero trackers. Failed controller reads return a problem-coded 503 from `GET /api/v1.0/proxy/connections`, rather than a successful empty list. The desktop connections page refreshes independently every three seconds, preserves a still-active selection, reports counts, empty state or read failure, and stops its timer when detached.

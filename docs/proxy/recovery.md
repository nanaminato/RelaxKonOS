# 代理网络恢复

启动时，RelaxKonOS 会先评估任何持久化的 TUN 恢复标记，随后才允许再次激活。“紧急禁用 TUN”会独立于运行时卸载恢复已捕获的网络状态；若恢复失败，标记会保留。

Mihomo 直连重载失去确认时，组件中心的运行时恢复面板显示原操作 ID。具备管理权限并完成宿主提权的操作员可以重试。结果未知时，重试只在受保护的活动文件仍匹配候选摘要时恢复原磁盘配置。原操作仍显示待恢复，因为 Mihomo 可能继续运行已加载的候选配置。

如果档案发布已记录控制器确认，启动恢复或具名重试会核对候选文件并完成原档案提交。按原 ID 再次重试可读取已保存的回执。文件或档案身份发生变化时，恢复保持待处理。TUN 紧急禁用和系统代理恢复继续使用各自的持久记录。

活动订阅的排队刷新使用原刷新 ID 记录直连重载确认。启动恢复完成档案提交后，刷新回执和原幂等键仍指向同一次刷新。恢复沿用已转换的候选配置和原订阅时间，不重新下载订阅或重载控制器。如果 Server 在原控制器确认前退出，查询或再次提交时会根据匹配的发布检查点，将原队列记录保存为中断且等待发布恢复（`publication_pending`），完成时间留空。以原键重试返回同一条记录，新刷新继续受写入门禁限制。

如果直连设置已记录运行时和宿主的成功应答，且宿主代理策略前后一致，恢复会核对候选配置和设置文件并完成本地提交。结果仍未知或文件出现独立改动时，原操作继续待处理。

Linux 直连设置的宿主策略变更在收到运行时确认后，可按原 ID 核对 Helper 的历史回执和当前代理值。两者匹配且候选文件一致时，恢复完成本地设置提交。guard 需要独立维护已保存策略时，会保留原操作为待恢复，便于区分原变更和后续安全操作。

如果待恢复变更切换了监听端口，guard 恢复已保存的代理地址后，Mihomo 仍可能在候选端口运行。此时指向旧端口的新连接可能被拒绝，已有连接仍可能继续转发。恢复面板会保留原操作 ID 和待恢复状态。

对于 guard 已接管的 Linux 直连设置，具备管理权限并完成宿主提权的操作员可确认“恢复已保存代理策略”。应用会使用独立恢复 ID，核对旧监听和宿主代理效果。完成后原操作显示中断，并关联补偿 ID。TUN 安全责任尚未解除、文件漂移或补偿重载结果未知时，恢复仍待处理。

首次平台验证应在带有第二条管理连接的一次性 VM 上进行。尝试 Windows 或 Ubuntu 恢复演练前，请先查看跳过测试登记表。
